# 案例分析·考点简洁背诵版（最后 3 天只背这个）

> 适用：系统架构设计师下午案例题。结构：每模块只给 **①必背得分点 ②关键骨架/口诀 ③致命禁句/易错**，考场上套通用模板展开即可。
> 五大模块 = 本仓库 5 个正文文件：**架构基础与风格 / 软件工程综合 / 数据库与数据设计 / 分布式云原生与集成 / 专项架构与新技术**。
> 考试结构：**第 1 题必答（25 分）+ 第 2~5 题选 2（共 3 题，45 分及格）**，90 分钟独立计时。

---

## 〇、通用答题铁律（每题都套）

1. **有问必答、逐条回应**：题干 ①②③ 少一条扣一条的分。
2. **万能方案模板**：问题定位 → 方案名称 → 收益 → 代价/风险 → 适用场景/权衡结论。
3. **权衡句必写**：只写收益不写代价 = 只得一半分。万能句：*「采用 X 提升 Y 质量属性，但带来 Z 代价，需权衡。」*
4. **结合题干场景**：纯默写理论不结合项目场景，扣一半分（写清"在 XX 系统中…"）。
5. **时间纪律**：单题超 30 分钟立即止损跳下一题；最后 5~10 分钟回填填空/拖拽小题。
6. **选答优先级**：①架构设计与评估(必做) + ②数据架构(Redis/数据库) + ③分布式云原生 组合最稳；AI/嵌入式/大数据按背景选。

## 第一部分 · 架构基础与风格（试题一·必做·25 分）

**① 必背得分点**
- 5 大经典风格 + 特点/场景/优缺点：分层、微服务、事件驱动、管道-过滤器、仓库/黑板。
- 教材五大类：数据流 / 调用返回 / 独立构件 / 虚拟机 / 仓库。
- 六大质量属性：性能、可用性、安全性、可修改性、可测试性、易用性（＋可伸缩性＝可修改性子属性，强调加节点时优先写"可伸缩性"）。
- 质量属性战术（按属性背：缓存/异步/负载均衡＝性能；心跳/冗余/熔断＝可用性；认证/加密/审计＝安全性；高内聚低耦合/配置化＝可修改性）。
- ATAM 四大概念：
  - 敏感点＝影响**一个**属性（且是**架构决策**不是指标本身）
  - 权衡点＝一升一降**两个**属性冲突
  - 风险点＝有隐患的决策；非风险点＝无隐患（≠优点）
- 质量属性场景**六要素**：刺激源 / 刺激 / 环境 / **制品**(必写) / 响应 / 响应度量(必写，要量化)。
- 效用树：根(效用)→质量属性→场景→(优先级 H/M/L, 难度 H/M/L)。
- ABSD 六步：需求→设计→文档化→复审(ATAM)→实现→演化。
- 评估三法：SAAM(改可修改性) / ATAM(多属性权衡) / CBAM(成本效益 ROI)。

**② 关键骨架 / 口诀**
- 风格判读：容器主动调度知识源→**黑板**；数据别人主动读→**仓库**；发布订阅解耦→**事件驱动**；数据一步步处理→**管道-过滤器**；解析代码/规则→**解释器(虚拟机类)**；向量库做核心存储→**仓库**；多模型协作→**黑板/事件驱动**(见 AI 映射表)。
- 别名速记：隐式调用=事件驱动；知识库=仓库；连接器-组件=C2；显式调用=主程序-子程序。
- 权衡句：*「微服务提升可修改性/可用性，但大量远程调用降性能＋分布式事务复杂，需权衡。」*
- AI 场景质量属性：训练 1 分钟分配 GPU→性能；新增 GPU 不改核心代码→可修改性；推理 P99≤2s→性能；多 Agent 失败可回滚→可用性。
- RAG 权衡点：增大 Top-K→准确性↑但检索时延↑（准确性-性能权衡）。

**③ 致命禁句（写了几乎清零）**
- ❌「微服务提升系统整体性能」→ ✅ 降性能、升可修改性/可用性。
- ❌「事件驱动/消息队列一定降低延迟」→ ✅ 异步可能增加端到端延迟。
- ❌「读写分离一定存在主从延迟」(云原生存算分离可规避) → ✅ 传统自建才有。
- ❌「黑板=用了数据库」「响应时间 0.5s 是敏感点」→ ✅ 敏感点是架构决策不是指标。
- ❌「权衡点只提升单项属性」→ ✅ 必须一升一降两属性。

## 第二部分 · 软件工程综合（选做·权重下降）

**① 必背得分点**
- 过程模型选型：需求稳定→瀑布；需求模糊→原型；分批交付→增量；高风险→**螺旋(核心是风险分析非原型)**；面向对象→喷泉；测试对应→V 模型。
- 需求三类：功能 / 非功能(质量属性) / 约束。V&V：验证(做对了没,符合规格) vs 确认(做对的东西没,满足业务)。
- 风险管理四步＋四策略：规避(放弃方案)/减轻(降概率或损失)/转移(外包保险)/接受；风险发生后的处理叫"应急措施"(非事前策略)。
- EVM 挣值：PV/EV/AC；CV=EV-AC(>0 节约)；SV=EV-PV(>0 提前)；CPI=EV/AC；SPI=EV/PV；EAC=BAC/CPI(典型) 或 AC+(BAC-EV)(非典型)；TCPI=(BAC-EV)/(EAC-AC)。
- 敏捷 Scrum：PO(管 Backlog)/SM(清障碍非项目经理)/自组织团队；事件：Sprint/站会/评审/回顾。DevOps 三大支柱=人(文化)+流程(精益)+工具(自动化)；DORA 四指标=部署频率/变更前置时间/MTTR/变更失败率。
- CMMI 五级：初始→受管理(2级管项目)→已定义(3级管组织)→定量管理(4级管数据)→优化(5级管改进)。（⚠️第4级是"定量管理级"非"已管理级"）
- UML：结构图(类/对象/构件/部署/包) vs 行为图(用例/顺序/通信/活动/状态机)。顺序图=时间先后；状态图=单对象生命周期；活动图=业务流程。
  - 类关系6种：依赖(虚线,方法参数)/关联(实线,成员)/聚合(空心菱形,可独立)/组合(实心菱形,依赖整体)/泛化(继承)/实现(接口)。
  - 用例关系：include 基础→被包含(必须)；extend 扩展→基础(可选)。
- 系统切换三策略：直接(成本低风险高,小系统)/并行(风险最低成本最高,核心系统)/分段(折中)。**末尾必补回退计划 Rollback**。
- 内聚(越高越好)：功能>顺序>通信>过程>时间>逻辑>偶然。耦合(越低越好)：无直接>数据>标记>控制>外部>公共>内容。目标=高内聚低耦合。

**② 关键骨架 / 口诀**
- 模型口诀：*需求稳定选瀑布；模糊用原型；分批选增量；高风险螺旋。*
- 找错题三段论：①错误点 ②理由(理论) ③正确做法——缺一段只给一半分。
- 填空题"原词重现"：答案常藏于题干（"各构件独立运行通过事件总线"→填事件驱动）。

**③ 致命禁句**
- ❌「螺旋模型核心是原型迭代」→ ✅ 是风险分析。
- ❌「Scrum Master 是项目经理分配任务」→ ✅ 只清障碍、团队自组织。
- ❌「并行切换风险高」→ ✅ 风险最低。
- ❌「SV<0 进度提前」→ ✅ SV<0 进度滞后。
- ❌「风险规避=减轻」→ ✅ 规避是放弃方案消除风险条件，减轻是继续做但加防护。

## 第三部分 · 数据库与数据设计（选做高频·≈Redis 专项）

**① 必背得分点**
- 数据库设计流程：需求→概念(E-R图)→逻辑(关系模式)→物理(索引/分区)→实施→运维。
- **范式(必考)**：1NF 原子 → 2NF 消非主对候选键部分依赖 → 3NF 消传递依赖 → BCNF 消主属性部分/传递依赖。一律写"候选键"非"主键"。
- E-R 转关系：1:1 合并或独立；1:N 在 N 端加 1 端外键；M:N 必须独立关系(主键=两端主键组合)。
- 规范化分解必写两条：**无损连接性**(自然连接可还原) + **函数依赖保持**。
- 索引：B+树(叶子双向链,3~4 次 IO)；聚簇索引(叶子存整行,每表1个,主键即聚簇) vs 二级索引(存索引列+主键,需回表)；覆盖索引(字段全在索引免回表)；ICP(回表前先过滤)。失效：函数运算/隐式转换/前导%模糊/破最左前缀。
- 反规范化：增冗余列/派生列/合并表/垂直拆表 → 提升查询、降 join；代价=冗余+不一致。一致性维护：事务同步/触发器/定时任务/MQ/Binlog 监听。
- 分片：垂直(切字段) vs 水平(切行, 策略=范围/哈希/列表)；分片键均匀+多数查询带键；全局 ID=号段/雪花/Redis；跨分片查询用映射表/异构索引/搜索引擎/基因法。
- 读写分离：主写从读；代价=主从延迟(写完立即读可能旧)；应对=强制走主库/会话一致性/半同步。
- 事务并发四类：丢失更新/脏读/不可重复读/幻读。隔离级别：读未提交→读已提交→可重复读(MySQL默认,靠 MVCC+Next-Key 很大程度避幻读)→串行化。
- 分布式事务：2PC(强一致CP,金融短事务)/TCC(高性能,短事务,需幂等/空回滚/悬挂)/Saga(长事务补偿,跨多服务,编排式vs协作式)/本地消息表/可靠消息/最大努力通知。选型维度=**事务执行时长**：短高并发选 TCC，长链路选 Saga。
- 缓存三兄弟：穿透(查不存在,布隆过滤器/空值缓存)/击穿(热点key过期,互斥锁/逻辑过期)/雪崩(批量过期,随机过期/多级缓存/限流)。Cache Aside：更新库→删缓存。
- NoSQL 选型：交易账务→MySQL；热点缓存→Redis；日志内容→MongoDB；海量历史→HBase；关系图谱→Neo4j。
- Redis：分布式锁 `SET key val EX NX`(原子)+唯一value防误删+看门狗续期；击穿互斥锁序列图要点=线程2取锁失败**休眠重试→重新查缓存(非直接查库)**；主从→哨兵→Cluster(16384槽)。
- 数仓/湖：OLTP vs OLAP；ETL；星型(单级维,常用) vs 雪花(规范维,join多)；SCD Type2 保留历史；事实表=事务/周期快照/累积快照；OLAP=上卷/下钻/切片/切块/旋转。
- CAP：P 必选，分区时 CP(保一致,ZooKeeper) vs AP(保可用,Eureka)；BASE=基本可用+软状态+最终一致。
- 云原生/NewSQL：存算分离(PolarDB/Aurora)消主从延迟；TiDB=TiDB Server+PD+TiKV(Raft)。
- RAG 数据存储(2026 AI 热点)：向量库(Milvus/ES/pgvector)存切片向量 + MySQL 存元数据/权限；数据流=切片→Embedding→向量库→ANN 召回 TopK→拼 Prompt→LLM。

**② 关键骨架 / 口诀**
- 反规范化权衡句：*「提升查询性能，但带来数据冗余与不一致风险，需权衡。」*
- 读写分离模板：*「分散读压力提性能与可用性；代价是主从同步延迟、一致性下降。」*
- 水平分片模板：*「降单表数据量提查询；代价是跨分片查询/事务/聚合复杂。」*
- 分布式事务模板：强一致选 2PC(牺牲性能)；最终一致选 TCC/Saga/消息(提吞吐)；短事务 TCC、长事务 Saga。
- 慢 SQL 四步：定位(索引失效/回表)→方案(去函数/覆盖索引/调联合索引顺序)→代价(存储+维护)→效果(降 IO)。

**③ 致命禁句**
- ❌「反规范化提升写入性能」→ ✅ 提升查询、增写成本。
- ❌「读写分离解决单表大数据量慢」→ ✅ 只分散读压力，需分库分表。
- ❌「水平分片是把字段拆开」→ ✅ 水平切行、垂直切字段。
- ❌「主从保证写完立即读到最新」→ ✅ 有同步延迟。
- ❌「TCC 保证全局强一致」→ ✅ TCC 是最终一致，金融强一致用 2PC。

## 第四部分 · 分布式、云原生与集成架构（选做高频）

**① 必背得分点**
- 微服务六大特征：单一职责/独立部署/去中心化治理/一服务一库/轻量通信/面向失败设计。缺点=分布式复杂度+事务一致+运维暴涨+雪崩。拆分按**DDD 限界上下文**(标准答案)。
- SOA vs 微服务：SOA 重 ESB/粗粒度/共享库/集中治理；微服务轻网关/细粒度/每服务独立库/去中心化。
- API 网关功能：路由/负载均衡/认证授权/限流熔断/日志/协议转换/灰度/缓存。管**南北流量**。ESB 管**东西流量**(协议/数据转换/编排)。Service Mesh 管内部**东西流量**非侵入治理(不替代网关)。
- 认证授权：OAuth2.0(授权) + OIDC(认证) + JWT(自包含令牌,无状态,适配微服务)；RBAC(角色) vs ABAC(属性,更细)。JWT vs Session：JWT 自包含本地校验、天然无状态横向扩展；Session 需中心化存储违背去中心化。
- 限流三算法：计数器(窗口临界突发翻倍)/漏桶(绝对平滑)/令牌桶(允许合理突发,最常用)。
- 微服务治理=注册中心+配置中心+容错(熔断/降级/限流/超时重试)+可观测三支柱(指标/日志/链路追踪)。
- CAP(见第三部分)；BASE；分布式事务6方案(2PC/TCC/Saga/本地消息表/事务消息/Seata)。
- Saga 两模式：编排式(协调器,状态可见/补偿可控,复杂长流程首选) vs 协作式(无中心,事件驱动,简单流程)。**银行跨单元转账=编排式**(事件表与业务表同本地事务=RPO=0 根本保证)。
- MQ 可靠性三问：丢失→confirm+持久化+手动ACK；重复→幂等(唯一键去重表)；乱序→同业务键同分区。
- 云原生四大支柱=微服务+容器+DevOps+持续交付。七大原则口诀：**服弹可观韧，自动零演进**(服务化/弹性/可观测/韧性/自动化/零信任/持续演进)。12-Factor：配置与代码分离、无状态、日志当事件流等(最高频=无状态)。
- Docker(镜像只读/容器实例,解决环境不一致)；K8s：Pod(最小调度)/Deployment(无状态)/StatefulSet(有状态,稳定标识+持久化)/DaemonSet(每节点一个,日志/监控)/Service/Ingress/ConfigMap/Secret/HPA(加实例)/VPA(改规格)。探针三类型：liveness(失败重启)/readiness(失败摘流量不重启)/startup(保护慢启动)。不可变基础设施(构建新镜像非 exec 改)。
- Service Mesh：数据平面(Sidecar-Envoy)+控制平面(Istio Pilot)；零信任 mTLS；与网关南北+东西互补。
- Web 高可用：反向代理/负载均衡/动静分离/CDN/Session 共享(Redis,禁止绑单机)。
- 发布策略：滚动(不停机)/蓝绿(双倍资源,回滚快)/金丝雀(小流量,云原生首选)/红黑。
- 遗留演化三模式：绞杀者(流量拦截)/防腐层(模型隔离)/抽象分支(单体内部替换)。数据迁移三阶段：双写→对账→切读。
- 信创：国产芯片(龙芯/飞腾/鲲鹏/海光)、OS(麒麟/UOS)、库(达梦/人大金仓/OceanBase/GaussDB)、中间件(东方通/宝兰德)；国密 SM2(非对称/签名)/SM3(哈希)/SM4(对称)。

**② 关键骨架 / 口诀**
- 单体改微服务步骤：业务域识别→DDD限界上下文拆分→注册/配置/网关→库拆分→绞杀者增量迁移→治理监控→容器化CI/CD。
- 雪崩对策：网关限流→熔断降级超时→监控链路→优化事务→MQ削峰。
- 云原生改造模板：容器化→K8s编排→无状态改造→配置分离→服务治理→可观测三支柱→CI/CD。
- 容灾三阶段：检测(探针/心跳)→隔离(熔断/驱逐)→恢复(HPA/回滚)。RPO=允许丢多少数据；RTO=允许中断多久。
- 一页速查：SOA-微服务-ESB-网关-Mesh 对比；限流三算法；Saga两模式；发布四策略；探针三类型；演化三模式；信创关键词。

**③ 致命禁句**
- ❌「ESB 与 API 网关是一回事」→ ✅ 网关管南北、ESB管东西(传统集成)。
- ❌「Service Mesh 替代 API 网关」→ ✅ 互补不替代。
- ❌「微服务一定比单体好」→ ✅ 治理不足反而降可用性。
- ❌「K8s 有状态应用用 Deployment」→ ✅ 有状态用 StatefulSet。

## 第五部分 · 专项架构与新技术（选做·不稳定·含 AI 热点）

**① 必背得分点**
- **大数据 Lambda/Kappa**：Lambda=批处理层(精准历史,Spark/Hadoop)+速度层(实时,Flink)+服务层(合并,HBase/Druid)，双管道、复杂但精准；Kappa=仅流处理单管道(简单、一致好,重放历史)。选型：实时+历史并重→Lambda；实时为主偶回溯→Kappa。技术栈：采集(Flume/Kafka)、存储(HDFS/HBase)、批(Spark)、流(Flink)、数仓(星型/雪花)。Lakehouse：对象存储+Iceberg/Delta+ACID；Watermark(乱序)、Exactly-Once、CDC。
- **嵌入式/IoT**：资源受限+实时(硬实时飞控/软实时多媒体)+可靠；RTOS(VxWorks/RT-Thread/FreeRTOS/QNX)；协议 SOME/IP(车载SOA/RPC/服务发现) vs DDS(高实时/QoS/发布订阅,机器人)；ROS2 改进=用 DDS通信+跨平台+QoS+安全+生命周期；ROS 通信=话题/服务/动作/参数。IoT 端边云三层：端(采集)→边(就近低时延)→云(存储/训练)；MQTT(轻量Pub/Sub)/CoAP(UDP受限)。
- **AI 系统架构(2026 重点 25%)**：训练(集群/RDMA/并行) vs 推理(低延迟/高吞吐/模型服务化)；RAG=Query→向量检索→召回→LLM生成(解幻觉+时效)；Agent=感知→规划(ReAct/CoT)→行动(Tool)→记忆；质量属性结合：推理延迟(P99)/吞吐/准确率/可解释/隐私。推理加速=PagedAttention(vLLM)/算子融合/投机采样/量化(INT8/INT4)/蒸馏；成本=模型路由/语义缓存/弹性。AI 架构风格映射：训练平台→解释器；推荐/推理流水线→管道-过滤器；RAG→仓库；多Agent→黑板/事件驱动。
- **安全架构**：零信任(永不信任始终验证, mTLS)；RBAC/ABAC/ReBAC；加密 TLS/AES/RSA + 国密 SM2/3/4；脱敏；等保2.0 五级(核心常三级)。
- **系统计划**：可行性四方面=技术/经济(ROI/TCO/回收期)/运行/法律合规；立项产出章程；方案论证多维度对比+风险识别。
- **通信系统**：拓扑(总线/星/环/树/网状)；TCP(可靠)vs UDP(低时延)；时延四要素=传输/传播/处理/排队；RTT；QoS=带宽/时延/抖动/丢包；gRPC(HTTP2+Protobuf) vs REST。
- **区块链(2025 新增)**：去中心化/不可篡改/共识/智能合约；联盟链 Hyperledger Fabric(通道隔离/链码/CA)；五层=数据/网络/共识/激励/应用；共识：公链PoW/PoS，联盟链PBFT；适合多方不完全互信留痕审计，不适合高并发。
- **信创**：四类组件(芯片/OS/库/中间件)+四原则(自主可控/安全可靠/适配兼容/可扩展)；迁移=全量+增量双轨、选兼容 Oracle 的达梦、目标 RPO≈0/RTO分钟级。
- **数据要素**：数据治理(标准/质量/元数据/主数据)；数据血缘(溯源审计)；隐私计算联邦学习(数据不出域,可用不可见)；数据资产化。
- **可靠性**：R(t) 可靠度；MTBF/MTTR；可用度≈MTBF/(MTBF+MTTR)；串联 R=ΠRi，并联 R=1-Π(1-Ri)；容错=N版本程序(表决)/恢复块(主备)/冗余/看门狗。
- **架构演化**：绞杀者/防腐层/抽象分支(见第四部分)。

**② 关键骨架 / 口诀**
- 大数据选型口诀：*实时+历史并重→Lambda；实时为主偶回溯→Kappa。*
- 协议填空：SOME/IP→车载SOA/RPC/服务发现；DDS→高实时/QoS/Pub-Sub；MQTT→轻量Pub-Sub/低带宽。
- 区块链：多方协作/防篡改/存证溯源→联盟链(Fabric+PBFT)；共识口诀：匿名公链PoW/PoS，许可联盟PBFT。
- AI 话术：*「采用 RAG 提升准确率(功能)，向量缓存+量化控 P99<500ms(性能)，Guardrails 防泄露(安全)。」必须功能+非功能双答。*
- 可行性论述：技术/经济/运行/合规 四方面逐条。

**③ 致命禁句**
- ❌「Lambda 比 Kappa 好」→ ✅ 各有适用，按实时/历史权重选。
- ❌「区块链适合高并发高频交易」→ ✅ 吞吐低，适合留痕审计场景。
- ❌「联邦学习需要原始数据出域」→ ✅ 原始数据不出域，仅交换参数/梯度。
