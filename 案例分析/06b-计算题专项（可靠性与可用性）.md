## 二、三大时间指标

### 2.1 核心公式（死记这3行）

```
MTBF = MTTF + MTTR          ← 故障间隔 = 正常运行 + 修复时间
可用度 A = MTTF / MTBF      ← A = MTTF / (MTTF + MTTR)
停机时间 = 1 - A            ← 一年停机时长 = (1-A) × 8760小时
```

### 2.2 名词解释（配套记忆）

| 符号 | 名称 | 含义 | 单位 |
|------|------|------|------|
| **MTTF** | 平均无故障时间 | 系统正常运行多长时间才会坏一次 | 小时(h) / 分钟(min) |
| **MTTR** | 平均修复时间 | 系统坏了之后修好需要多久 | 小时(h) / 分钟(min) |
| **MTBF** | 平均故障间隔时间 | MTTF + MTTR，两次故障之间的平均时间 | 小时(h) / 分钟(min) |
| **A** | 可用度 | 系统处于可用状态的概率 | 小数（如0.9999） |

### 2.3 ⚠️ 致命陷阱：单位必须统一！

> **常见丢分场景**：MTTF=10000 小时，MTTR=60 分钟。不换算直接算：A=10000/(10000+60)≈0.994 → **错！**
>
> **正确做法**：先把 MTTR 换算成小时：60 分钟 = 1 小时
> ```
> A = 10000 / (10000 + 1) ≈ 0.9999
> ```

### 2.4 可用度与"几个9"的对应（考场直接写）

| 可用度 | 几个9 | 年停机时间 | 适用场景 |
|--------|:-----:|------------|----------|
| 0.99 | 两个9 | ~87.6 小时 | 普通办公系统 |
| 0.999 | 三个9 | ~8.76 小时 | 企业核心系统 |
| 0.9999 | 四个9 | ~52.6 分钟 | 金融交易系统 |
| 0.99999 | 五个9 | ~5.26 分钟 | 电信级系统 |

### 2.5 典型真题示例

> **题目**：监管要求系统可用性 ≥ 99.99%，当前 MTTR = 5 分钟。
>
> **问题①**：为满足 99.99% 可用度，MTTF 至少需多少？
>
> **解**：
> ```
> A = MTTF / (MTTF + MTTR) ≥ 0.9999
> MTTF ≥ 0.9999 × (MTTF + 5)
> MTTF ≥ 0.9999×MTTF + 4.9995
> 0.0001×MTTF ≥ 4.9995
> MTTF ≥ 49995 分钟 ≈ 833.25 小时
> ```

## 三、串并联可靠度计算

### 3.1 核心公式（死记这2行）

```
串联系统：R总 = R1 × R2 × … × Rn        ← 任一坏，全坏
并联系统：R总 = 1 - (1-R1)(1-R2)…(1-Rn) ← 全坏，才全坏
```

### 3.2 理解原理（一句话）

- **串联**：像链条，最弱一环决定整体。公式是"乘法"，越多组件越不可靠。
- **并联**：像备用轮胎，一个坏了还有另一个。公式是"1 - 各失效概率的乘积"。

### 3.3 混联系统（三步走）

**原则：先算并联子树，再与串联部分相乘。**

> **真题样本**：系统由 R1=0.9 串联（R2=0.8 ∥ R3=0.8）组成
>
> **解**：
> ```
> 第一步：算并联子树
>   R23 = 1 - (1-0.8)(1-0.8) = 1 - 0.04 = 0.96
>
> 第二步：算整体串联
>   R总 = R1 × R23 = 0.9 × 0.96 = 0.864
> ```

### 3.4 考场速判口诀

> **"信号走所有组件 → 串联；任选一个即可 → 并联"**

### 3.5 完整真题示例

> **题目**：某金融交易系统，前端接入层可靠度 R前=0.95，后端业务层有两个相同部件并联冗余，每个可靠度 R后单=0.9。
>
> **问题①**：后端并联部分可靠度是多少？
> **问题②**：整体系统可靠度是多少？
>
> **解**：
> ```
> 问题①：
>   R后并 = 1 - (1-0.9)(1-0.9) = 1 - 0.01 = 0.99
>
> 问题②：
>   R总 = R前 × R后并 = 0.95 × 0.99 = 0.9405
> ```
>
> **结论**：整体可靠度 94.05%，不满足 99.99% 可用性要求，需增加冗余。

## 四、N 模冗余（TMR）

### 4.1 三模冗余（TMR）公式

```
R_TMR = 3R²(1-R) + R³ = 3R² - 2R³
```

**原理**：三个模块独立运行，多数表决（2/3 通过即通过）。出错情况有两种：
- 恰好 2 个坏（1个正常）：C(3,2) × R² × (1-R) = 3R²(1-R)
- 恰好 3 个都坏：R³

### 4.2 典型计算

> **题目**：单模块可靠度 R = 0.9，采用三模冗余后系统可靠度是多少？
>
> **解**：
> ```
> R_TMR = 3×0.9² - 2×0.9³
>       = 3×0.81 - 2×0.729
>       = 2.43 - 1.458
>       = 0.972
> ```
> **结论**：从 0.9 提升到 0.972，提升显著。

### 4.3 N 模冗余速记

| N | 表决方式 | 可靠度公式 |
|---|----------|-----------|
| 2（并联） | 2选1 | R = 1-(1-R单)² |
| 3（TMR） | 2/3表决 | R = 3R²-2R³ |
| 5 | 3/5表决 | R = 10R³(1-R)² + 5R⁴(1-R) + R⁵ |

> 📌 **考试高频**：TMR（三模冗余）必考，5模较少。

## 五、马尔可夫双机冷热备份模型

> **这是近年案例计算的"压轴题型"，难度最高，但套路固定，掌握模板即可。**

### 5.1 模型背景

系统有两台机器：
- **热备**：两台同时运行，一台故障另一台立即接管（无缝切换）
- **冷备**：一台运行，另一台待机，故障后才启动切换（有切换延迟）

考试主要考**双机热备**模型。

### 5.2 状态定义

| 状态 | 含义 | 可用度贡献 |
|------|------|-----------|
| **S₀** | 两台都正常运行 | 1（完全可用） |
| **S₁** | 一台运行，一台故障（热备切换中） | 1（仍可用，单模式运行） |
| **S₂** | 两台都故障 | 0（系统不可用） |

### 5.3 转移速率（λ = 故障率，μ = 修复率）

```
S₀ → S₁：速率 λ（一台故障）
S₁ → S₀：速率 μ（故障机修复）
S₁ → S₂：速率 λ（运行机也故障）
S₂ → S₁：速率 2μ（任一台修复，但通常 S₂→S₁ 速率取 μ）
```

### 5.4 稳态可用度公式（必背模板）

```
P₀ = μ(μ+λ) / [λ² + μ(μ+2λ)]
P₁ = λμ / [λ² + μ(μ+2λ)]
P₂ = λ² / [λ² + μ(μ+2λ)]

可用度 A = P₀ × 1 + P₁ × 1 + P₂ × 0
         = P₀ + P₁
         = (μ² + 2λμ) / (λ² + μ² + 2λμ)
```

### 5.5 解题模板（按步骤套）

> **题目**：双机热备系统，每台 MTTF=1000 小时，MTTR=10 小时。求系统可用度。
>
> **解**：
> ```
> 第一步：求故障率 λ 和修复率 μ
>   λ = 1/MTTF = 1/1000 = 0.001 /小时
>   μ = 1/MTTR = 1/10 = 0.1 /小时
>
> 第二步：代入公式
>   分子 = μ² + 2λμ = 0.1² + 2×0.001×0.1 = 0.01 + 0.0002 = 0.0102
>   分母 = λ² + μ² + 2λμ = 0.001² + 0.0102 = 0.000001 + 0.0102 ≈ 0.010201
>
> 第三步：求可用度
>   A = 0.0102 / 0.010201 ≈ 0.9999
> ```
>
> **结论**：系统可用度约 99.99%，满足金融系统要求。

### 5.6 关键技巧

- λ 和 μ 通常是题目直接给的，或者是 MTTF/MTTR 的倒数
- 公式记住 **A = (μ² + 2λμ) / (λ² + μ² + 2λμ)** 即可
- 考试时先写语义公式"可用度 = 正常状态概率之和"，再代入，有步骤分

## 六、效用树加权评分法

### 6.1 适用场景

题干要求"对多个候选方案进行质量属性评估，选出最优方案"时，用效用树加权评分。

### 6.2 公式（一句话）

```
方案加权总分 = Σ(各质量属性权重 × 该方案在该属性的得分)
```

### 6.3 解题模板

> **题目**：某系统需评估两种架构方案，质量属性及权重如下：性能(0.4)、可用性(0.3)、安全性(0.2)、可修改性(0.1)。两种方案在各属性得分（1-5分）如下表：
>
> | 属性 | 权重 | 方案A得分 | 方案B得分 |
> |------|:----:|:---------:|:---------:|
> | 性能 | 0.4 | 4 | 3 |
> | 可用性 | 0.3 | 3 | 5 |
> | 安全性 | 0.2 | 5 | 3 |
> | 可修改性 | 0.1 | 3 | 4 |
>
> **解**：
> ```
> 方案A加权总分 = 0.4×4 + 0.3×3 + 0.2×5 + 0.1×3
>               = 1.6 + 0.9 + 1.0 + 0.3
>               = 3.8
>
> 方案B加权总分 = 0.4×3 + 0.3×5 + 0.2×3 + 0.1×4
>               = 1.2 + 1.5 + 0.6 + 0.4
>               = 3.7
>
> 结论：方案A（3.8分）略优于方案B（3.7分），推荐方案A。
> ```

### 6.4 注意事项

- 权重之和必须等于 1（或 100%）
- 得分通常为 1-5 分（1=极差，5=极佳）
- 答题时写明公式→代入→算出→结论，四步缺一不可

## 七、风险指数

### 7.1 公式

```
风险指数 = 发生概率 × 影响程度
```

### 7.2 典型考法

> **题目**：识别系统的 Top3 风险并计算风险指数。
>
> **解**：
> | 风险 | 概率(1-5) | 影响(1-5) | 风险指数 |
> |------|:---------:|:---------:|:--------:|
> | 数据库单点故障 | 4 | 5 | 20 |
> | 第三方服务不可用 | 3 | 4 | 12 |
> | 网络延迟过高 | 3 | 3 | 9 |
>
> **结论**：数据库单点故障风险最高（指数20），优先通过冗余/集群解决。

## 八、准计算小题

### 8.1 缓存命中率（题型3偶考）

```
命中率 = 命中次数 / 总请求数
```

> **真题示例**：某缓存系统总请求 10000 次，未命中 800 次，求命中率。
> ```
> 命中率 = (10000 - 800) / 10000 = 92%
> ```

### 8.2 布隆过滤器误判率（题型3偶考）

```
误判率 ≈ (1 - e^(-kn/N))ᵏ
```
- k = 哈希函数个数
- N = 元素个数
- n = 布隆过滤器比特位数

> 考试一般只要求**定性判断**：布隆过滤器可能有误判（假阳性），但不可能漏判（假阴性）。

### 8.3 消息队列分区数与 TPS（题型4偶考）

> **关键结论**：单分区吞吐量有上限（如 Kafka 单分区约 100MB/s）。所需分区数 ≈ 总 TPS / 单分区能力。
>
> **答题话术**："直接选用 Kafka 而不计算分区数的方案会被判定为缺乏定量分析能力。"

### 8.4 分库分表容量估算（题型3偶考）

```
单表数据量 = 总数据量 / 分表数
预估存储 = 单表数据量 × 单条记录大小 × 1.5（预留空间）
```

## 九、考场答题五步法

> **计算题是案例题里唯一的"公式对就给分"的客观题，性价比极高。严格按以下步骤作答：**

### 第一步：画系统结构图

把题干里的组件关系画成串/并联拓扑，标出每个节点的可靠度。**这一步错了后面全错。**

```
示例：
  R前 ──┬── R2
        │
        └── R3
```

### 第二步：判断串并联

- 信号要走完**所有**组件 → **串联**
- 多个组件**任选一个**即可 → **并联**
- 混联 → 先算并联子树，再算串联

### 第三步：统一单位

MTBF / MTTR 的时间单位必须一致（全化为小时或全化为分钟）。

> **口决**："先换算，再代入，单位一致不扣分。"

### 第四步：写公式 → 代入 → 出结果

即使结果算错，公式写对也有分。务必分步写：

```
R并 = 1 - (1-0.9)² = 1 - 0.01 = 0.99
R总 = 0.95 × 0.99 = 0.9405
```

### 第五步：可用性换算成"几个9"

算出的可用度要能对应到工程语境：
- 99% = 普通办公
- 99.9% = 企业核心
- 99.99% = 金融交易
- 99.999% = 电信级

若题目要求"99.99%"，你算出来是 99.9%，要**明确指出**："不满足要求，需增加冗余。"

## 十、速记口诀总结

### 口诀一：串并联
> **串联相乘可靠性降，并联相并可靠性升。**
> 串联：R总 = R1 × R2 × … × Rn
> 并联：R总 = 1 - (1-R1)(1-R2)…(1-Rn)

### 口诀二：可用度
> **可用度 = 正常时间 ÷ (正常 + 停机)**
> MTBF = MTTF + MTTR，单位统一别忘记！

### 口诀三：TMR
> **三模冗余用表决，3R²-2R³ 直接套。**
> R=0.9 时 TMR=0.972，提升显著记牢它。

### 口诀四：马尔可夫
> **双机热备三状态，S0全好S1单好S2全坏。**
> 可用度 = (μ²+2λμ) / (λ²+μ²+2λμ)

### 口诀五：效用树
> **加权总分 = Σ(权重 × 得分)，权重之和必为一。**

### 口诀六：风险指数
> **风险 = 概率 × 影响，数值越大越要防。**

## 附：典型综合真题演练

> **题目**：某金融交易系统监管要求可用性 ≥ 99.99%，当前 MTTR=5 分钟。后端业务层有两个相同部件做并联冗余，每个可靠度 0.9；前端接入层独立部件可靠度 0.95。
>
> **问题①**：为满足 99.99% 可用性，MTTF 至少需多少？
> **问题②**：该混联架构整体可靠度是多少？
> **问题③**：系统是否满足监管要求？如不满足，提出改进方案。
>
> **完整解答**：
>
> **① 求最小 MTTF**
> ```
> A = MTTF / (MTTF + MTTR) ≥ 0.9999
> MTTF ≥ 0.9999 × (MTTF + 5)
> MTTF - 0.9999×MTTF ≥ 4.9995
> 0.0001×MTTF ≥ 4.9995
> MTTF ≥ 49995 分钟 ≈ 833.25 小时
> ```
>
> **② 求混联架构可靠度**
> ```
> 并联部分（后端）：R后并 = 1 - (1-0.9)² = 1 - 0.01 = 0.99
> 整体串联：R总 = R前 × R后并 = 0.95 × 0.99 = 0.9405
> ```
>
> **③ 判断与改进**
> ```
> 0.9405 = 94.05%，远低于 99.99% 要求，不满足。
>
> 改进方案（答出2-3条即可）：
> 1. 前端接入层也做冗余：R前并 = 1-(1-0.95)² = 0.9975
>    R总 = 0.9975 × 0.99 = 0.9875，仍不满足
> 2. 后端并联改为三模冗余（TMR）：
>    R后TMR = 3×0.9² - 2×0.9³ = 0.972
>    前端也冗余：R总 = 0.9975 × 0.972 = 0.9696，仍不足
> 3. 提高单部件可靠度至 0.99：
>    R后并 = 1-(1-0.99)² = 0.9999
>    R总 = 0.95 × 0.9999 = 0.9499，仍不足
> 4. 前后端均用 TMR，单部件 R=0.95：
>    R后TMR = 3×0.95² - 2×0.95³ = 0.99975
>    R总 = 0.99975 × 0.99975 ≈ 0.9995，接近但不满足
>    需进一步各部件可靠度提升至 0.99 或采用双机热备马尔可夫模型
> ```
