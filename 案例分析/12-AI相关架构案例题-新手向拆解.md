# 0. 开场：本模块在考试里的位置 + 黑话速查表 + 用法

## 0.1 它在考试中是什么地位

| 项目 | 说明 |
|------|------|
| 属于 | **题型 5 · 专项架构与新技术（选做题）** 的 AI 子方向；也可与**试题四（高并发）/ 试题一（质量属性）**结合出题 |
| 分值 | 选做题每题约 **25 分**，全套 5 题选 3 题作答（第 1 题必答），满分 75 分，**45 分及格** |
| 趋势 | **2026 上半年已考** AIoT 四层、多模态大模型测试 **2 道**；**2026 下半年 AI 至少占 1 题**，且题型从"名词解释"转向"**架构设计 + 问题诊断**" |
| 难度 | 概念新，但**套路固定**——把 AI 组件翻译成通用架构手法就能拿分，不考训练细节、不考推导公式 |

> **给新手的定心丸**：AI 案例题**不考你写模型、不考你算梯度、不考你背论文**。它考的是"**能不能把 RAG / 推理 / Agent / 云边端这些组件，按场景正确地摆进架构图，并答出优缺点与问题对策**"。所以**记"每个 AI 组件对应哪套通用架构手法"比记模型原理重要 10 倍**。

## 0.2 新手黑话速查表（**先扫一遍，后面就不卡壳了**）

| 黑话 | 人话解释 |
|------|----------|
| **RAG** | **开卷考试** —— 答题前先去向量库翻资料，再结合资料生成，解决大模型胡编（幻觉） |
| **Embedding / 向量化** | 把文字变成一串数字（向量），**意思越近，数字越像**，才能"按相似度找" |
| **向量数据库** | 一种**按"相似度"而不是按"精确匹配"**查询的存储（传统库按 `=` 查，它按"最近邻"查） |
| **ANN 近似最近邻** | 向量检索的加速算法，牺牲一点点精度换海量数据的**毫秒级**召回 |
| **召回率 / 延迟 / 容量** | 向量库选型三指标：**找得准不准、快不快、装不装得下** |
| **训练 / 推理** | 训练 = **读书**（离线批处理，耗算力）；推理 = **答题**（在线实时，要快要省） |
| **量化 / 蒸馏** | 量化 = 把浮点换低精度整数（**变小变快**）；蒸馏 = **大模型教小模型** |
| **PagedAttention** | 显存的"**虚拟内存分页**"，把 KV Cache 分页复用，提升吞吐 |
| **语义缓存** | 相似问题**直接用上次答案**，省一次推理（降本神器，但**有污染风险，诊断题必考**，见 §5.2） |
| **模型路由** | 简单问题走小模型、难问题走大模型（**省成本**） |
| **Agent / 智能体** | 会**规划 → 调工具 → 记事 → 自查**的 AI 实习生 |
| **MCP / A2A** | MCP = Agent **接工具**的协议；A2A = Agent **之间互相通话**的协议 |
| **云边端 / AIoT** | 端=设备（感知）；边=就近处理（低时延）；云=全局（训练/存储）；或 感知/边缘/决策/应用 四层 |
| **Guardrails 护栏** | AI 的"安检三层"：**输入防注入、模型防幻觉、输出防泄密** |
| **提示词注入** | 用户用特殊话术骗模型干坏事（如"忽略之前指令"） |
| **LLMOps** | 把大模型推理当**生产服务**来运维（部署、弹性、监控、成本） |

| 定位 | 主攻 / 备选方向 | 说明 |

# 2. AI × 架构风格辨析（必答题最爱考）

> 对应**必答题最爱考的"架构风格辨析"** ｜ 2026 上半年必答题考的就是"管道‑过滤器 vs 批处理"。AI 流水线天然是**管道‑过滤器**，这块是送分也是拉分点。

## 🧊 直觉：同一个 AI 系统，换个"风格眼镜"看

命题人不一定问"这是什么 AI 组件"，他可能问"**这整套系统体现了哪种软件架构风格？和另一种有什么区别？**"——这就是必答题的辨析套路。你要把 AI 场景**翻译成经典架构风格**。

## 📖 原理拆解：AI 场景 → 架构风格 映射表（**必背**）

| AI 场景 | 对应架构风格 | 辨析关键词（踩分点） |
|---------|--------------|----------------------|
| **RAG 链路、数据预处理流水线** | **管道‑过滤器 Pipe‑Filter** | 流式、各过滤器**可并行、易扩展替换**、数据沿管道单向流动 |
| **模型训练平台（写代码→解析→执行）** | **解释器 Interpreter** | 用户写代码，平台**解析后执行**，用户无需关心底层硬件/调度 |
| **知识库 / 知识图谱多源融合** | **仓库 / 黑板 Repository / Blackboard** | 多知识源**共享中央存储、协同求解**，各模块读同一黑板 |
| **多智能体事件触发协同** | **隐式调用 / 事件驱动 Implicit Invocation** | **松耦合**、触发者**不知道谁在处理**，靠事件广播 |
| **批量离线推理任务** | **批处理 Batch** | 一次性攒一批、离线跑、与管道‑过滤器对比见下 |

## 🎯 怎么考（必答题高频辨析）

| 问法 | 典型提问 |
|------|---------|
| ① 风格判定 | "RAG 数据预处理流水线体现了哪种架构风格？说明特征。" |
| ② 对比辨析 | "管道‑过滤器 与 批处理 有何区别？各适合什么 AI 场景？" |
| ③ 联动 | "训练平台为何是解释器风格？与推理服务的风格有何不同？" |

## ✍️ 怎么答（模板）

**【模板：AI 场景 → 架构风格】**
> - **RAG / 预处理** → **管道‑过滤器**：文档切片、向量化、检索、重排、生成各环节为独立**过滤器**，沿管道**流式**处理，各过滤器**可并行、易替换扩展**；
> - **训练平台** → **解释器**：用户提交训练代码，平台**解析并执行**，屏蔽底层万卡调度；
> - **知识融合** → **仓库/黑板**：多源知识写入中央存储，各推理模块**共享协同求解**；
> - **多智能体** → **事件驱动（隐式调用）**：Agent 间靠**事件广播松耦合协同**，触发者不知谁处理；
> - **批量推理** → **批处理**：攒批离线执行。

**【模板：管道‑过滤器 vs 批处理（必背辨析）】**
> - **管道‑过滤器**：数据**流式**逐过各过滤器，**实时/近实时**、过滤器**并行可替换**，适合在线预处理/RAG 链路；
> - **批处理**：数据**攒成批**一次性处理，**高吞吐、离线**，适合训练、离线推理、海量 ETL；
> - **辨析点**：是否"流式 + 各阶段可独立替换并行"。RAG 检索段是管道‑过滤器，万卡训练是批处理，二者常**共存于同一 AI 系统不同链路**。

## ⚠️ 丢分点

1. ❌ **RAG 答成"批处理"** → RAG 检索段是**流式管道‑过滤器**，只有"离线批量推理"才归批处理，**别混**。
2. ❌ **管道‑过滤器只写"像流水线"** → 必须点出"**过滤器可并行、易扩展替换、单向流**"三个特征。
3. ❌ **漏"训练平台=解释器"** → 这是 2025 上真题联动点，用户写代码平台解析执行，**屏蔽底层**。
4. ❌ **多智能体答成"主从调用"** → 事件驱动的核心是**松耦合、触发者不知谁处理**，不是显式调用。

# 3. RAG（检索增强生成）：检索 + 生成两段式，中间夹向量库

> 对应考试热点 ｜ **超高频独立模块**，2026 上半年论文已考"向量数据库"，案例跟进 RAG 概率极高

## 🧊 直觉：开卷考试（两段式 + 中间夹存储）

**闭卷考试（纯大模型）**：只靠脑子记的答题 → 遇到没见过的、最新的信息，就**一本正经地胡说** = **幻觉（Hallucination）**。

**开卷考试（RAG）**：答题前先去**资料库翻一翻**，把相关内容摊在面前，再结合资料作答，还能**标注引用出处**。

```
用户提问
   │
   ├─【第一段：检索】→ 向量化 → 向量数据库召回相关片段
   │
   ├─【中间：向量库做存储】← 知识都提前切好、向量化、存这里
   │
   └─【第二段：生成】→ 把召回片段拼进 Prompt → 大模型生成 → 带引用来源的答案
```

> **一句话记住 RAG 的结构**：**检索 + 生成两段式，中间夹一个向量库做存储**。这比"RAG 是开卷考试"更具体到能画图——案例题常要你画/填这条链路。

## 📖 原理拆解

### 3.1 五步标准流程（**必背，画图/填空直接考**）

| 步骤 | 动作 | 踩分关键词 |
|------|------|-----------|
| ① **文档切片 Chunking** | 把知识 PDF/文档按段落切成 512 token 左右的小块 | 切片粒度、重叠（避免截断） |
| ② **向量化 Embedding** | 每块用 Embedding 模型变成向量 | bge‑large‑zh / m3e（领域词需微调或加词典，**论文弹药，案例只背"向量化"即可**） |
| ③ **向量检索 ANN** | 用户问句向量化，去向量库找**最相似的 Top‑K 块** | 近似最近邻、相似度 |
| ④ **重排 Rerank** | 把召回的 Top‑K 再精排，取最相关的 Top‑N | 混合检索（向量 + BM25 关键词） |
| ⑤ **生成 + 引用** | 把 Top‑N 拼进 Prompt，大模型作答，**末尾强制附出处** | 无依据不许答、引用必填校验 |

### 3.2 RAG vs 微调（**选型高频，必背**）

| 对比 | RAG | 微调 Fine‑tune |
|------|-----|---------------|
| 做法 | **外挂知识库**，不改模型参数 | **改模型脑子**（调参数） |
| 知识更新 | **改库即可**，分钟级生效 | 要重新训练，成本高 |
| 引用出处 | **能**（基于检索片段） | 不能 |
| 适用 | **知识频繁更新 / 要引用 / 防幻觉** | 风格格式固定 / 任务专一 |

> 🔥 **选型口诀**：**知识更新频繁、要引用出处 → RAG；风格格式固定、任务专一 → 微调。**

### 3.3 落地问题与对策（**案例诊断题标配**）

| 问题 | 根因 | 对策 |
|------|------|------|
| **召回不准**（专业词多义） | 纯向量召回受一词多义干扰 | **混合检索**（向量 + BM25 关键词）+ 领域词典扩展 |
| **幻觉**（编造未检索到的限值） | 模型自由发挥 | Prompt 硬约束"**无依据不许作答**" + 引用必填校验 |
| **知识滞后** | 标准更新后向量库没更新 | **增量索引管道**：新标准发布即触发切片+向量化，旧片段标记失效 |

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 架构设计 | "为某企业知识库问答系统设计架构，解决幻觉问题。" |
| ② 链路填空 | "补全 RAG 流程：Query → ？ → ？ → 大模型生成 → ？" |
| ③ 选型论述 | "为何选 RAG 而非微调？说明理由。" |
| ④ 问题诊断 | "系统问答准确率低、偶有编造，分析根因并给出对策。" |

## ✍️ 怎么答（模板）

**【模板：RAG 架构设计（问题 1 直接默写）】**
> 采用 **RAG（检索增强生成）架构**，流程为 **用户 Query → 向量化 → 向量数据库检索召回相关片段 → 混合重排取 Top‑N → 拼接进 Prompt → 大模型基于上下文生成 → 输出并标注引用出处**。
> **解决的问题**：① **幻觉** —— 答案基于检索到的真实文本生成，避免编造；② **知识时效性** —— 知识更新只需**更新向量库、无需重新训练模型**；③ **可追溯** —— 可标注引用出处，便于核对与合规审计。
> **关键设计**：① 文档**切片**（512 token、重叠 64）后**向量化（Embedding）**写入向量库；② 检索采用**向量 + BM25 混合检索 + 重排**提升召回准确率；③ 生成侧以 **Prompt 约束"仅依据检索片段作答、附出处"**，并做**引用必填校验**抑制幻觉。

**【模板：RAG vs 微调选型】**
> 选 **RAG** 而非微调：本系统知识**更新频繁**（每周数十份新文件）、且要求**回答可标注出处、不允许编造**。RAG 通过**外挂知识库**解决幻觉与时效性问题，更新知识只需刷新向量库；微调改的是模型参数，**无法解决知识时效、也不能提供引用出处**，且重训成本高。

## ⚠️ 丢分点

1. ❌ **把 RAG 答成"微调"** → 最高频失分。**RAG = 外挂知识库、不改模型**；微调 = 改参数。看关键词"更新频繁/要引用"→ RAG。
2. ❌ **只说"检索+生成"漏掉"中间夹向量库"** → 题干常要画/填链路，**向量库是中间存储底座**，漏它链路就不闭环。
3. ❌ **召回不准只答"换更好的模型"** → 标准对策是**混合检索（向量+BM25）+ 领域词典**，不是单纯换 Embedding。
4. ❌ **幻觉对策漏"引用必填校验"** → "Prompt 约束无依据不许答 + 引用必填校验"是一对，**只写一条不完整**。
5. ❌ **切片粒度不提"重叠"** → 切片要带**重叠（overlap）**避免语义在边界被截断，这是细节加分点。

# 4. 向量数据库：按"相似度"查询的存储

> 对应 RAG 的存储底座 ｜ **选型/填空高频**

## 🧊 直觉：图书馆按"意思相近"找书

**传统数据库（精确匹配）**：你问"书名是《红楼梦》吗？" → 它按 `=` 精确比对，书名不对就找不到。

**向量数据库（相似度匹配）**：你问"**帮我找本讲家族兴衰、儿女情长的书**" → 它把你的话变成向量，去书库里找**意思最相近**的那本（哪怕书名完全不同）。

> **一句话记住**：传统库按"**叫什么名字**"找，向量库按"**是什么意思**"找。RAG 的检索段就是把知识变成向量，再"按意思就近捞"。

## 📖 原理拆解

### 4.1 核心机制（**必背**）

| 概念 | 人话 | 答题关键词 |
|------|------|-----------|
| **Embedding** | 文字 → 一串数字向量，**意思越近数字越像** | 语义表示 |
| **相似度度量** | 用**余弦相似度 / 内积**算两个向量多像 | 余弦 / 欧氏距离 |
| **ANN 近似最近邻** | 海量向量下**不穷举全部**，用索引（HNSW/IVF）近似找最近的，换速度 | 索引、近似、毫秒级 |
| **元数据过滤** | 向量检索同时按"部门=财务"等条件过滤 | 标量过滤、混合 |

### 4.2 选型三指标（**简答必写全**）

| 指标 | 含义 | 考题怎么问 |
|------|------|-----------|
| **召回率 Recall** | 相关片段**找没找全**（准不准） | "回答经常漏关键点"→ 召回率不足 |
| **延迟 Latency** | 一次检索**多快**（毫秒级） | "实时问答卡顿"→ 延迟不达标 |
| **容量 Capacity** | 能**装多少**向量（亿级？） | "知识库海量增长"→ 容量/扩展性 |

> **记忆口诀**：**"准（召回）、快（延迟）、装（容量）"**。

### 4.3 常见选型（**填空/选型**）

| 产品 | 特点 | 适用 |
|------|------|------|
| **Milvus** | 分布式、海量、开源，ANN 索引丰富 | 企业级大规模（本题常用） |
| **Faiss** | 轻量、单机、高性能 | 中小规模、嵌入业务进程 |
| **Elasticsearch（kNN）** | 既有全文检索又有向量 | 已用 ES 的团队，混合检索方便 |
| **国产 / 华为云 / 腾讯云向量库** | 自主可控场景 | 信创要求 |

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 概念题 | "什么是向量数据库？与传统关系库有何区别？" |
| ② 选型题 | "RAG 系统应选什么存储？从召回率/延迟/容量说明。" |
| ③ 填空 | "将 Milvus / Faiss / ES 填入架构图对应位置。" |

## ✍️ 怎么答（模板）

**【模板：向量库选型（万能骨架）】**
> RAG 的检索段需一种**按语义相似度（而非精确匹配）查询**的存储，即**向量数据库**：将文档切片经 **Embedding 向量化**后写入，检索时把问句向量化，通过 **ANN 近似最近邻索引（如 HNSW）** 毫秒级召回 Top‑K 相似片段。
> **选型依据三指标**：① **召回率** —— 相关片段找全（混合检索+重排可提升）；② **延迟** —— 在线问答要求毫秒级；③ **容量** —— 知识库持续增长需支持亿级向量与水平扩展。
> 本项目选 **Milvus**（分布式、海量、ANN 索引丰富）；若已用 ES 也可选其 **kNN 能力**做混合检索；信创场景选国产向量库。

## ⚠️ 丢分点

1. ❌ **说"向量库就是存向量文件的数据库"** → 关键是"**按相似度查询**"，不是"存向量"而已。
2. ❌ **选型只写名字不写三指标** → 必须答"**召回率/延迟/容量**"三个维度，否则像背书。
3. ❌ **把 ANN 说成"精确全量扫描"** → ANN = **近似最近邻、用索引加速**，牺牲一点精度换速度。
4. ❌ **余弦相似度说成"等于判断"** → 它是**算两个向量多像**（余弦/内积），不是 `=` 匹配。
5. ❌ **漏"元数据过滤/混合检索"** → 真实系统常"向量 + 标量条件（如部门）"联合，高分要提。

# 5. 模型推理服务：一个高延迟、高算力消耗的"普通服务"

> 对应 LLMOps ｜ **2026 下半年高概率**，本质是"把大模型推理当生产服务运维"

## 🧊 直觉：一个特别慢的"计算器"

把大模型推理想象成一台**超级慢、超级费电的计算器**：
- 算一道题（生成一个回答）要**几百毫秒到几秒**（高延迟）；
- 算一题要吃掉**一张 GPU 卡的大量算力**（高算力）；
- 同时来 1000 人排队算 → 卡被占满、后面全超时。

**关键认知**：它**本质就是一个"高延迟、高算力消耗的普通服务"**。所以——**你学过的所有高并发/高可用手法，直接套！**

```
普通高并发服务怎么做？          模型推理服务就怎么做：
缓存热点结果        →          语义缓存（相似问题复用答案）
异步解耦          →          请求入队、异步生成、回调
门口限流          →          网关/推理网关限流（保护 GPU）
加机器/弹性       →          HPA 按 GPU 利用率/队列长度扩缩容
降本              →          模型路由（简单走小模型）+ 量化（变小变快）
```

## 📖 原理拆解

### 5.1 推理服务的"通用手法"映射（**核心踩分表**）

| 通用架构手法 | 在推理服务里的落地 | 解决什么 |
|------------|------------------|---------|
| **缓存** | **语义缓存**：相似问法命中上次答案 | 省一次推理、降延迟与成本 |
| **异步** | 请求进 **MQ/任务队列**， worker 异步生成，完成回调 | 削峰、防超时、提升吞吐 |
| **限流** | **推理网关**按 Token/QPS 限流，超限拒绝或排队 | 保护昂贵 GPU 不被打垮 |
| **弹性伸缩** | **HPA** 基于 **GPU 利用率 / 请求队列长度**扩缩 Pod | 流量波动时保延迟 |
| **模型路由** | 简单问题→小模型，复杂→大模型 | 降本 |
| **压缩加速** | **INT8/INT4 量化、蒸馏、PagedAttention、投机采样** | 变小变快、提吞吐 |

### 5.2 语义缓存的"坑"：好处之外必考风险（**案例诊断题高频**）

> ⚠️ **别只写好处**！案例诊断题最爱问"**新措施带来什么新问题**"。语义缓存是降本神器，但**有污染风险**：

| | 说明 |
|---|------|
| **风险** | **语义相似 ≠ 答案相同**。时间敏感类（"今天/昨天股价""当前库存"）、个性化类（"我的订单到哪了"）问题，语义命中会**返回错误答案 = 缓存污染** |
| **对策①** | 缓存 key **叠加用户 / 时效维度**（user_id + 日期），避免串味 |
| **对策②** | 设 **TTL** 自动过期，过期数据不回放 |
| **对策③** | 对**时效敏感类目禁用语义缓存**，走实时推理（股价/库存/实时状态） |
| **对策④** | **相似度阈值调高**，避免"勉强相似"也命中 |
| **对策⑤** | 命中后做**答案时效校验**（答案是否过期/是否适用当前用户） |

> 🔥 **阅卷加分话术**：算法工程师写"**缓存有污染风险，对时效/个性化类目禁用并叠加用户‑时效维度 key**"，阅卷人一眼就知道你是真做过的。

### 5.3 推理专属加速三件套（**名词解释常考**）

| 技术 | 生活类比 | 作用 |
|------|---------|------|
| **PagedAttention（vLLM）** | 显存"**虚拟内存分页**"，KV Cache 分页复用 | 显存利用率 20%→90%+，提吞吐 |
| **量化 INT8/INT4** | 精确到小数点后 8 位 → 只留整数 | 模型变小、算得快，精度略降 |
| **模型蒸馏** | **老师（大模型）教学生（小模型）** | 小模型学到本事，体积小数倍 |

### 5.4 成本治理（**政务/金融题必写**）

- **Token 成本监控**：记录每请求消耗 Token，设预算告警；
- **语义缓存命中率**：提升命中即降本（但需配合 §5.2 防污染）；
- **Spot 实例混合部署**：非实时批量推理用低价 Spot 卡。

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 优化题 | "P99 ≤ 500ms、2000 QPS、控成本，给出推理侧优化措施。" |
| ② 设计题 | "设计大模型问答服务的部署架构。" |
| ③ 诊断题 | "高峰时推理服务大面积超时 / 上了语义缓存反而答错，分析原因与对策。" |

## ✍️ 怎么答（模板）

**【模板：推理服务优化（万能骨架）】**
> 模型推理本质是**高延迟、高算力的普通服务**，采用"**通用高并发手法 + 推理专属加速**"组合优化：
> ① **缓存**：**语义缓存**，相似问法直接复用答案，省推理、降延迟与成本（**需叠加用户‑时效维度 key、设 TTL、对时效敏感类目禁用以防污染**）；
> ② **异步解耦**：请求入 **MQ/任务队列**，worker 异步生成并回调，削峰填谷防超时；
> ③ **限流防护**：**推理网关**按 Token/QPS 限流，保护昂贵 GPU 不被冲垮；
> ④ **弹性伸缩**：基于 **GPU 利用率 / 请求队列长度**的 **HPA** 自动扩缩容；
> ⑤ **加速压缩**：**PagedAttention（vLLM）** 分页复用 KV Cache、**INT8/INT4 量化**、**模型蒸馏**、**投机采样**；
> ⑥ **成本治理**：**模型路由**（简单走小模型）、**Token 消耗监控**、**Spot 实例**承载离线批量推理；
> ⑦ **可观测**：建设 **Token 监控、链路追踪、幻觉检测**，持续度量 P99 延迟。

## ⚠️ 丢分点

1. ❌ **把推理服务当"特殊黑盒"不套通用手法** → 最高频失分。**它就是高延迟普通服务，缓存/异步/限流/弹性全直接套**。
2. ❌ **只写"加 GPU"不写调度** → 完整答法要含 **HPA 弹性 + 队列 + 限流 + 成本治理**。
3. ❌ **量化说成"提高精度"** → 量化是**降低精度换速度/体积**（INT8/INT4），精度略降。
4. ❌ **PagedAttention 说不清** → 关键词："**KV Cache 分页复用、显存利用率提升、提吞吐**"。
5. ❌ **漏"语义缓存"和"模型路由"** → 这两个是**降本核心**，案例控成本题必写。
6. ❌ **语义缓存只写好处不写污染风险** → 诊断题必问"新措施带来什么问题"，必须答**污染风险 + 5 条对策（用户/时效 key、TTL、时效类禁用、阈值调高、命中校验）**。

```
                    ↑
              多智能体：父 Agent 编排，子 Agent 各管一摊（监测/分析/处置）
```

## 📖 原理拆解

### 6.1 Agent 三要素（**必背**）

| 要素 | 人话 | 答题关键词 |
|------|------|-----------|
| **规划 Planning** | 任务分解、反思（ReAct / CoT） | 任务拆解、自我修正 |
| **记忆 Memory** | 短期=对话上下文；长期=向量库持久化 | 上下文压缩、长期记忆外置 |
| **工具调用 Tool Use** | 调 API / 查库 / 发指令（Function Calling） | 工具注册发现、Schema 校验 |

### 6.2 多智能体协同（**五星押题**）

- **角色划分**：监测 Agent、分析 Agent、处置 Agent、编排器（Orchestrator）；
- **通信协议**：**MCP**（Agent 接工具）、**A2A**（Agent 之间通话），均归 Linux 基金会 AAIF 治理；
- **记忆外置**：关键状态落向量库，避免长链路"忘事"。

### 6.3 治理四件套（**案例方案题直接套**）

| 治理点 | 做法 | 关键词 |
|--------|------|--------|
| **编排** | 中央编排器分配子任务、汇总决策 | 角色边界、任务编排 |
| **工具接入** | 工具注册发现 + **Schema 强校验** | 防参数错误误调 |
| **权限管控** | **最小权限 + 危险操作人工确认/白名单** | 防越权、防误派单 |
| **降级兜底** | **最大步数上限 + 循环检测 + 超时熔断 + 异常转人工** | 防环路失控 |

### 6.4 破题素材借用法（**通用**）

若真考 Agent，可直接借用政策《智能体规范应用与创新发展实施意见》把智能体拆成的 **"感知、记忆、决策、交互、执行"五个能力要素**——这五个词天然就是一套架构分层，比自己编分层更容易被阅卷认可。

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 设计题 | "设计多智能体协同架构，说明角色与通信。" |
| ② 方案题 | "将告警人工派单改为 Agent 自动闭环，给出架构与治理。" |
| ③ 问题诊断 | "Agent 长链路忘事/误派单/循环失控，分析与对策。" |

## ✍️ 怎么答（模板）

**【模板：多智能体编排架构（万能骨架）】**
> 采用**多智能体协同架构**，由**编排器 Orchestrator** 统一分配子任务与汇总决策，下设**监测 Agent（收告警取上下文）、分析 Agent（调知识库研判等级）、处置 Agent（生成建议、调工单/接口）**等角色，遵循**《实施意见》"感知—记忆—决策—交互—执行"五能力要素**分层。
> **治理四件套**：① **编排** —— 角色边界清晰、任务编排机制；② **工具接入** —— 工具注册发现 + **Schema 强校验**防参数错误；③ **权限管控** —— **最小权限 + 危险操作人工确认/白名单**；④ **降级兜底** —— **最大步数上限 + 循环检测 + 超时熔断 + 异常转人工**。
> **通信**：Agent 接工具用 **MCP**，Agent 间协同用 **A2A**；**长期记忆外置向量库**，关键状态落库防"忘事"。

## ⚠️ 丢分点

1. ❌ **把 Agent 写成"一个大模型"** → 它是**编排层 + 工具调用**，不是单个模型。漏"工具接入/编排"丢大分。
2. ❌ **治理四件套只写"编排"** → 必须四样：**编排 + 工具接入 + 权限管控 + 降级兜底**。
3. ❌ **漏"权限管控/人工确认"** → Agent 最易越权误派单，**最小权限 + 危险操作人工确认**是安全得分点。
4. ❌ **环路失控无对策** → 必须答"**最大步数 + 循环检测 + 超时熔断 + 转人工**"。
5. ❌ **MCP / A2A 混** → **MCP = 接工具**；**A2A = Agent 间通信**。
6. ❌ **多智能体协同答成"主从显式调用"** → 事件驱动核心是**松耦合、触发者不知谁处理**（见 §2）。

# 7. 云边端 / AIoT：感知—边缘—决策—应用 四层

> 对应 2026 上半年案例已考 AIoT 四层 ｜ **论文跟进概率高**

## 🧊 直觉：眼睛 — 小脑 — 大脑 — 手脚

把智能系统想象成人：
- **端/感知层（眼睛）**：摄像头、传感器，**只负责看、只负责采**；
- **边/边缘层（小脑）**：小区机房的小盒子，**当场反应**（识别到可疑人员立刻报警），不把原始视频全传云；
- **云/决策层（大脑）**：中心云，**慢慢想大事**（训练模型、全局分析、跨域协同）；
- **应用层（手脚）**：把决策变成动作（App 推送、工单、大屏）。

> **两套说法等价**：
> - **三层**：端 — 边 — 云；
> - **四层**：感知层 — 边缘层 — AI 决策层 — 应用层。
> 案例题两种填空都可能出现，**会互译**。

### 为什么"边缘"这么重要（**边缘计算四价值**）

10 万路摄像头全传云 → 带宽爆炸、延迟 10 秒、隐私泄露。放边缘盒子就地分析 → **时延 100ms、带宽省 95%、原始数据不出小区、断网也能报警**。

> **记忆口诀**：**"快、省、私、稳"**（低时延 / 省带宽 / 隐私保护 / 离线可用）。

## 📖 原理拆解

### 7.1 四层职责（**填空/简答必背**）

| 层 | 职责（踩分词） | 典型组件 |
|----|---------------|---------|
| **感知层（端）** | 数据采集、执行指令 | 摄像头、传感器、执行器、嵌入式设备 |
| **边缘层（边）** | **就近实时处理、协议转换、断网自治** | 边缘网关、边缘节点、轻量模型推理 |
| **AI 决策层（云）** | **模型训练、全局分析、跨域协同** | 训练集群、向量库、知识库 |
| **应用层** | 业务呈现、动作执行 | App、工单系统、大屏、第三方集成 |

### 7.2 边缘 AI 推理 + 云端训练（**闭环**）

- **边缘**：端侧轻量化模型（量化/蒸馏后下发），**低时延推理**、断网自治；
- **云端**：**模型训练与 OTA 下发**，把新模型推到边缘执行；
- **协同**：边缘采数据 → 云训练 → 模型下发边缘 → 边缘执行，形成闭环。

### 7.3 11 组件归类（**2026 上半年真题题型**）

| 组件 | 归属层 |
|------|--------|
| 智能门禁控制器、生物识别、身份验证 | **感知层** |
| 周界保护、边缘网关 | **边缘层** |
| 视觉分析引擎、融合认知引擎、模型训练与 OTA | **AI 决策层（云）** |
| 事件中心、移动端应用、第三方系统集成 | **应用层** |

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 填空 | "将 11 个组件归类到感知/边缘/决策/应用四层。" |
| ② 价值题 | "说明云边端协同相比全上云的优势。" |
| ③ 设计题 | "设计智慧工厂 AIoT 架构，说明各层职责。" |

## ✍️ 怎么答（模板）

**【模板：云边端 AIoT 架构（万能骨架）】**
> 采用**端—边—云三层（或 感知—边缘—AI 决策—应用 四层）**协同架构：
> ① **感知层（端）**：传感器/摄像头/执行器**采集数据、执行指令**；
> ② **边缘层（边）**：**边缘网关/节点**做**就近实时处理、协议转换、断网自治**，达到**低时延、省带宽、隐私保护（原始数据不出本地）、离线可用**四价值；
> ③ **AI 决策层（云）**：中心云负责**模型训练、全局分析、跨域协同**，并将训练好的轻量化模型**OTA 下发**边缘；
> ④ **应用层**：将决策转化为**App 推送、工单、大屏、第三方集成**等动作。
> 端侧部署**量化/蒸馏后的轻量模型**做边缘推理，云边**闭环协同**（边采云训、模型下发边执行）。

## ⚠️ 丢分点

1. ❌ **只答"三层"不会翻"四层"** → 两套说法要会互译：端=感知、边=边缘、云=AI 决策、再加应用层。
2. ❌ **边缘价值只答"低时延"一条** → 四条：**低时延、省带宽、隐私保护、离线可用**。
3. ❌ **说"用边缘替代云"** → 正确是**边云协同**：边管"快"、云管"大"（训练与存储）。
4. ❌ **组件归类错层** → 口诀："**采/识/验在感知；网关/周界在边缘；分析/训练在决策；呈现/集成在应用**"。
5. ❌ **漏"模型 OTA 下发"** → 完整闭环是"边采 → 云训 → 模型下发边执行"。

# 8. 模型训练 vs 推理：离线批处理 vs 在线实时（两条链路）

> 对应 AI 基础设施 ｜ **天然对应"离线/在线两条链路"，是架构分层的送分题**

## 🧊 直觉：读书 vs 答题（两条完全不同的链路）

| | 训练 Training | 推理 Inference |
|---|---|---|
| 类比 | **读十年书**（一次性/周期） | **上考场答题**（每秒成千上万次） |
| 频率 | 周期性、低频 | **高频、实时** |
| 关心 | **吞吐、互联带宽、算力堆料** | **延迟、成本、并发** |
| 硬件 | 万卡 GPU 集群 | 少量 GPU / 推理卡 |
| 链路性质 | **离线批处理** | **在线实时** |

> **一句话记住**：**训练 = 离线批处理链路；推理 = 在线实时链路**。这俩需求几乎相反，所以**架构也分开设计**——不要试图用一套链路伺候两者。

## 📖 原理拆解

### 8.1 两条链路对照（**必背表**）

| 维度 | 训练链路（离线批处理） | 推理链路（在线实时） |
|------|----------------------|---------------------|
| 处理模式 | **批处理**、周期性 | **在线、逐请求** |
| 核心指标 | **吞吐、互联带宽** | **延迟（P99）、成本** |
| 网络 | **RDMA/RoCE 绕过 CPU**，万卡互联 | 普通服务网络 + 推理网关 |
| 弹性 | 训练任务级弹性（扩卡） | **HPA 按 QPS/队列** 扩实例 |
| 容错 | **Checkpoint 断点续训** | 实例重启/限流降级 |
| 故障恢复 | 目标 **≤5 分钟**（自动隔离+重调度） | 秒级重启 + 熔断 |

### 8.2 训练平台 = 解释器风格（**2025 上真题联动 + §2 架构风格**）

用户写 Python 模型代码 → **解析器** → **执行引擎** → **资源调度器** → **GPU 硬件**。用户无需关心底层硬件，符合**解释器风格**（见 `11` §5，亦见 [§2](#s2) 架构风格映射）。

### 8.3 训练集群高性能网络（**2025 真题方向**）

- **RDMA/RoCE**：绕过 CPU 极低时延，**万卡训练刚需**；
- **ECMP** 易哈希不均 → **包喷洒 Packet Spraying** 打散到多路径；
- **APSCC 拥塞控制** 动态调整阈值；
- **弹性 + 高可靠**：故障恢复 **≤5 分钟**。
> *（以上 RDMA/包喷洒/APSCC 为**论文弹药**，案例只背"万卡互联、RDMA、断点续训≤5 分钟"即可。）*

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 对比题 | "比较模型训练与推理在架构设计上的差异。" |
| ② 设计题 | "设计支持大模型训练与推理的云原生架构。" |
| ③ 诊断题 | "万卡训练拥塞/恢复超时，给出优化。" |

## ✍️ 怎么答（模板）

**【模板：训练 vs 推理双链路设计】**
> 训练与推理需求相反，应**分两条链路**设计：
> ① **训练链路（离线批处理）**：关心**吞吐与互联带宽**，采用**万卡 GPU 集群 + RDMA/RoCE 绕过 CPU**，**ECMP + 包喷洒**缓解哈希不均，**APSCC** 拥塞控制；通过 **Checkpoint 周期性保存状态 + 故障节点自动隔离重调度**实现**断点续训、恢复 ≤5 分钟**；
> ② **推理链路（在线实时）**：关心**延迟与成本**，采用 [§5](#s5) 的"缓存/异步/限流/弹性 + 量化/PagedAttention"组合，按 **GPU 利用率/队列 HPA** 扩缩；
> ③ **协同**：训练产出的模型**经 OTA/镜像下发**到推理集群与边缘，形成"**云训练—边/端推理**"闭环。

## ⚠️ 丢分点

1. ❌ **训练和推理需求混为一谈** → **训练要吞吐与互联带宽（RDMA）**；**推理要低延迟与成本（量化/PagedAttention）**。
2. ❌ **只用一套链路伺候两者** → 标准答法是"**分离线训练链路 + 在线推理链路**两条"。
3. ❌ **RDMA 说成"普通网卡加速"** → 它是**绕过 CPU 直接读内存**，万卡训练刚需，极低时延。
4. ❌ **故障恢复不写"≤5 分钟"** → 训练集群题常给"恢复 12 分钟不达标"，对策是压到 **≤5 分钟**（Checkpoint+自动重调度+演练）。
5. ❌ **漏"云训练—边推理闭环"** → 与 [§7](#s7) 联动，模型下发是闭环最后一环。

# 9. AI 的数据维度（补：训练数据治理 / 版本 / 血缘 / 特征一致性）

> 对应**下半年"数据治理 / 数据要素"红色重点** ｜ 上半年案例已考知识图谱（本质=数据），AI 题几乎必谈数据，本文件原 7 块对此覆盖少，这里补齐。

## 🧊 直觉：垃圾进，垃圾出（Garbage In, Garbage Out）

模型再聪明，喂的料不行就全完。AI 系统的"数据维度"决定了**上限、可复现、可审计、不翻车**。

## 📖 原理拆解

### 9.1 训练数据治理（**数据质量决定上限**）

| 要点 | 说明 | 踩分词 |
|------|------|--------|
| 数据清洗 | 去噪、去重、纠错 | 质量门禁 |
| 数据脱敏 | 个人信息/敏感字段脱敏后再训练 | PII 脱敏、合规 |
| 标注质量 | 标注一致性、复核机制 | 标注规范、抽检 |
| **特征一致性** | 训练与推理用**同一套特征逻辑**，防偏斜 | Feature Store、统一特征服务 |

### 9.2 数据集版本管理（Dataset Versioning）

- 数据集随模型迭代**打版本**，可**复现、可回滚**；
- 思路：数据血缘 + 版本标签（类似代码 Git），出问题能定位"哪版数据喂出的坏模型"。

### 9.3 数据血缘 Data Lineage

- 追踪"**数据从哪来、被谁改、喂给哪个模型**"；
- 用途：**合规审计 + 问题溯源**（模型答错 → 反查数据哪环污染）。

### 9.4 特征一致性（训练 / 推理特征偏斜 Training‑Serving Skew）— **高频诊断点**

| | 说明 |
|---|------|
| **根因** | 训练用**批处理特征**、推理用**实时特征**，口径/计算逻辑不同 → 线上效果骤降 |
| **对策** | **统一特征平台（Feature Store）**，离线在线**同一份特征代码**；特征计算逻辑集中管理、版本一致 |
| **验证** | 离线/在线特征输出比对，差异超阈值告警 |

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 数据治理 | "AI 系统如何保障训练数据质量与合规？" |
| ② 诊断 | "模型训练效果好、上线推理效果骤降，分析原因。" |
| ③ 知识图谱 | "知识图谱作为多源数据融合，如何做版本与血缘管理？" |

## ✍️ 怎么答（模板）

**【模板：AI 数据治理】**
> AI 系统需补齐数据维度：① **训练数据治理** —— 清洗去重脱敏、标注质量门禁；② **数据集版本管理** —— 数据随模型打版本、可复现回滚；③ **数据血缘** —— 追踪来源与加工链路，支撑合规审计与问题溯源；④ **特征一致性** —— 训练/推理共用 **Feature Store 统一特征逻辑**，消除特征偏斜（training‑serving skew），离线在线特征输出比对校验。知识图谱类多源融合，同样按"版本 + 血缘"管理。

## ⚠️ 丢分点

1. ❌ **AI 题只答模型不答数据** → 下半年数据治理是红色重点，**数据质量/版本/血缘/特征一致性**必写一条。
2. ❌ **特征偏斜只答"数据不一样"** → 必须点出"**训练批处理特征 vs 推理实时特征口径不同**" + 对策"**统一特征平台**"。
3. ❌ **知识图谱当纯算法** → 知识图谱**本质是多源数据融合**，要答数据治理（版本/血缘/融合冲突消解）。

# 10. AI 安全架构：三层护栏 + 四类风险 + 合规闭环

> 对应 2026 下半年"智能体安全治理"押题 ｜ **输入—模型—输出 三层 Guardrails + 合规管理双闭环**

## 🧊 直觉：AI 的"机场三层安检"

普通系统安全是"进门查一次"；AI 系统因为会**自己生成内容、自己调工具**，风险贯穿全程，所以要**三层都查**：

```
用户输入 →【输入安检】→ 大模型 →【模型安检】→ 生成内容 →【输出安检】→ 给用户
              防注入          防幻觉/对齐        防泄密/合规
```

同时，政策点名的 **四类风险** 要逐个有对策：
1. **提示词注入**（骗模型干坏事）
2. **误操作**（模型调错工具/参数）
3. **插件投毒**（第三方工具供应链带毒）
4. **权限失控**（Agent 拿到不该有的权限）

## 📖 原理拆解

### 10.1 Guardrails 三层防护（**简答/方案题直接考**）

| 层级 | 措施 | 答题关键词 |
|------|------|-----------|
| **输入防护** | 提示词注入检测、敏感词过滤、PII 识别脱敏 | 输入校验、PII 脱敏 |
| **模型防护** | 安全对齐（RLHF）、输出过滤、幻觉检测 | 安全对齐、幻觉检测 |
| **输出防护** | 引用溯源验证、合规检查、人工审核兜底 | 引用验证、人机协同 |

### 10.2 四类风险 ↔ 对策（**治理题标配**）

| 风险 | 对策 |
|------|------|
| **提示词注入** | 输入净化、指令与数据隔离（系统提示不可被用户覆盖）、注入检测 |
| **误操作** | 工具 **Schema 强校验** + 执行前确认 + 失败回滚 |
| **插件/工具投毒** | 工具**签名校验、白名单、供应链审计** |
| **权限失控** | **最小权限原则 + 危险操作人工确认/白名单** |

### 10.3 AI 专属合规闭环（**政务/金融题必写，补充：等保 + 信创**）

| 合规项 | 说明 | 踩分词 |
|--------|------|--------|
| **算法备案** | 有舆论属性或社会动员能力的算法需向**网信部门备案** | 算法备案 |
| **生成内容标识** | AI 生成内容需**显式/隐式标识（水印）** | 内容标识、溯源 |
| **数据安全评估** | 涉大量个人信息或**数据出境**时需评估 | 数据出境评估 |
| **等保 2.0** | 政务 AI 系统通常要求**等保三级** | 三级等保 |
| **信创适配** | 国产数据库、国产 OS、**国密算法 SM2/SM3/SM4** | 自主可控、国密 |

> 🔥 **答题金句（直接背）**："AI 系统安全需**技术防护与合规管理双闭环**：技术侧**三层 Guardrails + 四类风险分治**；合规侧**算法备案 + 内容标识 + 数据不出域 + 等保三级 + 信创适配（国密 SM2/SM3/SM4）**。"

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 设计题 | "设计大模型应用的安全与治理架构。" |
| ② 论述题 | "说明 AI 系统面临的安全风险及对策。" |
| ③ 合规题 | "政务 AI 需满足哪些合规要求？（等保/信创/备案）" |

## ✍️ 怎么答（模板）

**【模板：AI 安全治理架构（万能骨架）】**
> 构建 **输入—模型—输出 三层 Guardrails**：
> ① **输入防护** —— 提示词注入检测、敏感词过滤、PII 识别与脱敏；
> ② **模型防护** —— 安全对齐（RLHF）、输出过滤、**幻觉检测**；
> ③ **输出防护** —— 引用溯源验证、合规性检查、人工审核兜底；
> **四类风险分治**：提示词注入→输入净化+指令数据隔离；误操作→工具 Schema 校验+确认回滚；插件投毒→**签名校验+白名单+供应链审计**；权限失控→**最小权限+危险操作人工确认**；
> **合规闭环**：落实**算法备案、生成内容标识（水印）、数据安全评估**，敏感数据**脱敏且不出域**；政务系统满足**等保三级**，并做**信创适配（国产库/OS + 国密 SM2/SM3/SM4）**，实现技术防护与合规管理双闭环。

## ⚠️ 丢分点

1. ❌ **只答"加个防火墙"** → AI 安全是**三层护栏 + 四类风险分治**，不是单点防护。
2. ❌ **Guardrails 只写一层** → 必须 **输入/模型/输出** 三层都写。
3. ❌ **漏"插件投毒/供应链"** → 这是 2026 政策明点的风险，**签名校验+白名单**是标准对策。
4. ❌ **权限失控只写"加权限"** → 关键词是"**最小权限 + 危险操作人工确认/白名单**"。
5. ❌ **漏合规（算法备案/内容标识）** → 政务/金融题必写，**算法备案 + 生成内容标识 + 数据不出域**。
6. ❌ **政务题漏"等保三级 / 信创 / 国密"** → 政务 AI 默认**等保三级**；信创场景点**国产库/OS + SM2/SM3/SM4**，漏了扣分。

# 11. AI 与传统架构的融合（补充：微服务 / 缓存 / MQ / 数据库）

> 对应**"AI + 传统架构"融合题** ｜ 案例可能出交叉题，本文件原 7 块对这类覆盖少，这里补齐。

## 🧊 直觉：AI 不是另起炉灶，是"传统架构 + 一个 AI 组件"

推理服务本质就是个**高延迟普通服务**，所以它能直接套进你早已会的技术栈里。

## 📖 原理拆解

### 11.1 AI + 微服务

把推理能力拆成微服务：
- **模型路由层**：按问题难度分发大/小模型；
- **推理网关**：统一入口、限流、鉴权；
- **向量检索服务**：独立部署的向量库访问层；
- **Prompt 管理服务**：统一模板/版本管理。
- **治理**：直接套微服务的**注册发现、API 网关、熔断限流、链路追踪**。

### 11.2 AI + 缓存（语义缓存 vs 传统 Redis）

- **关系**：语义缓存是 **Redis 的上层**——先用**向量相似度**判断是否命中，命中走语义缓存；未命中再走 Redis 精确 key 或实时推理；
- **分工**：Redis 负责**精确 key 缓存、会话态、限流计数**；语义缓存负责**相似问法复用答案**（见 §5.2 防污染）。

### 11.3 AI + 消息队列

- 推理请求**入 MQ 异步处理**，削峰填谷；
- 处理完**回调通知**调用方，避免长连接超时。

### 11.4 AI + 数据库（向量库与传统关系库并存）

- **元数据过滤用关系库**（如"部门=财务""时间范围"）；
- **语义检索用向量库**（相似度召回）；
- 二者**联合查询**：关系库先缩范围，向量库再按语义精排。

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| ① 融合设计 | "将大模型推理能力接入现有微服务系统，给出架构。" |
| ② 缓存辨析 | "语义缓存与传统 Redis 缓存是什么关系？" |
| ③ 存储设计 | "RAG 系统如何同时使用关系库与向量库？" |

## ✍️ 怎么答（模板）

**【答题话术（直接背）】**
> "推理服务本质是一个**高延迟普通服务**，可直接套用微服务的**注册发现、API 网关、熔断限流、链路追踪**等治理手段；语义缓存是 **Redis 上层**，用向量相似度判断是否命中；推理请求入 **MQ 异步削峰、回调通知**；**向量库与传统关系库并存**——元数据过滤用关系库，语义检索用向量库，联合查询。"

## ⚠️ 丢分点

1. ❌ **把 AI 当完全独立系统** → 融合题要体现"**AI 组件嵌入既有技术栈**"，套微服务/MQ/缓存治理。
2. ❌ **语义缓存与 Redis 混为一谈** → 语义缓存是**上层（向量相似）**，Redis 是**精确 key**，二者互补不替代。
3. ❌ **向量库替代关系库** → 正确是**并存**：关系库管元数据/事务，向量库管语义检索。

# 12. AI 案例题新考法：问题诊断题（补充：性能 / 成本 / 安全 / 召回）

> 对应**题型从"架构设计"转向"问题诊断"** ｜ 统一框架：**根因 → 对策 → 验证指标**（三段式）。

## 🧊 直觉：不是让你"画架构"，是让你"看病开药方"

诊断题给一个**出问题的系统**，要你：① 找根因；② 给对策；③ 说怎么验证对策有效。

## 📖 四类高频诊断（**根因 → 对策 → 验证指标**）

### 12.1 性能诊断：推理服务 P99 超时

| | 内容 |
|---|------|
| **根因** | GPU 利用率高（算力瓶颈）、批处理参数不当、KV Cache 不足、语义缓存命中率低 |
| **对策** | 扩 GPU / **量化+PagedAttention** 提吞吐、调批大小与 KV Cache、提升语义缓存命中率（并防污染） |
| **验证** | P99 回落到阈值内、GPU 利用率均衡、缓存命中率上升 |

### 12.2 成本诊断：Token 成本过高

| | 内容 |
|---|------|
| **根因** | 模型路由缺失（全走大模型）、语义缓存命中率低、未量化、未用 Spot 实例 |
| **对策** | **模型路由**分层、提升语义缓存、**量化**压缩、离线批推理用 **Spot** |
| **验证** | 单请求 Token 成本下降、Spot 占比、命中率 |

### 12.3 安全诊断：Agent 误派单 / 越权

| | 内容 |
|---|------|
| **根因** | Schema 校验缺失、权限过大、**无人工确认、无循环检测** |
| **对策** | 工具 **Schema 强校验**、**最小权限 + 危险操作人工确认/白名单**、**最大步数+循环检测+超时熔断+转人工** |
| **验证** | 误派单率归零、越权拦截率、环路自停 |

### 12.4 召回诊断：RAG 召回不准

| | 内容 |
|---|------|
| **根因** | 切片粒度不当、**无重叠**、纯向量受一词多义干扰、**无重排** |
| **对策** | 调切片粒度+**加重叠**、**混合检索（向量+BM25）+ 领域词典**、加**重排** |
| **验证** | 召回率/答案准确率上升、相关片段覆盖全 |

## 🎯 怎么考

| 问法 | 典型提问 |
|------|---------|
| 性能 | "推理服务高峰 P99 超时，分析根因与对策。" |
| 成本 | "Token 成本高企，如何降本？" |
| 安全 | "Agent 误派单/越权，分析原因与对策。" |
| 召回 | "RAG 问答准确率低，分析根因与对策。" |

## ✍️ 怎么答（模板）

**【诊断题万能框架：根因 → 对策 → 验证指标】**
> ① **根因**：……（定位到具体组件/参数）；② **对策**：……（对应通用手法）；③ **验证指标**：……（用可量化指标证明对策有效）。

## ⚠️ 丢分点

1. ❌ **只写对策不写根因** → 诊断题**根因是前半分**，必须"先定位再开方"。
2. ❌ **不写验证指标** → "对策是否有效"要用**指标**说话（P99、命中率、误派单率、召回率）。
3. ❌ **召回不准只换 Embedding** → 标准对策是**混合检索 + 重叠 + 重排**。

# 13. AI 系统"缺点 / 不足"清单（补：高频"写 5 个缺点"）

> 对应**上半年 AIoT 那道"写出 5 个缺点"（10 分）** ｜ 这类问法在 AI 题里几乎必现。下面 10 条可直接挑 5 条抄。

## 📖 10 条缺点清单（**背熟，按场景挑**）

| # | 缺点 | 一句话 |
|---|------|--------|
| ① | **幻觉不可根除** | 模型可能编造，RAG/对齐只能压不能绝 |
| ② | **推理成本高** | GPU/Token 消耗大，规模上来费用陡增 |
| ③ | **延迟大、首响应慢** | 生成式推理天然高延迟，首 token 慢 |
| ④ | **可解释性差、黑盒** | 决策过程难追溯，难向监管/用户解释 |
| ⑤ | **模型迭代致行为漂移** | 换版/微调后表现漂移，**回归测试难** |
| ⑥ | **强依赖数据质量** | 垃圾进垃圾出，**冷启动难**（无数据时无能力） |
| ⑦ | **新攻击面** | 注入/越权/**插件投毒**等传统系统没有的风险 |
| ⑧ | **效果难量化评估** | 生成质量无单一指标，评估主观 |
| ⑨ | **边缘算力受限** | 端侧设备算力/功耗天花板，模型需狠压缩 |
| ⑩ | **模型/供应商锁定** | 绑死某厂商大模型/云，迁移成本高 |

## 🎯 按场景挑 5 条（**直接抄**）

| 场景 | 挑哪 5 条 |
|------|-----------|
| **政务题** | ①④⑥⑦⑩（幻觉 / 黑盒 / 数据依赖 / 新攻击面 / 锁定） |
| **边缘题** | ③⑥⑨①②（延迟 / 数据依赖 / 边缘算力 / 幻觉 / 成本） |
| **成本题** | ②⑧①③⑤（成本 / 难量化 / 幻觉 / 延迟 / 漂移） |

> 🔥 **答题技巧**：挑的 5 条要**贴题干场景**，别乱抓。政务挑"可信/合规/安全"向，边缘挑"算力/延迟"向，成本挑"钱/评估"向。

## ⚠️ 丢分点

1. ❌ **只写 1~2 条** → "写 5 个"就要满 5 条，凑不够直接丢分。
2. ❌ **5 条不贴场景** → 政务写"边缘算力受限"就偏了，按上表挑。
3. ❌ **把缺点写成优点** → 例如写"推理快"当缺点，自相矛盾。

# 14. 三套完整模拟题演练（带参考答案）

> **怎么用**：先自己写要点（限时，每题约 25 分钟），再对照答案。重点看"答案是怎么组织的"。

---

## 📝 模拟题一：企业政策智能问答（RAG + 向量库 + 推理）

**【背景】**
某企业有海量产品手册与政策文件（每周更新数十份），客服大模型直接作答时**经常编造条款、且答不出出处**，高峰并发 **1500 QPS**、要求 **P99 ≤ 600ms**。

**【问题 1】（9 分）** 为解决"编造 + 无出处 + 知识更新频繁"，应采用什么架构？说明流程与存储底座。

**【问题 2】（8 分）** 针对"P99 ≤ 600ms、1500 QPS、控成本"，给出推理侧与检索侧优化措施。

**【问题 3】（8 分）** 系统偶尔召回无关内容、仍有少量编造，分析原因与对策。

---

### ✅ 参考答案

**【问题 1】**
采用 **RAG（检索增强生成）架构**，结构为 **检索 + 生成两段式，中间夹向量数据库做存储**：
- **流程**：用户 Query → **向量化** → **向量数据库 ANN 召回**相关片段 → **混合重排（向量+BM25）取 Top‑N** → 拼入 Prompt → **大模型生成 + 强制标注引用出处**；
- **存储底座**：文档切片（512 token、重叠 64）经 **向量化（Embedding）**写入**向量数据库（Milvus）**；
- **解决问题**：① **幻觉**（基于真实文本生成）；② **知识时效**（更新只需刷向量库）；③ **可追溯**（引用出处）。

**【问题 2】**
① **推理侧**：**语义缓存**（相似问复用答案，需叠加用户‑时效 key 防污染）、**异步队列**削峰、**推理网关限流**护 GPU、**HPA 按 GPU 利用率扩缩**、**INT8/INT4 量化 + PagedAttention** 加速、**模型路由**（简单走小模型）、**Token 监控**降本；
② **检索侧**：**向量 + BM25 混合检索 + 重排**提召回率、ANN 索引保毫秒级延迟、向量库按**召回率/延迟/容量**三指标选型（Milvus 分布式）。

**【问题 3】**
- **召回无关** → 根因：纯向量召回受一词多义干扰；对策：**混合检索 + 领域词典扩展**，重排模型调优；
- **少量编造** → 根因：模型自由发挥；对策：**Prompt 硬约束"无依据不许作答" + 引用必填校验**，幻觉率压到阈值下；
- **知识滞后** → 增量索引管道，新文件发布即触发切片+向量化，旧片段失效。

## 📝 模拟题二：城市安防多智能体（Agent + 云边端）

**【背景】**
某市安防系统原靠人工研判告警、人工派单，响应慢。拟改造为**多智能体协同**：监测 Agent 收告警、分析 Agent 研判等级、处置 Agent 调工单/设备接口，边缘摄像头做实时识别、云端训练模型。

**【问题 1】（9 分）** 设计多智能体协同架构，说明角色划分、编排与通信。

**【问题 2】（8 分）** 给出 Agent 的权限管控与降级兜底设计，防止越权误派单与环路失控。

**【问题 3】（8 分）** 说明云边端各层职责与"边采云训"闭环。

---

### ✅ 参考答案

**【问题 1】**
采用**多智能体协同架构**：**编排器**统一分配与汇总；**监测 Agent**（收告警取上下文）、**分析 Agent**（调知识库研判等级）、**处置 Agent**（生成建议、调工单/设备接口）。通信：**MCP** 接工具、**A2A** Agent 间协同；**长期记忆外置向量库**。分层按《实施意见》"**感知—记忆—决策—交互—执行**"五能力要素。

**【问题 2】**
治理四件套：① **编排**（角色边界清晰）；② **工具接入**（注册发现 + **Schema 强校验**防参数错误）；③ **权限管控**（**最小权限 + 危险操作人工确认/白名单**）；④ **降级兜底**（**最大步数上限 + 循环检测 + 超时熔断 + 异常转人工**）。

**【问题 3】**
- **感知层（端）**：摄像头采集；
- **边缘层（边）**：边缘网关**就近实时识别、断网自治**（低时延/省带宽/隐私/离线可用四价值）；
- **AI 决策层（云）**：模型训练、全局分析，**OTA 下发**轻量化模型到边缘；
- **应用层**：告警推送、工单、大屏；
- 闭环：**边采 → 云训 → 模型下发边执行**。

## 📝 模拟题三：政务大模型训练与推理平台（训练vs推理 + AI安全 + 数据）

**【背景】**
某政务平台需同时支撑**模型训练（周期性、万卡）**与**在线问答推理（2000 QPS、P99≤500ms）**，涉及市民身份信息，需等保三级与自主可控，并防提示词注入与泄密；训练数据来自多部门、需可溯源。

**【问题 1】（9 分）** 设计训练链路与推理链路，说明两者架构差异。

**【问题 2】（8 分）** 训练集群测试发现拥塞、故障恢复 12 分钟（要求 ≤5 分钟），给优化。

**【问题 3】（8 分）** 给出 AI 安全与合规设计（含四类风险、三层护栏、等保/信创、数据治理）。

---

### ✅ 参考答案

**【问题 1】**
分两条链路：① **训练链路（离线批处理）**——万卡 GPU + **RDMA/RoCE** 互联、**ECMP+包喷洒**、**APSCC** 拥塞控制、**Checkpoint 断点续训**；② **推理链路（在线实时）**——缓存/异步/限流/弹性 + 量化/PagedAttention，HPA 按队列扩缩。差异：训练要**吞吐与带宽**，推理要**延迟与成本**。

**【问题 2】**
① **ECMP 不均** → **包喷洒**打散多路径；② **拥塞收敛不足** → **APSCC 自适应**调阈值 + PFC/ECN 无损；③ **恢复 12 分钟** → **健康探测+Checkpoint 周期保存+故障节点自动隔离重调度+断点续训**，压到 **≤5 分钟** + 故障演练。

**【问题 3】**
**三层 Guardrails**：输入（注入检测/PII 脱敏）、模型（对齐/幻觉检测）、输出（引用验证/人工兜底）；**四类风险**：注入→输入净化+指令数据隔离；误操作→Schema 校验+确认回滚；投毒→签名校验+白名单；权限失控→最小权限+人工确认；**合规**：算法备案、内容标识、数据脱敏不出域、**等保三级**、**信创适配（国产库/OS + 国密 SM2/SM3/SM4）**；**数据治理**：训练数据清洗脱敏、数据集版本管理、数据血缘溯源、训练/推理统一特征平台防偏斜。

# 15. 新手最易丢分的点（考前扫一遍）

> 按"丢分频率"从高到低排列，考前 30 分钟扫这一节性价比最高。

| # | 易错点 | 正确表述 |
|---|--------|---------|
| 1 | RAG 答成微调 | **RAG = 外挂知识库、不改模型**（更新频繁/要引用→RAG）；微调=改参数 |
| 2 | RAG 漏"中间夹向量库" | 结构=**检索+生成两段式，中间夹向量库做存储** |
| 3 | 召回不准只换模型 | 对策=**混合检索（向量+BM25）+领域词典+重排** |
| 4 | 幻觉对策漏引用校验 | **Prompt 约束无依据不许答 + 引用必填校验** |
| 5 | 向量库说成"存向量" | 关键是"**按相似度查询**"（余弦/内积 + ANN 索引） |
| 6 | 向量库选型不写三指标 | **召回率 / 延迟 / 容量** |
| 7 | ANN 说成全量扫描 | ANN=**近似最近邻、索引加速**（HNSW/IVF） |
| 8 | 推理服务不套通用手法 | 它就是**高延迟普通服务**：缓存/异步/限流/弹性直接套 |
| 9 | 推理只写"加 GPU" | 要含 **HPA 弹性 + 队列 + 限流 + 语义缓存 + 模型路由 + 成本治理** |
| 10 | 量化说成提精度 | 量化=**降精度换速度/体积**（INT8/INT4） |
| 11 | PagedAttention 说不清 | **KV Cache 分页复用、显存利用率提升、提吞吐** |
| 12 | Agent 写成单个模型 | 它是**编排层 + 工具调用**（规划/记忆/工具/反思） |
| 13 | Agent 治理只写编排 | 四件套：**编排 + 工具接入 + 权限管控 + 降级兜底** |
| 14 | Agent 漏权限/人工确认 | **最小权限 + 危险操作人工确认/白名单** |
| 15 | 环路失控无对策 | **最大步数 + 循环检测 + 超时熔断 + 转人工** |
| 16 | MCP / A2A 混 | **MCP = 接工具**；**A2A = Agent 间通信** |
| 17 | 云边端只答三层不会翻四层 | 端=感知、边=边缘、云=AI 决策、再加应用层 |
| 18 | 边缘价值只答一条 | **低时延、省带宽、隐私保护、离线可用** |
| 19 | 说"边缘替代云" | 是**边云协同**：边管快、云管大（训练/存储） |
| 20 | 组件归类错层 | 采/识/验在感知；网关/周界在边缘；分析/训练在决策；呈现/集成在应用 |
| 21 | 训练推理混为一谈 | **训练=离线批处理（吞吐/带宽/RDMA）**；**推理=在线实时（延迟/成本）** |
| 22 | 只用一套链路伺候两者 | 分**离线训练 + 在线推理**两条链路 |
| 23 | RDMA 说成普通加速 | **绕过 CPU 直接读内存**，万卡训练刚需 |
| 24 | 故障恢复不写 ≤5 分钟 | 训练集群对策：Checkpoint+自动重调度+演练，压到**≤5 分钟** |
| 25 | AI 安全只答防火墙 | **三层 Guardrails + 四类风险分治** |
| 26 | Guardrails 只写一层 | **输入/模型/输出** 三层全写 |
| 27 | 漏"插件投毒/供应链" | 对策=**签名校验 + 白名单 + 供应链审计** |
| 28 | 权限失控只写"加权限" | **最小权限 + 危险操作人工确认/白名单** |
| 29 | 漏合规要求 | **算法备案 + 生成内容标识 + 数据脱敏不出域 + 等保三级** |
| 30 | AI 题只答功能不答非功能 | **功能 + 性能 + 安全 + 可解释性/合规 + 成本** 五维同答 |
| 31 | 语义缓存只写好处 | 必答**污染风险 + 5 对策**（用户/时效 key、TTL、时效类禁用、阈值调高、命中校验） |
| 32 | 架构风格辨析错配 | RAG/预处理=**管道‑过滤器**；训练平台=**解释器**；多智能体=**事件驱动**；别混 |
| 33 | 政务题漏等保三级/信创/国密 | 政务 AI 默认**等保三级**；信创点**国产库/OS + SM2/SM3/SM4** |
| 34 | AI 题不答数据维度 | 下半年重点：写**数据治理/版本/血缘/特征一致性（防偏斜）**至少一条 |

# 16. 一页纸速查清单

> **考前最后一眼，只看这一屏。**

```
【总纲：AI 组件 → 通用架构手法】
RAG          = 检索+生成两段式，中间夹向量库
向量库        = 按相似度查询的存储（召回率/延迟/容量）
推理服务      = 高延迟高算力普通服务 → 缓存/异步/限流/弹性
Agent        = 会调工具的编排层 → 编排+工具+权限+兜底
云边端        = 端(感知)—边(边缘)—云(决策)—应用 四层 / 端—边—云 三层
训练 vs 推理  = 离线批处理(吞吐/带宽/RDMA) vs 在线实时(延迟/成本)
AI 安全       = 三层护栏 + 四类风险分治 + 合规闭环

【AI × 架构风格辨析】RAG/预处理=管道‑过滤器；训练平台=解释器；知识融合=仓库/黑板；多智能体=事件驱动；批量推理=批处理
【管道‑过滤器 vs 批处理】流式+过滤器可并行替换  vs  攒批离线高吞吐（常共存于同一系统不同链路）

【RAG 五步】切片 → 向量化(Embedding) → 向量检索(ANN) → 重排(混合) → 生成+引用
【RAG vs 微调】外挂知识库不改模型(时效/引用) vs 改参数(风格固定) → 更新频繁/要引用选 RAG
【幻觉对策】Prompt 约束无依据不许答 + 引用必填校验

【向量库】相似度(余弦/内积) + ANN 近似最近邻(HNSW/IVF) + 三指标(召回/延迟/容量)
          选型：Milvus(分布式) / Faiss(轻量) / ES-kNN(混合)

【推理优化】语义缓存(防污染!) · 异步队列 · 推理网关限流 · HPA(GPU利用率/队列) · 量化INT8/INT4
          · PagedAttention(KV Cache分页) · 模型路由 · Token监控 · Spot实例
【语义缓存坑】相似≠答案同 → 用户/时效key + TTL + 时效类禁用 + 阈值调高 + 命中校验
【加速三件套】PagedAttention · 量化 · 蒸馏(老师教学生)

【Agent 三要素】规划(ReAct/CoT) · 记忆(短上下文/长向量库) · 工具调用(Function Calling)
【多智能体】编排器 + 监测/分析/处置 Agent；MCP接工具 · A2A间通信
【治理四件套】编排 + 工具接入(Schema校验) + 权限管控(最小权限/人工确认) + 降级兜底(步数/循环/熔断/转人工)
【五能力要素】感知—记忆—决策—交互—执行（政策《实施意见》分层法）

【云边端四价值】低时延 · 省带宽 · 隐私保护 · 离线可用（边管快，云管大，边云协同）
【闭环】边采 → 云训 → 模型OTA下发边执行

【训练vs推理】训练=离线批处理(吞吐/RDMA/ECMP+包喷洒/APSCC/Checkpoint断点续训/恢复≤5min)
            推理=在线实时(延迟/成本/缓存异步限流弹性)

【AI 数据维度】数据治理(清洗/脱敏) · 数据集版本 · 数据血缘 · 特征一致性(防训练-推理偏斜, Feature Store)
【知识图谱】本质=多源数据融合，按版本+血缘管理

【AI 安全】三层 Guardrails：输入(注入检测/PII脱敏) · 模型(对齐/幻觉检测) · 输出(引用验证/人工兜底)
【四类风险】注入(输入净化) · 误操作(Schema校验+回滚) · 投毒(签名+白名单+审计) · 权限失控(最小权限+人工确认)
【合规闭环】算法备案 · 生成内容标识(水印) · 数据脱敏不出域 · 等保三级 · 信创(国产库/OS + 国密SM2/SM3/SM4)

【AI + 传统架构】推理=高延迟服务 → 微服务(注册发现/网关/熔断/链路追踪) · 语义缓存=Redis上层 · MQ异步削峰回调 · 向量库+关系库并存(元数据用关系库/语义用向量库)

【诊断题框架】根因 → 对策 → 验证指标（性能/成本/安全/Agent/召回 四类见 §12）

【AI 缺点清单(挑5)】①幻觉 ②成本高 ③延迟大 ④黑盒 ⑤漂移 ⑥数据依赖 ⑦新攻击面 ⑧难量化 ⑨边缘算力 ⑩供应商锁定
            政务①④⑥⑦⑩ · 边缘③⑥⑨①② · 成本②⑧①③⑤

【AI 题必答五维】功能 + 性能 + 安全 + 可解释性/合规 + 成本
【备考策略】AI 为主 + 数据/分布式为辅（选答 2~3 道，别只押 AI）
```
