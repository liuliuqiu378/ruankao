# 01 · 考题分析 — 五大题型逐一拆解

> **目标**：搞清楚每类题"考什么、怎么问、答什么"，并理解命题的真实逻辑。
>
> ⚠️ **重要认知**：案例分析**并非官方固定按五类出题**，而是每次从若干命题域中抽 5 道题（**第 1 题必答 + 后 4 题选 2，共 3 题，75 分满分，45 分及格**）。本文件的"五大题型"**作为备考知识模块是正确的**，但不等于"真题的固定题型"。真正稳定的规律是**"题号—考点"的绑定关系**（见第二节）。

---

## 一、考试结构与命题逻辑（先读这段）

### 1. 考试结构

| 项目 | 说明 |
|------|------|
| 题目数量 | 一般 5 道大题 |
| 作答数量 | **第 1 题必答 + 后 4 题选 2** |
| 总分 | 75 分，每题约 25 分 |
| 及格线 | 45 分 |
| 考试时间 | 案例分析单场 90 分钟；**与论文连考，合计 240 分钟**（13:30–17:20，中间休息 20 分钟） |
| 考试形式 | 机考，打字作答，可能含填表、拖拽、简答 |

### 2. 实际命题的"题号—考点"绑定关系（近年真题规律）

| 题号 | 性质 | 实际考查方向 | 稳定性 |
|------|------|--------------|--------|
| **试题一（必答）** | 固定 | 架构基础与质量属性——架构风格辨析、质量属性场景分析、架构评估（ATAM/SAAM） | ✅ 高度稳定 |
| **试题二（选答）** | 不稳定 | 历史考 UML/DFD 建模，近年转向**陌生架构图识别填空** | ⚠️ 不稳定 |
| **试题三（选答）** | 高度稳定 | **Redis 专项**——缓存击穿/穿透/雪崩、主从复制、分布式锁 | ✅≈Redis 专项 |
| **试题四（选答）** | 视背景 | **嵌入式 + AI**——端侧 AI/云侧 AI、实时操作系统 | ⚠️ 视个人储备 |
| **试题五（选答）** | 不稳定 | Web / 陌生架构——常出现陌生架构图填空 | ⚠️ 不稳定 |

**关键发现**
- 试题三 ≈ Redis 专项，而非泛泛的"数据库与数据设计"。近年 Redis 考查深度已达**命令级**，远超传统数据库设计。
- 试题四 ≈ 嵌入式 + AI，而非"嵌入式与前沿技术"的宽泛覆盖。
- 试题二、试题五极其不稳定，用固定学科分类框定它们反而会误导备考。
- **超纲题占比越来越高**：2024 年 11 月改版后"只有试题一还在教材范围内"。

### 3. 与官方考纲的对照（避免盲区）

官方考纲模块是独立的架构类型，本备考体系应**补全被降级的模块**，避免复习盲区：

| 官方考纲模块 | 在本体系的位置 | 备注 |
|--------------|----------------|------|
| 系统计划 | ❌ 原分类未覆盖 | 🔴 **重点补充，非边缘考点**（项目立项、可行性研究、技术方案论证） |
| 信息系统架构 / 层次式架构 | 题型 1 | ✅ |
| 面向服务的架构（SOA） | 题型 4 | ✅ |
| 嵌入式系统架构 | 题型 5 | ✅ 2024 下半年真题作为**独立案例**出现，是值得重视的选答方向 |
| 通信系统架构 | ❌ 原分类未覆盖 | 🔴 **重点补充，非边缘考点**（网络拓扑、协议、通信中间件） |
| **云原生架构** | 原放"前沿技术" | ✅ 已提为独立模块（题型 4 主线之一）；2025 大纲明确纳入「云原生架构设计」 |
| **区块链技术应用** | 原未明确 | ✅ 2025 大纲新增「区块链技术应用」，应明确纳入专项模块 |
| **安全架构** | 原归"架构基础" | ✅ 已提为独立模块（题型 5 主线之一） |
| **大数据架构（Lambda/Kappa）** | 原放"前沿技术" | 🔴 已提为**高频独立模块**（题型 5 主线之一）；Lambda/Kappa 在 2024 年 11 月真题作为大题出现，不应低估 |

> ✅ **结论**：原五分法在**学科知识维度**上大体成立，可作为备考知识模块；但不能等同于固定题型。下面给出**修正后的五个备考知识模块**（边界与命名更贴近真题）。

## 二、修正后的五大备考知识模块

> **关键改动**：①题型 1 扩大为"架构设计与评估"；②题型 2 由"软件工程综合"聚焦为"系统建模与设计模式"（UML 与设计模式才是真高频）；③题型 3 保留并强化 Redis/缓存；④题型 4 合并云原生；⑤题型 5 明确为"专项架构与新技术"，把安全/大数据/云原生独立化。

| 题型 | 是否常考 | 性质 | 核心考点 |
|------|----------|------|----------|
| 1. 架构设计与评估 | **必做高频** | 必答 | 架构风格、质量属性、架构战术、效用树、ATAM/SAAM |
| 2. 系统建模与设计模式 | 选做（权重下降） | 选答 | UML、类图、用例图、顺序图、设计模式（新大纲已弱化设计模式考察） |
| 3. 数据架构与数据库设计 | 选做高频 | 选答（≈Redis 专项） | ER 图、范式、NoSQL、缓存、分布式事务 |
| 4. 分布式、云原生与集成架构 | 选做高频 | 选答 | 微服务、ESB、API 网关、中间件、K8s、Service Mesh、云原生架构设计 |
| 5. 专项架构与新技术 | 选做高频（重点补充） | 选答 | 嵌入式、IoT、边缘计算、AI（2026 新增）、大数据（Lambda/Kappa）、安全可靠性、系统计划、通信系统、区块链 |

## 三、题型逐一拆解

### 题型 1 · 架构设计与评估（必做高频）

> 由原"架构基础与风格"扩写而来。第 1 题不一定永远只叫"架构基础"，更常见的是：架构风格选择与比较、质量属性识别、架构战术、效用树、ATAM/SAAM、敏感点/权衡点/风险点。

**核心考点**
- 架构风格：分层、微服务、SOA、事件驱动、管道-过滤器、仓库（黑板）、RESTful、Serverless 等
- 质量属性（六大）：性能、可用性、安全性、可修改性、可测试性、易用性
- 架构战术：针对每个质量属性的常见战术（如可用性→冗余/心跳/故障转移）
- 架构评估：ATAM / SAAM 方法、效用树、风险点 / 敏感点 / 权衡点

**常见场景与提问方式**
- 给出系统需求，要求**选择合适的架构风格并说明理由**
- 分析系统的质量属性（如"支持 2 万并发用户"对应什么属性）
- 给出提升某质量属性的**架构战术**
- 补全效用树中的质量属性场景
- 指出系统的**风险点、敏感点、权衡点**
- 用 ATAM 方法对架构进行评估（步骤、产出）

**备考重点**
- 五大经典 + 新架构风格的特点 / 适用场景 / 优缺点对比表
- 六大质量属性的定义、量化方式、保障策略
- 架构战术对应表（质量属性 → 战术）
- ATAM 评估步骤、效用树构建方法
- 敏感点 / 权衡点 / 风险点的识别与论证

> 📘 本题型已扩展为完整专章 👉 [06-架构基础与风格.md](./06-架构基础与风格.md)（含 2 个实战实例与答题框架）

### 题型 2 · 系统建模与设计模式（选做，权重下降）

> 由原"软件工程综合"聚焦而来。案例题里更常见的是 **UML 建模 + 设计模式**，而非泛泛地考过程模型、需求工程、测试管理。
>
> ⚠️ **新大纲调整**：传统 UML 建模权重下降，设计模式考察已被弱化。备考时**降低该模块优先级**，不必在 23 种设计模式上投入过多，把时间让给架构评估、云原生、大数据等高频模块。

**核心考点**
- UML 建模：用例图、类图、顺序图、状态图、活动图（高频：类图、用例图、顺序图；总体权重下降）
- 类图关系：泛化、实现、关联、聚合、组合、依赖
- 设计模式：创建型、结构型、行为型 23 种（高频：工厂、策略、观察者、适配器、代理、装饰器、状态）——新大纲已弱化，了解常见模式即可

**常见场景与提问方式**
- 补全类图中的类名、方法或关系
- 判断类之间的关系（聚合 vs 组合、依赖 vs 关联）
- 选择并说明适用设计模式（如"多种导出格式→策略模式"）
- 说明某设计模式的意图、优点

**易混淆模式速记**

| 易混模式 | 区别重点 |
|----------|----------|
| 工厂方法 vs 抽象工厂 | 一个产品等级结构 vs 多个产品族 |
| 策略 vs 状态 | 外部选择算法 vs 内部状态改变行为 |
| 适配器 vs 桥接 | 事后适配已有接口 vs 事前分离抽象与实现 |
| 装饰器 vs 代理 | 增强功能 vs 控制访问 |
| 观察者 vs 中介者 | 一对多广播 vs 多对多集中协调 |

### 题型 3 · 数据架构与数据库设计（选做高频，本质=数据架构与持久化）

> 由原"数据库与数据设计"保留并强化。**近年试题三≈Redis 专项**在部分场次确实成立、考点固化、性价比高，但存在**幸存者偏差风险**，不能"唯 Redis 论"。

> ⚠️ **考点纠偏**：试题三的本质是**"数据架构与持久化"**，远不止 Redis。除缓存/NoSQL 外，**传统关系型建模（E-R 图转关系模式、范式判断、反规范化）、数据仓库/数据湖设计、分布式事务（Seata 等）** 依然占据半壁江山。
> 💡 **备考警示**：若某次试题三考"大型电商数据仓库的 Lambda 架构与维度建模"，只复习 Redis 的考生会直接懵圈。**E-R 图与数仓基础绝不能被 Redis 完全替代**，二者必须并重。

**核心考点**
- 关系数据库设计：规范化、反规范化、E-R 图、主外键、范式（1NF~BCNF）
- NoSQL 与缓存：**Redis 命令级**（缓存、键值设计、主从复制、分布式锁）
- 缓存三兄弟：穿透、击穿、雪崩、布隆过滤器
- 分布式数据：分库分表、读写分离、缓存一致性、分布式事务（2PC/TCC/最终一致性/Seata）、CAP/BASE
- **数据仓库 / 数据湖**：维度建模（星型/雪花模型）、事实表/维表、Lambda/Kappa 批流一体（与题型 5 的大数据架构呼应）
- **数据要素相关**：数据治理、数据血缘、隐私计算（联邦学习）在架构设计中的比重正在悄悄增加（见题型 5 盲区补充）

**常见场景与提问方式**
- 补全 E-R 图、判断关系模式是否满足 3NF、**E-R 图转关系模式**
- 设计合适的缓存策略（如"**如何解决缓存雪崩问题？**"——随机过期/多级缓存/熔断）
- **Redis 专项**：主从复制、哨兵、分布式锁实现（SET NX + 过期）、缓存与数据库一致性
- 设计分布式事务 / 分布式锁方案
- **数仓/维度建模**：设计星型模型、区分事实表与维表、批流架构选型（Lambda vs Kappa）

**高频记忆点**
- 缓存三兄弟：**穿透**（布隆过滤器 / 空值缓存）、**击穿**（互斥锁 / 逻辑过期）、**雪崩**（随机过期时间 / 多级缓存 / 熔断）
- 分布式事务方案对比与选型；Redis 分布式锁：先占锁（SET key value NX PX）、防误删、续期
- 维度建模三范式之外：**星型模型**（单级维）vs **雪花模型**（规范化维），事实表分事务/周期快照/累积快照

> 📘 本题型已扩展为完整专章 👉 [08-数据库与数据设计.md](./08-数据库与数据设计.md)（含真题改编案例与答题套路）

### 题型 4 · 分布式、云原生与集成架构（选做高频）

> 由原"系统集成与架构"合并云原生而来。把微服务、SOA/ESB、中间件、Web 架构、云原生合并为一个大类，更符合近年趋势。

**核心考点**
- 微服务架构：服务拆分、注册发现、API 网关、配置中心、熔断限流、链路追踪、服务治理
- **DDD 驱动拆分**：限界上下文、聚合根、领域事件（微服务边界划分的"标准答案"，2025 真题已出现）
- **消息队列架构问题**：重复消费（消费幂等）、消息丢失（确认+持久化）、顺序消息（同 key 同分区）—— Kafka/RabbitMQ 高频
- **可观测性三支柱**：日志 / 指标 / 链路追踪（微服务治理高频小问）
- **12-Factor 云原生十二要素**：配置外部化、无状态、日志事件流（云原生改造踩分点）
- SOA 与 ESB：Web Service、SOAP/REST、服务编排/编制、ESB 功能（协议转换/路由/格式转换）
- **云原生架构（独立模块）**：Docker、Kubernetes、Service Mesh（Sidecar）、Serverless、DevOps/CI-CD
- Web 架构：负载均衡、CDN、反向代理、动静分离、无状态设计、Session 共享、高可用
- **性能测试**：并发用户数、吞吐量（TPS/QPS）、响应时间（RT）、错误率，常与质量属性"性能"绑定出题

**常见场景与提问方式**
- 为传统单体系统设计**微服务改造方案**（答：按 DDD 限界上下文拆分，聚合根为一致性边界）
- 分析微服务架构下的服务治理问题；解释 ESB 优缺点
- **消息队列可靠性题**：如何防止消息丢失 / 重复消费 / 乱序（答 6.9 三支柱 + 幂等）
- **可观测性题**：微服务如何保障稳定运行（答：日志+指标+链路追踪三支柱）
- **云原生改造**：容器化、无状态化、配置外部化（12-Factor）、可观测性、CI/CD
- 设计高并发 Web 系统（网关 + 负载均衡 + 缓存 + 限流）
- **性能测试题**：给出并发/吞吐/响应时间指标，分析是否满足性能质量属性（详见题型 1 质量属性）

### 题型 5 · 专项架构与新技术（选做不稳定）

> 由原"嵌入式与前沿技术"改名而来。覆盖不稳定方向，并把**安全架构、大数据架构（Lambda/Kappa）、系统计划、通信系统架构**作为官方独立模块纳入，避免盲区。其中部分方向（大数据、嵌入式、系统计划、通信系统）**并非边缘考点，应重点补充**，而非仅作补充。

**可能涉及的方向（官方独立模块 + 前沿）**

| 方向 | 常见考点 | 重要性 |
|------|----------|--------|
| 嵌入式系统 | 实时性、可靠性、资源受限、任务调度、实时操作系统 | 🔴 2024 下半年真题作为**独立案例**出现，值得重视的选答方向 |
| IoT / 边缘计算 | 设备接入、MQTT/CoAP、端边云架构、低时延 | ⚠️ 视背景 |
| **大数据架构（高频独立模块）** | **Lambda / Kappa、批处理、流处理** | 🔴 2024 年 11 月真题作为大题出现，应提升为独立/高频模块，不应低估 |
| **AI 架构** | 模型训练/推理、RAG、Agent | 🔴 2026 新大纲重点（占比约 25%） |
| **安全架构（独立模块）** | 零信任、身份认证、**访问控制模型（RBAC/ABAC）**、数据加密、**数据脱敏**、审计、**等保 2.0 分级保护** | ✅ 建议补等保/RBAC/脱敏体系化考点 |
| **系统计划（原遗漏模块）** | 项目立项、可行性研究、技术方案论证 | 🔴 重点补充，非边缘考点 |
| **通信系统架构（原遗漏模块）** | 网络拓扑、协议、通信中间件 | 🔴 重点补充，非边缘考点 |
| **区块链技术应用** | 共识机制、智能合约、分布式账本 | ✅ 2025 大纲新增，应明确纳入 |
| 可靠性设计 | 冗余、容错、N 版本程序设计、恢复块、可靠度计算（串联/并联） | ✅ |
| 架构演化 | 遗留系统改造、**绞杀者模式**、**防腐层（ACL）**、**抽象分支（Branch by Abstraction）**、并行运行 | ✅ 除绞杀者外，防腐层/抽象分支近年真题更易踩分 |
| **信创与国产化替代** | 自主可控、国产化适配（国产数据库达梦/人大金仓、国产 OS、国密算法 SM2/3/4、信创软硬件栈） | 🔴 2024–2025 极热隐藏考点，常在架构选型/安全架构中考查 |
| **数据要素与数据资产** | 数据治理、数据血缘、隐私计算（联邦学习）、数据资产化（"数据二十条"导向） | 🔴 近年比重悄悄增加，易出超纲/论述题 |

> 🔴 **盲区补充（近年极热隐藏考点）**：结合 2024–2025 国家宏观政策与软考命题导向，以下两点极易出**超纲题/论述题**，务必纳入视野：
> - **信创与国产化替代**：在架构选型、安全架构中常考"自主可控""国产化适配"——如选用国产数据库（达梦、人大金仓）、国产 OS、国密算法 SM2/SM3/SM4 的应用场景与适配要点。
> - **数据要素与数据资产**：随"数据二十条"发布，数据治理、数据血缘、隐私计算（联邦学习）在架构设计中的比重正在增加，可能以论述题形式出现。

**常见场景与提问方式**
- 设计 IoT 端边云架构 / AI·RAG 架构 / Lambda/Kappa 大数据处理架构
- 分析系统可靠性并做可靠度计算（先判断串联/并联/混合）
- 设计安全架构、区块链应用方案或系统迁移/演化方案
- 系统计划类：项目立项论证、可行性研究分析
- **信创类**：在架构选型中论证"自主可控"、给出国产数据库/国产 OS/国密算法的适配方案
- **数据要素类**：设计数据治理体系、说明数据血缘追踪、隐私计算（联邦学习）在跨域数据共享中的架构角色

> ⚠️ **大纲动态**：
> - **2025 年大纲**：新增「云原生架构设计、区块链技术应用」等，应明确纳入复习范围（云原生并入题型 4，区块链纳入本题型）。
> - **2026 年新大纲重点**：AI 内容占比约 25%，新增「AI 系统架构设计」「大模型部署策略」「智能系统性能优化」三个专题；质量属性（性能 / 可用性）常与 AI 需求（推理延迟、模型准确率、可解释性）结合出题。

## 四、选答策略建议（按备考策略分类，而非按学科）

> **核心策略**：必答题稳拿 + Redis 必选 + 根据个人背景选 1 题，同时注重培养分析陌生架构的能力（应对超纲题）。

### 押题优先级

| 优先级 | 模块 | 建议 |
|--------|------|------|
| **第一优先级（必须拿下）** | 1. 架构设计与评估 | 第 1 题核心，目标至少 15~18 分 |
| **第二优先级（选做主力）** | 3. 数据架构（Redis） + 4. 分布式/云原生 | 考点固化、性价比最高、符合趋势 |
| **第三优先级（重点补充，非边缘）** | 5. 专项架构（大数据/Lambda-Kappa、嵌入式、系统计划、通信系统、AI、区块链） | 近年真题高频出现，须重点补充，工作背景匹配时可作为选做依靠 |
| **第四优先级（权重下降，备选）** | 2. 系统建模与设计模式 | 新大纲已弱化设计模式、传统 UML 权重下降，不熟不建议硬啃，降低复习优先级 |

### 推荐选题组合
- **组合一（通用）**：架构设计与评估 + 数据架构 + 分布式/云原生
- **组合二（开发背景）**：架构设计与评估 + 系统建模与设计模式 + 数据架构
- **组合三（云/AI/IoT 背景）**：架构设计与评估 + 分布式/云原生 + 专项架构

### 考场上 3 分钟选题
1. 先浏览全部选做题，判断：是否熟悉核心概念、能否写出 3 个小问、是否需大量计算、是否过于冷门。
2. 不选完全陌生、只靠猜的题；优先选能写满、能分点、能结合案例的题。
3. 选好后集中精力攻克，遇到困难先跳过，最后回头补。

### ⏱️ 90 分钟机考时间管理（生死线）

> 90 分钟要**阅读 3 道大题的超长背景材料**，并完成打字、拖拽、填表，**极度残酷**。平均每题只有约 30 分钟（≈5 分钟阅读 + 25 分钟作答），务必提前演练。

**应试技巧**
- **先扫视问题，再带着问题读材料**：开题先读小问，标记要提取的关键信息，回材料时只找答案，避免通读浪费时间。
- **机考工具提前演练**：考试前务必熟悉机考系统自带的**公式编辑器、表格快捷键、画图工具**。很多考生做不完题，不是不会，而是打字慢或不会用自带表格/画图工具。
- **分配纪律**：单题超过 30 分钟立即止损，先跳到下一题；最后留 5–10 分钟回填拖拽/填表类小题，避免整题 0 分。
- **打字速度**：主观题全靠打字，建议平时用键盘练习答题，把"想得出来但打不出来"的风险降到最低。
