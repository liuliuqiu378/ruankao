## 🌳 系统架构师案例核心知识体系（与五大备考模块对齐）

```
系统架构师案例核心知识体系
├── 1. 架构设计与评估（必做高频）
│   ├── 架构风格（分层/微服务/SOA/事件驱动/管道-过滤器/仓库/RESTful/Serverless）
│   ├── 质量属性（性能/可用性/安全性/可修改性/可测试性/易用性）
│   ├── 架构战术（质量属性 → 战术对应表）
│   ├── 效用树与 ATAM / SAAM
│   └── 敏感点 / 权衡点 / 风险点
├── 2. 系统建模与设计模式（选做高频）
│   ├── UML（用例图/类图/顺序图/状态图/活动图）
│   ├── 类图关系（泛化/实现/关联/聚合/组合/依赖）
│   └── 设计模式（创建型/结构型/行为型 23 种）
├── 3. 数据架构与数据库设计（选做高频 ≈ Redis 专项）
│   ├── 关系数据库（规范化/反规范化/E-R图/范式 1NF~BCNF）
│   ├── NoSQL 与 Redis（缓存/主从复制/分布式锁命令级）
│   ├── 缓存策略（穿透/击穿/雪崩）
│   └── 分布式数据（分库分表/一致性/分布式事务/CAP-BASE）
├── 4. 分布式、云原生与集成架构（选做高频）
│   ├── 微服务（拆分/注册发现/网关/配置中心/熔断限流）
│   ├── SOA 与 ESB（Web Service/服务编排/总线功能）
│   ├── 云原生（独立模块：Docker/K8s/Service Mesh/Serverless/DevOps）
│   └── Web 架构（负载均衡/CDN/无状态/Session 共享/高可用）
└── 5. 专项架构与新技术（选做不稳定，含官方独立模块）
    ├── 嵌入式系统（实时性/资源约束/RTOS）
    ├── IoT 与边缘计算（MQTT/端边云）
    ├── 大数据架构（独立模块：Lambda/Kappa）
    ├── AI 架构（模型训练推理/RAG/Agent）
    ├── 安全架构（独立模块：零信任/认证/加密/审计）
    ├── 系统计划（独立模块：立项/可行性/方案论证）★
    ├── 通信系统架构（独立模块：拓扑/协议/通信中间件）★
    └── 可靠性与架构演化（冗余/容错/N版本/恢复块/绞杀者）
```
> ★ 标记项为原分类遗漏或降级的官方模块，需重点补盲。

## 一、架构风格对比表

> 更完整版与实例见 👉 [06-架构基础与风格.md](./06-架构基础与风格.md)

| 架构风格 | 核心思想 | 优点 | 缺点 / 挑战 | 适用场景 |
|----------|----------|------|--------------|----------|
| 分层架构 | 上层仅调用相邻下层，关注点分离 | 结构清晰、易理解、可并行开发、复用好 | 多层调用性能瓶颈；易过度设计；不适高并发低延迟 | 企业应用、传统信息系统 |
| 微服务 | 按业务能力拆为自治服务，轻量 API 通信 | 独立部署伸缩、技术栈灵活、故障隔离强 | 分布式复杂、运维成本高、一致性挑战 | 大型复杂互联网应用、快速迭代 |
| 事件驱动 | 组件经事件（消息）异步通信 | 高响应性、松耦合、高吞吐、易扩展 | 测试难、一致性保障复杂、消息顺序/可靠性需额外处理 | 高并发异步处理、实时数据流 |
| 管道-过滤器 | 过滤器封装独立功能，数据经管道流动 | 模块复用强、可维护可扩展、具并发性 | 不适交互强应用；关系数据流需协调；额外 IO 开销 | 编译器、图像处理、ETL |
| 仓库/黑板 | 多知识源协同处理共享黑板数据 | 解决复杂非结构化问题、灵活可扩展 | 控制逻辑复杂、难测试、并发访问控制难 | AI（语音/图像）、决策支持 |

## 二、质量属性场景树（效用树）

```
质量属性（效用树）
├── 性能
│   └── 响应时间 → 99% 请求 500ms 内完成
│   └── 吞吐量 → 支持 2 万并发用户
├── 可用性
│   └── 容错 → 单节点故障不影响服务（99.99%）
├── 安全性
│   └── 认证授权 → 防越权访问
├── 可修改性
│   └── 模块化 → 变更影响范围可控
└── 互操作性
    └── 接口标准 → 跨系统数据交换
```

> 练习：看到案例描述的具体需求，能立刻对应到质量属性，并给出量化场景。

## 二之一、ATAM 三要素速记

| 要素 | 定义 | 判别特征 | 例子 |
|------|------|----------|------|
| **敏感点** | 影响**一个**质量属性的要素 | 改它，单属性明显变 | 缓存最大内存 → 性能 |
| **权衡点** | 影响**多个**且冲突的质量属性 | 改它，利弊同现 | 冗余服务 → 可用性↑但成本/一致性↓ |
| **风险点** | 可能导致问题的潜在隐患 | "若…则出事" | 两服务耦合过高 → 影响独立扩展 |

> 完整质量属性策略与实例见 👉 [06-架构基础与风格.md](./06-架构基础与风格.md)

## 三、记忆建议

1. **按五大模块主线归类**，不零散记；云原生/安全/大数据/系统计划/通信系统等官方独立模块单列，避免盲区。
2. **对比表 + 口诀 + 思维导图**巧记精确内容（如 ATAM 步骤、六大质量属性、架构战术对应表、五种经典架构风格）。
3. **理论代入项目**：思考"这个理论在我的项目中怎么体现？换方案会怎样？"
4. **侧重"分析陌生架构"的能力**：近年超纲题多，练会"识别组件—判断关系—结合质量属性"的通用分析框架，比死记特定知识点更关键。
