# 08 · 专业英语专项 — 5 分，用 6 小时换 4 分的最划算买卖

> **一句话定位**：综合知识**最后 5 题**（通常为第 71~75 题），每题 1 分，共 **5 分**。
>
> **为什么值得专门准备**：
> - 5 分 = 及格线 45 分的 **11%**。很多人在 43、44 分挂掉，差的往往就是这 5 分里的 2~3 分。
> - 它**不考语法、不考时态**，只考"技术词汇 + 上下文逻辑"。**这两样都能短期突击**。
> - 投入产出比：约 **6~8 小时 → 稳定拿 3~4 分**，是全科最高的。
>
> **为什么很多人放弃**：觉得"英语不好，5 分算了"。**这是最可惜的丢分**——因为这套题的瓶颈不是英语水平，而是**技术术语量**。你认识 `cache`、`latency`、`throughput` 就够了。

# 一、考情：先看清题长什么样

| 项目 | 说明 |
|------|------|
| 位置 | 综合知识**最后 5 题**（第 71~75 题），**先翻到最后确认，别漏** |
| 形式 | 一篇 **150~250 词**的英文技术短文，挖 **5 个空**，每空 4 选 1 |
| 分值 | 5 × 1 = **5 分** |
| 题材 | 云计算、微服务、AI/大模型、**软件工程与敏捷**、网络安全、数据库、分布式系统 |
| 考查本质 | **技术词汇量 + 上下文逻辑**，几乎不考语法 |
| 难度 | 句子结构不复杂，四级水平能读懂；难在**术语** |

**样题长相（先感受一下，不用做）**

> Cloud computing enables organizations to access computing resources **on demand**. One of the key characteristics of cloud computing is **(71)** — the ability to automatically increase or decrease resources according to workload. …
>
> (71) A. reliability　B. elasticity　C. durability　D. portability

> 🎯 这题的关键是：**读破折号后面的解释** "自动增减资源" = **弹性** = `elasticity`。
> **根本不需要你认识 B 选项**，只要读懂后半句的解释就能选对。这就是本篇要教的核心能力。

# 二、性价比分析

| 板块 | 分值 | 需投入时间 | 每小时得分 | 建议 |
|------|:----:|:----------:|:----------:|------|
| **专业英语** | 5 | **6~8 h** | **≈ 0.6 分/h** | 🟢 **必做**，优先级仅次于计算题 |
| 计算题 | 12~18 | 15~20 h | ≈ 0.8 分/h | 🟢 第一优先 |
| 知识产权/标准化 | 6~8 | 4~6 h | ≈ 1.3 分/h | 🟢 必做（背就有分） |

> 💡 **结论**：英语题是"**中等投入、稳定回报**"的典型。它不像新技术那样"背了也不一定考到"——**每年固定 5 题，就那几个主题，词汇表是收敛的**。

# 三、解题四步法（核心）

> 这套方法保证你**在词汇量不足时也能拿 3 分**，词汇量够了能拿 5 分。

### 第 1 步（30 秒）：读首句 + 标题，锁定主题

英文说明文**第一句几乎一定是主题句**。先读它，判断这篇文章在讲什么领域（云？微服务？安全？AI？）。

> 例：首句是 "Cloud computing enables organizations to access computing resources on demand."
> → 主题 = **云计算**，脑子里立刻调出相关词汇：`elasticity`、`provision`、`virtualization`、`scalability`、`pay-as-you-go`。

### 第 2 步（1 分钟）：通读全文，跳过空格，抓大意

**不要一看到空就选**。先完整读一遍（空当"括号"跳过），搞清楚文章在讲什么、态度是正面还是负面。

### 第 3 步（每空 30 秒）：看空的前后各一句，找线索

这是最关键的一步。正确答案**几乎总能在空的前后一句找到依据**。线索有六大类（见下一节）。

### 第 4 步（30 秒）：代入通读，检查逻辑是否顺

把 5 个选项代进去读一遍。**读起来别扭的，大概率错了**——英语语感在这里是真能用的。

# 四、六大上下文线索

> 这是本篇最值钱的部分。**考场上 80% 的空靠线索就能定，不需要认识所有选项。**

| # | 线索类型 | 标志词 | 解题动作 | 示例 |
|:-:|----------|--------|----------|------|
| **1** | **解释/重述** | 破折号 `—`、冒号 `:`、`that is`、`in other words`、`namely`、`which means`、`i.e.` | **答案就在后面** | "___ — the ability to automatically increase or decrease resources" → 后面是"自动增减资源" → **elasticity** |
| **2** | **转折** | `but`、`however`、`yet`、`although`、`whereas`、`nevertheless`、`in contrast`、`unlike` | 选**与前文相反**的词 | "Monoliths are simple to deploy. ___, microservices are much harder to operate." → **However** |
| **3** | **因果** | `because`、`since`、`therefore`、`thus`、`hence`、`consequently`、`as a result`、`due to`、`so ... that` | 顺着因果推 | "The service was overloaded; ___, response time increased." → **therefore/consequently** |
| **4** | **并列** | `and`、`or`、`as well as`、`both ... and`、`not only ... but also`、顿号、分号 | 选**同类/同义**词 | "authentication and ___" → **authorization**（并列同类） |
| **5** | **举例** | `for example`、`for instance`、`such as`、`e.g.` | 空是**概括**，后面是**具体**；或反之 | "techniques ___ caching and sharding" → **such as** |
| **6** | **指代** | `this`、`these`、`such`、`it`、`they`、`the former/latter` | **回上文找它指什么** | "This ___ allows..." → 回前句找那个机制 |

### 🎯 线索优先级
**破折号/冒号 > 转折 > 因果 > 并列 > 举例 > 指代**
> 看到破折号 `—`，**先把破折号后面的话读完**——那是命题人白送给你的定义。

# 五、词性判断法（不会也能排掉两个选项）

看空**前后紧邻的词**，判断该空需要什么词性，直接排除一半选项。

| 空前/空后的信号 | 空里需要 | 例子 |
|-----------------|---------|------|
| `a` / `an` / `the` + ___ | **名词（单数）** | "is a ___" → 名词 |
| `to` + ___ | **动词原形** | "to ___ resources" → 动词 |
| `of` / `in` / `for` + ___ | **名词 / 动名词(-ing)** | "the cost of ___" → 动名词 |
| `be` + ___ + `by` | **过去分词（被动）** | "data is ___ at rest" → encrypted |
| ___ + 名词 | **形容词** | "___ resources" → additional / elastic |
| 动词 + ___（修饰动词） | **副词** | "can be deployed ___" → independently |
| `and` 前后 | **与另一半词性一致** | "authentication and ___" → 名词 |
| 句首 + 逗号 | **副词（连接性状语）** | "___, microservices are harder" → However |

> 💡 **实测场景**：一个空，4 个选项里 2 个是动词、2 个是名词。空前是 `the`，空后是 `of` → 必填名词 → **直接排除 2 个动词，命中率从 25% 提到 50%**。

# 八、形近词 / 易混词辨析

> 这些词**长得很像但意思完全不同**，是命题人最爱放的干扰项。**必背**。

| 词对 | 辨析 | 一句话记住 |
|------|------|-----------|
| **sensitive**（敏感的） vs **sensible**（明智的） | sensitive = 易受伤害/需保密的；sensible = 合理的 | "敏感信息" sensitive information |
| **principal**（主要的/校长） vs **principle**（原则） | 结尾 -al 常是形容词/人；-le 是"原则" | prin**ciple** = 原则（都有 le） |
| **adapt**（适应/改编） vs **adopt**（采用/收养） | adapt **t**o（适应）；adopt = 采纳方案 | "采用新技术" **adopt** a technology |
| **affect**（动词，影响） vs **effect**（名词，效果） | affect = 动词；effect = 名词 | 🔴 R**e**member: **A**=Action, **E**=End result |
| **ensure**（确保） vs **assure**（使确信） vs **insure**（保险） | ensure = 保证；assure **人**；insure = 投保 | 保险 = insure |
| **complementary**（互补的） vs **complimentary**（赞美的/免费的） | 差一个字母 e / i | 互补 = compl**e**ment |
| **precede**（在…之前） vs **proceed**（继续） | pre- = 前；pro- = 向前 | — |
| **considerable**（相当大的） vs **considerate**（体贴的） | considerable = 量大；considerate = 体贴人 | — |
| **economic**（经济的） vs **economical**（节约的） | — | — |
| **explicit**（明确的） vs **implicit**（隐含的） | ex- = 外（说出来）；im- = 内（没说出来） | — |
| **discrete**（离散的） vs **discreet**（谨慎的） | **两个 e 挨在一起**(discr**ee**t) 的那个是"谨慎" | 数学/技术文里 99% 是 **discrete** |
| **eminent**（杰出的） vs **imminent**（即将发生的） | imminent = 迫在眉睫 | — |
| **statue / status / statute** | status = **状态/地位**（技术文里几乎只有它） | `status code`（状态码） |
| **later / latter / latency** | latter = 后者；**latency = 延迟** 🔴 | — |

# 九、高频固定搭配

> 英语题常考"空前后的介词/固定结构"，这些搭配背下来能直接定答案。

| 搭配 | 含义 | 例句片段 |
|------|------|---------|
| **based on** | 基于 | generate an answer **based on** documents |
| **capable of** | 能够 | is **capable of** handling |
| **responsible for** | 负责 | is **responsible for** routing |
| **in terms of** | 在…方面 | measured **in terms of** latency |
| **with respect to / regarding** | 关于 | policies **with respect to** data |
| **result in / lead to / contribute to** | 导致（后接结果） | This may **result in** data loss. |
| **result from / arise from** | 由…引起（后接原因） | Failures **result from** network issues. |
| **due to / owing to / because of** | 由于 | unavailable **due to** overload |
| **rely on / depend on** | 依赖 | services **rely on** the registry |
| **susceptible to / vulnerable to / prone to** | 易受…影响的 | **vulnerable to** attacks |
| **take advantage of / leverage** | 利用 | **leverage** existing infrastructure |
| **in addition to / moreover / furthermore** | 此外 | — |
| **despite / in spite of** | 尽管（表转折） | **Despite** these benefits, … |
| **play a key role in** | 在…中起关键作用 | — |
| **such as / for example / for instance** | 例如 | techniques **such as** caching |
| **rather than / instead of** | 而不是 | scale out **rather than** scale up |

## 📝 演练一 · Cloud Computing（云计算）

> Cloud computing enables organizations to access computing resources **(71)**. One of the key characteristics of cloud computing is **(72)** — the ability to automatically increase or decrease resources according to workload. This means a company running an e-commerce site can **(73)** additional servers during a shopping festival and release them afterwards, paying only for what it actually **(74)**. Another important concept is virtualization, which allows multiple virtual machines to run on a single physical server, improving resource **(75)**.

| 题号 | 选项 |
|:----:|------|
| (71) | A. on average　B. **on demand**　C. on purpose　D. on board |
| (72) | A. reliability　B. **elasticity**　C. durability　D. portability |
| (73) | A. release　B. delete　C. **provision**　D. compile |
| (74) | A. wastes　B. **consumes**　C. produces　D. invests |
| (75) | A. **utilization**　B. consumption　C. pollution　D. corruption |

<details>
<summary>答案与解析</summary>

**答案：71-B　72-B　73-C　74-B　75-A**

**71. B — on demand（按需）**
- 线索：**常识 + 固定搭配**。"云计算让用户___获取计算资源" → 云计算的定义就是**按需**获取。`on demand` 是云计算的标准描述词。
- 排除：on average（平均）、on purpose（故意）、on board（在船上/入职）都不搭。

**72. B — elasticity（弹性）**
- 线索：**破折号后的解释** ← 第 1 优先级线索！
  "the ability to **automatically increase or decrease** resources according to workload" = 自动增减资源 = **弹性**。
- 即使你不认识 elasticity，也能靠这句解释选出来。

**73. C — provision（配置/开通）**
- 线索：**并列对比**。空格与后面的 `release`（释放）对应：节日期间"开通"服务器，节后"释放"它们。
- provision 作动词 = 提供/配置资源。这是云计算的标准术语。

**74. B — consumes（消耗）**
- 线索：**固定说法** `pay-as-you-go` / "pay for what you consume"（按实际消耗付费）。
- 排除：wastes（浪费）语义负面；produces（生产）主语错；invests（投资）不搭。

**75. A — utilization（利用率）**
- 线索：**固定搭配** `resource utilization`（资源利用率）+ 语义（虚拟化提升资源利用率）。
- 排除：consumption 也有"消耗"义，但技术文里说"资源利用"固定用 utilization。

</details>

## 📝 演练二 · Microservices（微服务）

> A microservices architecture structures an application as a collection of **(71)** coupled services. Each service is designed around a specific business capability and can be developed, deployed and scaled **(72)**. Because services communicate over the network rather than through in-process calls, developers must handle **(73)** failures gracefully — for example, by using a circuit breaker that stops calling a service that is known to be down. To reduce this complexity, many teams place an API **(74)** in front of the services to handle authentication, routing and rate limiting. Despite these benefits, microservices also increase operational **(75)**, since a system that once consisted of one application now consists of dozens.

| 题号 | 选项 |
|:----:|------|
| (71) | A. tightly　B. **loosely**　C. hardly　D. closely |
| (72) | A. **independently**　B. dependently　C. instantly　D. rarely |
| (73) | A. **remote**　B. local　C. internal　D. static |
| (74) | A. **gateway**　B. compiler　C. browser　D. debugger |
| (75) | A. **overhead**　B. output　C. outcome　D. outbreak |

<details>
<summary>答案与解析</summary>

**答案：71-B　72-A　73-A　74-A　75-A**

**71. B — loosely（松散地）**
- 线索：**常识 + 固定搭配** `loosely coupled`（松耦合）。微服务的核心定义就是松耦合。
- 若认识 `decouple`（解耦）更好。

**72. A — independently（独立地）**
- 线索：**并列结构**。`developed, deployed and scaled ___` — 三个动词并列，缺一个副词修饰它们。
- 语义：微服务的特点就是**独立**开发、部署、伸缩。答案必定是 independently。

**73. A — remote（远程的）**
- 线索：**因果 + 对比**。前句说"服务通过网络通信，而不是进程内调用"→ 所以要处理的是**远程**调用失败。
- `remote failure` 是分布式系统的标准说法。

**74. A — gateway（网关）**
- 线索：**破折号/同位解释** + 固定搭配 `API gateway`（API 网关）。
- 后面列举的功能（认证、路由、限流）正是 API 网关的职责 → 即使不认识 gateway 也能推出来。

**75. A — overhead（开销）**
- 线索：**转折词 Despite**。"尽管有这些好处，微服务也增加了运维___" → 转折后是**负面词**。
- `operational overhead`（运维开销）是固定搭配。
- 排除：output（产出）、outcome（结果）中性偏正面，与 Despite 矛盾；outbreak（爆发）完全不同义。

> 🎯 **本篇的解题亮点**：75 题只靠 `Despite`（尽管）这一个转折词，就能确定空里要填负面词，从而排除 B、C。**这就是线索法的威力**。

</details>

## 📝 演练三 · AI / RAG（2026 新大纲方向）

> Large language models (LLMs) have become a common component of modern systems. However, an LLM only knows what was included in its training data, so it may produce outdated or incorrect answers — a problem often called **(71)**. Retrieval-Augmented Generation (RAG) addresses this by first retrieving relevant documents from an external knowledge base and then asking the model to generate an answer **(72)** those documents. When designing such a system, architects must consider inference **(73)**, which directly affects user experience, as well as the cost of each request. They should also make the model's behavior **(74)**, so that users can understand why a particular answer was produced. Finally, safeguards must be added to prevent the model from leaking **(75)** information.

| 题号 | 选项 |
|:----:|------|
| (71) | A. **hallucination**　B. hesitation　C. isolation　D. migration |
| (72) | A. depended　B. **based on**　C. relied　D. insisted |
| (73) | A. **latency**　B. legacy　C. luxury　D. literacy |
| (74) | A. **explainable**　B. exchangeable　C. expandable　D. expendable |
| (75) | A. **sensitive**　B. sensible　C. sensory　D. sentimental |

<details>
<summary>答案与解析</summary>

**答案：71-A　72-B　73-A　74-A　75-A**

**71. A — hallucination（幻觉）**
- 线索：**破折号 + 同义解释**。"产生过时或错误的答案" = 大模型**幻觉**。
- `hallucination` 是 2024 年后的绝对高频词，务必记住。

**72. B — based on（基于）**
- 线索：**固定搭配 + 词性**。空后是 `those documents`（名词短语），需要一个**介词**。
- 四个选项里只有 `based on` 是介词短语。A、C、D 都是动词过去式且都需接介词（depend **on** / rely **on** / insist **on**）。
- 🎯 **这题用「词性判断法」1 秒出答案**。

**73. A — latency（延迟）**
- 线索：**后置定语从句** `which directly affects user experience`（直接影响用户体验）→ 推理延迟。
- 排除：legacy（遗留）、luxury（奢侈）、literacy（读写能力）都不搭。

**74. A — explainable（可解释的）**
- 线索：**因果** `so that users can understand why…`（让用户理解为什么）→ **可解释性**。
- `-able` 结尾的形容词：exchangeable（可交换的）、expandable（可扩展的）、expendable（可消耗的）。

**75. A — sensitive（敏感的）**
- 线索：**固定搭配** `sensitive information`（敏感信息）。
- 🔴 形近词陷阱：`sensible` = 明智的，意思完全不同！见[第八节](#八形近词--易混词辨析)。

</details>

# 十二、考场策略

### ⏰ 什么时候做英语题？

| 方案 | 做法 | 适用 |
|------|------|------|
| 🟢 **推荐：发卷后先做** | 拿到卷子（或机考可翻页时）**先翻到最后 5 题做完** | 所有人。理由：英语题不需要技术推理，脑子最清醒时做最准；且**避免最后时间不够，慌乱中丢掉这最容易的 5 分** |
| 🟡 备选：最后统一做 | 做完 70 题后，留 **8 分钟**集中处理 | 英语阅读快、不慌的人 |
| 🔴 不推荐：穿插做 | 做到第 70 题时顺便做 | 此时脑子已疲累，正确率明显下降 |

> 💡 **机考提示**：软考机考通常**可以前后翻页**。进场确认操作后，第一件事就是翻到最后 5 题做掉英语。

### 时间分配

```
5 道英语题 × 5 分钟 = 最多 8 分钟
  第 1 步 读首句定主题   …… 30 秒
  第 2 步 通读抓大意     …… 1 分钟
  第 3 步 逐空找线索     …… 4 分钟（每空约 45 秒）
  第 4 步 代回通读检查   …… 30 秒
```

### 🎯 考场救命三招（实在看不懂时）

1. **找破折号和冒号**——后面那句话基本就是答案的中文翻译。
2. **看词性**——空前是 `a/the/to/of`，直接排除一半选项。
3. **选"最专业的那个"**——如果四个选项里有一个是明显的技术术语（如 `gateway`、`latency`），而另外三个都是普通词，选技术术语。**命题人不会把专业术语当干扰项放到一个普通语境的正确答案旁边**（反过来：如果文章讲的是通用概念，别硬选技术词）。

### ⚠️ 最后提醒

- **英语题不倒扣分，不会也要蒙**。
- 5 题全蒙，期望得分 = 5 × 25% = **1.25 分**；用本篇方法，期望 = **3.5~4.5 分**。
- **差的这 3 分，可能就是你和及格线之间的全部距离。**

---

📌 专业英语是"**看起来最吓人、实际最容易拿**"的 5 分。按第 11 节的计划走 30 天，考场上它会变成你的送分题。
