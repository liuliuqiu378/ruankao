# 零、给新手的三句话

**第一句：计算题不需要你"聪明"，需要你"见过"。**
软考计算题的套路极其固定，每年就那 20 来个模型换数字。你不需要会推导，只需要**看到题能认出模型、套对公式**。

**第二句：单位不统一是头号杀手。**
据统计，算错的人里有一半不是不会，而是 **毫秒没换成秒、MB 没换成 Mb、分钟没换成小时**。
> 🔴 **强制动作**：拿到题第一件事——**把所有数字连同单位抄下来，统一到一个单位，再动笔**。

**第三句：先判断"考哪个模型"，再动笔。**
看到题先花 10 秒归类（是流水线？是子网？是挣值？），认错模型 = 全错。

## 三大秒杀技巧（不会算时用来救命）

| 技巧 | 做法 | 例子 |
|------|------|------|
| **① 量纲排除法** | 先看选项单位，错的直接划掉 | 问"传输时延（秒）"，选项里有 `kbps` 的排除；问"存储容量"，数量级是 `10⁶` 而不是 `10⁹` 的排除 |

# 一、进制与数据表示

## 1.1 先建立直觉

> **二进制就是"只有 0 和 1 的十进制"**，进位规则从"满 10 进 1"变成"满 2 进 1"。
> 生活类比：**电表/水表**——每一位只转 0~9 再归零，二进制每一位只走 0、1 再归零。

## 1.2 必须记住的换算

| 内容 | 公式 / 结论 |
|------|-------------|
| 二 ↔ 十 | 按权展开：`1011B = 1×2³ + 0×2² + 1×2¹ + 1×2⁰ = 11` |
| 十 → 二（整数） | **除 2 取余，倒序排列** |
| 十 → 二（小数） | **乘 2 取整，正序排列** |
| 二 ↔ 八 | **3 位一组**（从小数点向两侧分组，不足补 0） |
| 二 ↔ 十六 | **4 位一组** |

## 1.3 原码 / 反码 / 补码（每年必考）

**直觉**：计算机里只有加法器，没有减法器。为了让"减法变成加法"，才发明了补码。
生活类比：**时钟**——从 10 点调到 8 点，可以逆时针拨 2 格（减 2），也可以顺时针拨 10 格（加 10）。**10 就是 -2 在"模 12"下的补码**。

| 概念 | 正数 | 负数 | 表示范围（n 位） |
|------|------|------|-----------------|
| 原码 | 符号位 0 + 数值 | 符号位 1 + 数值 | -(2ⁿ⁻¹-1) ~ +(2ⁿ⁻¹-1) |
| 反码 | 同原码 | 符号位不变，数值位**取反** | 同上 |
| **补码** | 同原码 | 反码 **+1** | **-2ⁿ⁻¹ ~ +(2ⁿ⁻¹-1)** |

> 🔴 **唯一要背的数字**：**n 位补码范围 = -2ⁿ⁻¹ ~ +2ⁿ⁻¹-1**，负数比正数多一个。
> 8 位：`-128 ~ 127`；16 位：`-32768 ~ 32767`。
> 口诀：**"补码负数多一个，2 的 n-1 次方是下界。"**

## 1.4 浮点数（IEEE 754 简化考法）

```
单精度（32位）：  符号位 S(1) | 阶码 E(8，偏移 127) | 尾数 M(23)
双精度（64位）：  符号位 S(1) | 阶码 E(11，偏移 1023) | 尾数 M(52)
真值 = (-1)^S × 1.M × 2^(E - 偏移值)
```
- 阶码偏移量：**单精度 127，双精度 1023**（记住这两个数就行）
- 尾数隐含最高位 1（规格化时）

## 1.5 ⚠️ 单位换算陷阱表（抄下来贴在桌上）

| 场景 | 规则 | 例子 |
|------|------|------|
| **存储容量** | 1KB = **1024** B（2 进制） | 2MB = 2×1024×1024 B |
| **通信速率 / 带宽** | 1kbps = **1000** bps（10 进制） | 100Mbps = 100×10⁶ bps |
| **字节与位** | 1 Byte = **8** bit | 100Mbps ÷ 8 = **12.5 MB/s** |
| **时间** | 1s = 10³ms = 10⁶μs = 10⁹ns | 4ns = 4×10⁻⁹ s |

> ⚠️ **最常见的坑**：题目给带宽 `100 Mbps`，问"传输 100 MB 文件要多久"。
> 正解：`100 MB × 8 = 800 Mb`；`800 Mb ÷ 100 Mbps = 8 秒`。
> 错解（忘了 ×8）：1 秒 —— 差 8 倍。

# 二、计算机系统计算

> 这一章是**计算题第一大来源**，每年 3~5 题。

## 2.1 流水线（必考）

### ① 直觉

> 洗衣店流水线：**一个人洗-甩-烘全流程串行**，等于 3 台机器里只有 1 台在干活。
> 改成流水线：第 1 件进烘干时，第 2 件已经在甩干，第 3 件开始洗 —— **3 台机器同时干活**。

### ② 公式（只背这 4 行）

设：指令条数 `n`，流水线段数 `k`，各段中最长耗时为 `Δt`（**流水线周期 = 最长段耗时**）。

```
① 流水线周期 Δt = max(各段耗时)

② 流水线执行时间 T流 = (k + n - 1) × Δt
   解释：第一条指令走完 k 段用 k·Δt，之后每 Δt 出一条，还剩下 n-1 条

③ 顺序执行时间 T顺 = n × (各段耗时之和)     ← 不是 n×k×Δt！除非各段相等

④ 吞吐率 TP = n / T流     极限吞吐率 TPmax = 1 / Δt
   加速比 S = T顺 / T流   效率 E = S / k
```

### ③ 例题精讲

> **题**：某指令流水线分 4 段：取指 2ns、分析 3ns、执行 4ns、写回 2ns。连续执行 100 条指令。
> 求：① 流水线周期 ② 流水线执行时间 ③ 加速比 ④ 效率 ⑤ 极限吞吐率

```
① Δt = max(2, 3, 4, 2) = 4 ns
② T流 = (4 + 100 - 1) × 4 = 103 × 4 = 412 ns
③ T顺 = 100 × (2+3+4+2) = 100 × 11 = 1100 ns
   S = 1100 / 412 ≈ 2.67
④ E = S / k = 2.67 / 4 = 66.7%
⑤ TPmax = 1 / 4ns = 2.5 × 10⁸ 条/秒
```

### ④ ⚠️ 陷阱

- **陷阱 1**：`T顺` 是 `n × 各段之和`，**不是** `n × k × Δt`。只有各段耗时相等时才等价。
- **陷阱 2**：流水线段数 `k` 只算**功能段**，不算锁存器。
- **陷阱 3**：题目问"流水线周期"时，取的是**最长段**，不是平均、不是总和。
- **陷阱 4**：**瓶颈段**——若某段特别慢，可将其**细分或并联**，这是案例常见追问。

### ⑤ 口诀
> **"周期取最长，时间 k+n-1，顺时 n 乘总和，加速比一除效率除 k。"**

## 2.2 Cache 平均访问时间（必考）

### ① 直觉

> 你写文档时 90% 的字都在输入法候选里（Cache，1 秒出），10% 要去翻词典（主存，10 秒）。
> 平均查一个字 = 0.9×1 + 0.1×10 = 1.9 秒。

### ② 公式

```
命中率 h = 命中次数 / 总访问次数

【先访问 Cache，未命中再访问主存】（顺序访问，最常考）
  平均访问时间 T = h × tc + (1-h) × (tc + tm)

【Cache 与主存同时访问】
  平均访问时间 T = h × tc + (1-h) × tm

  其中 tc = Cache 存取时间，tm = 主存存取时间
  加速比 = tm / T
```

> 📌 **怎么判断题中是哪种**：题干说"先访问 Cache，未命中时再访问主存"→ 用第一个；说"同时访问 / 并行查找"→ 用第二个。**没说就按第一个**（顺序访问）。

### ③ 例题精讲

> **题**：Cache 存取时间 10ns，主存存取时间 100ns，命中率 95%。求平均访问时间与加速比。

```
顺序访问：
  T = 0.95 × 10 + 0.05 × (10 + 100)
    = 9.5 + 5.5 = 15 ns
  加速比 = 100 / 15 ≈ 6.67

若题中说"同时访问"：
  T = 0.95 × 10 + 0.05 × 100 = 9.5 + 5 = 14.5 ns
```

### ④ ⚠️ 陷阱

- `1-h` 是**失效率**，别写成 `h`。
- 平均时间一定介于 `tc` 和 `tc+tm` 之间，算出来超范围就是错了（**用这个自检**）。
- 三级存储（Cache-主存-外存）同理逐层套：**T = h₁t₁ + (1-h₁)[h₂t₂ + (1-h₂)t₃]**。

### ⑤ 口诀
> **"命中乘快的，失效乘慢的，加起来就是平均的。"**

## 2.3 主存容量与芯片数（高频）

### ① 公式

```
① 地址范围对应的容量（按字节编址）
   容量 = 末地址 - 首地址 + 1        ← 千万别忘 +1！

② 芯片数 = 总容量 / 单片容量
         = (总字数 / 单片字数) × (总位宽 / 单片位宽)

③ 地址线数 = log₂(编址单元数)
   例：4GB 按字节编址 → 需要 32 根地址线（2³² = 4G）
```

### ② 例题精讲

> **题**：内存按字节编址，地址区间 `A4000H ~ CBFFFH`，若用 `32K × 8bit` 的芯片构成，需要多少片？

```
第一步：算容量
  CBFFFH - A4000H + 1 = 28000H
  28000H = 2×16⁴ + 8×16³ = 131072 + 32768 = 163840 B
  163840 ÷ 1024 = 160 KB

第二步：算芯片数
  单片容量 32K × 8bit = 32 KB
  芯片数 = 160 KB / 32 KB = 5 片
```

### ③ ⚠️ 陷阱
- **忘记 +1**（首末地址都算在内）。
- 十六进制减法要借位，建议转成十进制再算，或分段算。
- **字编址 vs 字节编址**：题目说"按字编址，字长 32 位"时，容量要 ×4 才是字节数。

## 2.4 磁盘存取时间（高频，也是案例常客）

### ① 三部分时间

```
磁盘存取时间 = 寻道时间 + 旋转延迟（等待时间） + 传输时间

① 寻道时间：磁头移动到目标磁道（题目一般直接给）
② 旋转延迟：目标扇区转到磁头下方
     平均旋转延迟 = 1 / (2 × 转速)      例：7200 转/分 = 120 转/秒
                                          平均延迟 = 1/(2×120) ≈ 4.17 ms
③ 传输时间 = 数据量 / 传输速率
           或 = 每道记录数对应的时间片
```

### ② 经典题型：记录优化存放（必考，也最易错）

> **题（真题原型）**：某磁盘旋转速度 **20ms/周**，每个磁道划分 **10 个扇区**，每扇区存放 1 个记录。处理程序每读出一个记录后花 **4ms** 处理。问：
> ① 记录**顺序存放**时，处理完 10 个记录的总时间？
> ② 若**优化分布**，总时间是多少？

**解法：画时间轴（不要硬套公式，画出来最稳）**

先算基础量：每转一周 20ms，10 个记录 → **每个记录占 2ms**；读 1 个记录需 2ms，处理需 4ms。

**① 顺序存放（R1, R2 … R10 挨着排）**

```
t=0    读出 R1（用 2ms）→ t=2
t=2    处理 R1（用 4ms）→ t=6
t=6    R2 早就转过去了（R2 在 t=2 通过），只能等下一圈
       下一圈 R2 出现在 t = 2 + 20 = 22ms
       等待 16ms → 读 R2（2ms）→ 处理（4ms）→ t = 28ms
       ... 后续每个记录都是「等 16 + 读 2 + 处理 4」= 22ms
总时间 = 6 + 9 × 22 = 6 + 198 = 204 ms
```

> 🔑 **关键判断**：处理时间（4ms）> 记录间隔（2ms）→ 处理完时下一个记录已经转过去了，**必须等一整圈**。
> 如果处理时间 ≤ 记录间隔，则可以连续读，总时间 = n × 间隔 + 最后一个的处理时间。

**② 优化分布（错位存放）**

```
把记录间隔拉大到「读 2ms + 处理 4ms = 6ms」，即每隔 3 个扇区放一个记录。
处理完 R_i，磁头刚好到 R_{i+1} 起点，无需等待。
总时间 = 10 × 6 = 60 ms
```

**③ 单/双缓冲区（延伸）**
- **单缓冲区**：读入下一块 与 处理当前块 **不能并行** → `T = n × (读入 + 处理) + 最后一块传出`
- **双缓冲区**：读入与处理可**并行** → `T = max(读入, 处理) × n + 读入 + 传出`

### ③ ⚠️ 陷阱
- "转速 7200 转/分"要换成"转/秒"：`7200 ÷ 60 = 120`。
- **平均**旋转延迟是半圈，**最大**是一整圈，看题目问哪个。
- 优化存放题：答案通常远小于顺序存放（204ms → 60ms），算出来差不多就是错了。

### ④ 口诀
> **"处理比间隔快，就得等一圈；错位放一放，一圈就搞定。"**

## 2.5 总线带宽

```
总线带宽（数据传输率）= 总线宽度 / 8 × 总线工作频率
例：总线宽 32 位，频率 66 MHz
    带宽 = 32/8 × 66M = 4 × 66 = 264 MB/s

若一个总线周期传送一次数据需 N 个时钟周期，则再除以 N
```

## 2.6 位示图（磁盘空闲空间管理，选择题常考）

```
块数 = 磁盘容量 / 每块大小
位示图位数 = 总块数        ← 1 位代表 1 个物理块（0=空闲，1=占用）
占用位数 = 已用块数
```

> **例题**：1 TB 磁盘，块大小 4 KB，求位示图需要多少字节？
> ```
> 总块数 = 1 TB / 4 KB = 2^40 / (4×2^10) = 2^40 / 2^12 = 2^28 ≈ 2.68 亿块
> 位示图位数 = 2^28 位
> 字节数 = 2^28 / 8 = 2^25 字节 = 32 MB
> ```
> ⚠️ 陷阱：位示图按"位"算，最后要 ÷8 转字节；块大小单位（KB/MB）要统一。

# 三、可靠性计算

> 与案例 06b 完全共用。选择题只考**套公式**，大题才考写步骤。

## 3.1 三大时间指标

```
MTBF = MTTF + MTTR
可用度 A = MTTF / MTBF = MTTF / (MTTF + MTTR)
年停机时间 = (1 - A) × 8760 小时
```

| 可用度 | 几个 9 | 年停机 | 适用 |
|:------:|:------:|-------:|------|
| 0.99 | 2 个 9 | ~87.6 h | 普通办公 |
| 0.999 | 3 个 9 | ~8.76 h | 企业核心 |
| 0.9999 | 4 个 9 | ~52.6 min | 金融交易 |
| 0.99999 | 5 个 9 | ~5.26 min | 电信级 |

## 3.2 串并联可靠度

```
串联：R总 = R1 × R2 × … × Rn          ← 任一坏则全坏
并联：R总 = 1 - (1-R1)(1-R2)…(1-Rn)   ← 全坏才全坏
混联：先算并联子树，再与串联部分相乘
```

**失效率形式（更常考！）**
```
串联：λ总 = λ1 + λ2 + … + λn
      MTTF总 = 1 / λ总
单个：R(t) = e^(-λt)，MTTF = 1/λ
```

## 3.3 例题

> **题**：3 个部件串联，MTTF 分别为 1000h、2000h、500h，求系统 MTTF 与 100 小时后的可靠度。

```
λ1 = 1/1000 = 0.001    λ2 = 1/2000 = 0.0005    λ3 = 1/500 = 0.002
λ总 = 0.0035 /h
MTTF总 = 1 / 0.0035 ≈ 285.7 h
R(100) = e^(-0.0035 × 100) = e^(-0.35) ≈ 0.705
```

## 3.4 N 模冗余

```
三模冗余 TMR（2/3 表决）：R = 3R² - 2R³
例：R单 = 0.9 → R_TMR = 3×0.81 - 2×0.729 = 2.43 - 1.458 = 0.972
```

## 3.5 ⚠️ 陷阱
- **单位**：MTTF 用小时，MTTR 用分钟 → 必须先统一。
- **"可靠性" vs "可用性"**：可靠性 = 不发生故障的能力（不中断）；可用性 = 可正常使用的时间比例（允许短暂中断后恢复）。别混。
- 串联 N 个相同部件：`R总 = Rⁿ`；并联 N 个相同部件：`R总 = 1-(1-R)ⁿ`。

## 3.6 口诀
> **"串联相乘越串越差，并联相减越并越强；MTTF 是失效率的倒数，串起来失效率相加。"**

# 四、网络与通信计算

## 4.1 子网划分与 CIDR（必考 2 题左右）

### ① 直觉

> IP 地址 = **街道号（网络位）+ 门牌号（主机位）**。
> 子网掩码就是一把"分界尺"：`1` 的部分是街道，`0` 的部分是门牌。
> 从主机位借几位当街道号，就等于**把一条大街切成 2ⁿ 条小巷**。

### ② 公式

```
① 可用主机数 = 2^主机位数 - 2    ← 减 2：去掉网络地址（全0）和广播地址（全1）

② 子网数 = 2^借用的主机位数

③ 块大小（每个子网的跨度）= 256 - 掩码最后一个非 255 字节的值
   例：/26 → 掩码 255.255.255.192 → 块大小 = 256 - 192 = 64

④ CIDR 聚合（路由汇聚）：取各地址块的**最长公共前缀**
```

### ③ 例题精讲

> **题**：将 `192.168.10.0/24` 划分为 `/26` 的子网。求子网数、每子网可用主机数、各子网网络地址。

```
借用位数 = 26 - 24 = 2  → 子网数 = 2² = 4
主机位 = 32 - 26 = 6    → 可用主机 = 2⁶ - 2 = 62
掩码 = 255.255.255.192（因为 256-64=192）
块大小 = 64

4 个子网：
  192.168.10.0/26    （主机 .1 ~ .62，  广播 .63）
  192.168.10.64/26   （主机 .65 ~ .126，广播 .127）
  192.168.10.128/26  （主机 .129 ~ .190，广播 .191）
  192.168.10.192/26  （主机 .193 ~ .254，广播 .255）
```

> **题（路由聚合）**：`192.168.0.0/24`、`192.168.1.0/24`、`192.168.2.0/24`、`192.168.3.0/24` 聚合为？

```
看第三字节：0=00000000  1=00000001  2=00000010  3=00000011
公共前缀 = 000000（前 6 位）→ 前 16+6 = 22 位
聚合结果 = 192.168.0.0/22
```

### ④ 常用掩码速查（背下来）

| CIDR | 掩码（最后一字节） | 可用主机 |
|:----:|:------------------:|:--------:|
| /24 | 255.255.255.0 | 254 |
| /25 | .128 | 126 |
| /26 | .192 | 62 |
| /27 | .224 | 30 |
| /28 | .240 | 14 |
| /29 | .248 | 6 |
| /30 | .252 | 2（常用于点对点链路） |

### ⑤ ⚠️ 陷阱
- **忘记 -2**：问"可用主机数"必须减 2；问"地址数/主机位数"不减。
- 掩码 `/24` 写全应是 `255.255.255.0`，不要只写 24。
- 判断"IP 是否属于某子网"：把 IP 和掩码做**按位与**，看结果是否等于网络地址。

## 4.2 时延计算

```
① 发送时延（传输时延）= 数据帧长度(bit) / 发送速率(bps)
② 传播时延 = 信道长度(m) / 信号传播速率(m/s)   ← 通常取 2×10⁸ m/s（光纤/铜缆）
③ 处理时延 + 排队时延（题目一般给或忽略）
④ 总时延 = ① + ② + ③
⑤ 带宽-时延积 = 带宽 × 往返时延 RTT   ← 表示"在途的数据量"
⑥ 停等协议信道利用率 = 1 / (1 + 2a)，其中 a = 传播时延 / 发送时延
```

> **例题**：主机 A 向 B 发送 1000 B 数据，速率 100 Mbps，距离 1000 km，信号速率 2×10⁸ m/s。求发送时延与传播时延。
```
发送时延 = 1000 × 8 / (100 × 10⁶) = 8000 / 10⁸ = 8×10⁻⁵ s = 80 μs
传播时延 = 1000×10³ / (2×10⁸) = 5×10⁻³ s = 5 ms
→ 传播时延远大于发送时延（长途链路的典型特征）
```

## 4.3 奈奎斯特与香农（信道容量）

```
【奈奎斯特】无噪声信道：
   最大码元速率 B = 2W （波特）        W = 信道带宽(Hz)
   最大数据速率 R = 2W × log₂(V)      V = 码元离散值个数

【香农】有噪声信道：
   最大数据速率 C = W × log₂(1 + S/N)
   分贝换算： dB = 10 × log₁₀(S/N)   →  30dB ⇒ S/N = 1000
```

> **例题**：带宽 4 kHz，信噪比 30 dB，求最大数据速率。
```
S/N = 10^(30/10) = 1000
C = 4000 × log₂(1001) ≈ 4000 × 9.97 ≈ 39.9 kbps
```
> ⚠️ 陷阱：题目给的是 **dB**，必须先换成比值；给的是比值就直接用。两者别搞混。

## 4.4 差错控制码

### 海明码
```
校验位位数 r 满足：  2^r ≥ m + r + 1        （m = 数据位位数）
例：m = 8 → 2⁴=16 ≥ 8+4+1=13 → r = 4，共 12 位
    m = 16 → 2⁵=32 ≥ 16+5+1=22 → r = 5
```
- 校验位放在 **2⁰, 2¹, 2², 2³…**（第 1, 2, 4, 8 位）
- **海明距离 d** 与纠错检错能力：**检错 d-1 位，纠错 ⌊(d-1)/2⌋ 位**

### CRC 循环冗余校验
```
① 生成多项式 G(x) 的最高次幂 = 校验位位数
   例：G(x) = x³ + x + 1 → 二进制 1011 → 3 位校验位
② 在原始数据后补 r 个 0，用「模 2 除法」除以 G(x) 的二进制
③ 余数即为校验位（余数不足 r 位时左侧补 0）
```

> **例题**：数据 `1010`，G(x) = x³+x+1（即 1011），求 CRC 编码。
```
1010 后补 3 个 0 → 1010000
1010000 ÷ 1011（模2除）→ 余数 011
发送码 = 1010 011
```

### ⚠️ 陷阱
- 模 2 除法**不借位、不进位**，等价于**异或 XOR**。手算时最容易在这里算错。
- 海明码校验位位置从 **1** 开始数（不是 0）。

# 五、数据结构与算法计算

## 5.1 时间复杂度

### ① 常见量级（从小到大）

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

### ② 循环快速判定法（不用推导）

| 循环形态 | 复杂度 | 例子 |
|----------|:------:|------|
| 单层 `i < n` | O(n) | — |
| 单层 `i *= 2` 或 `i /= 2` | O(log n) | 二分查找 |
| 双层嵌套 `i<n` × `j<n` | O(n²) | 冒泡、选择、插入 |
| 双层 `i*=2` × `j<i` | **O(n)** | `Σ2ᵏ = 2n-1` |
| 递归 `T(n)=T(n/2)+O(1)` | O(log n) | 二分 |
| 递归 `T(n)=T(n/2)+O(n)` | O(n log n) | 归并、快排平均 |
| 递归 `T(n)=2T(n/2)+O(1)` | O(n) | 遍历二叉树 |
| 递归 `T(n)=T(n-1)+T(n-2)` | O(2ⁿ) | 朴素斐波那契 |

> **例题**：
> ```c
> for (i = 1; i < n; i *= 2)
>     for (j = 0; j < i; j++)
>         sum++;
> ```
> 外层 i = 1, 2, 4, 8 … n（共 log₂n 轮），内层分别执行 1, 2, 4 … n 次
> 总和 = 1 + 2 + 4 + … + n = 2n - 1 → **O(n)**
> （很多人会误答 O(n log n)——**注意内层上界是 i 不是 n**）

### ③ 主定理（记不住就跳过，用上面表格就够）

```
T(n) = a·T(n/b) + f(n)
令 c = log_b(a)
  f(n) = O(n^d) 且 d < c  →  T(n) = O(n^c)
  f(n) = O(n^d) 且 d = c  →  T(n) = O(n^c · log n)
  f(n) = O(n^d) 且 d > c  →  T(n) = O(n^d)
```

## 5.2 数组地址计算

```
二维数组 A[0..m-1][0..n-1]（m 行 n 列），每个元素占 L 字节，首地址 Base

【按行优先（C/Java）】
  Loc(A[i][j]) = Base + ( i × n + j ) × L

【按列优先（FORTRAN）】
  Loc(A[i][j]) = Base + ( j × m + i ) × L
```

> **例题**：`A[0..5][0..7]`（6 行 8 列），按行优先，每元素 2 字节，首址 1000。求 `A[3][5]`。
```
按行：1000 + (3 × 8 + 5) × 2 = 1000 + 58 = 1058
按列：1000 + (5 × 6 + 3) × 2 = 1000 + 66 = 1066
```
> ⚠️ 陷阱：题目若从 `A[1..6][1..8]` 起始（下标从 1 开始），要先减去下界：`(i-1)×n + (j-1)`。

## 5.3 树

### 二叉树性质（背 4 条）

```
① 第 i 层最多 2^(i-1) 个节点（根为第 1 层）
② 深度为 h 的二叉树最多 2^h - 1 个节点
③ 叶子数 n₀ = 度为 2 的节点数 n₂ + 1      ← 任何二叉树都成立
④ n 个节点的完全二叉树深度 = ⌊log₂ n⌋ + 1
```

### 完全二叉树的叶子数计算（高频）

```
完全二叉树中：度为 1 的节点 n₁ 只能是 0 或 1
  n 为偶数 → n₁ = 1
  n 为奇数 → n₁ = 0
由 n₀ + n₁ + n₂ = n 且 n₀ = n₂ + 1 联立求解
```

> **例题**：完全二叉树有 100 个节点，求叶子节点数。
```
n = 100（偶数）→ n₁ = 1
n₀ + 1 + n₂ = 100，且 n₀ = n₂ + 1
→ (n₂ + 1) + 1 + n₂ = 100  →  2n₂ = 98  →  n₂ = 49
→ n₀ = 50
```

### 哈夫曼树与 WPL

```
WPL（带权路径长度）= Σ( 叶子权值 × 该叶子到根的路径长度 )
构造：每次取权值最小的两个节点合并，重复至只剩一个根
哈夫曼编码长度 = 各字符在树中的路径长度
```

> **例题**：权值 {5, 9, 12, 13, 16, 45}，求哈夫曼树的 WPL。
```
合并过程：
  5+9=14  → {12,13,14,16,45}
  12+13=25 → {14,16,25,45}
  14+16=30 → {25,30,45}
  25+30=55 → {45,55}
  45+55=100（根）

深度：45→1；25、30→2；12、13、16、14→3；5、9→4
WPL = 45×1 + 25×2 + 30×2 ... 按叶子算：
    = 5×4 + 9×4 + 12×3 + 13×3 + 16×3 + 45×1
    = 20 + 36 + 36 + 39 + 48 + 45 = 224
```

> ⚠️ 陷阱：WPL 也可以直接 = **所有非叶子节点权值之和**。上例非叶节点为 14+25+30+55+100 = 224 ✓（自检用）

## 5.4 图

| 图类型 | 边数 | 说明 |
|--------|------|------|
| 无向完全图 | n(n-1)/2 | 任意两点有边 |
| 有向完全图 | n(n-1) | 双向都有 |
| 连通无向图（最少） | n-1 | 即一棵树 |
| 强连通有向图（最少） | n | 构成一个环 |

- **生成树**：连通图 n 个顶点 → 生成树有 **n-1** 条边
- **最小生成树算法**：Prim O(n²)（稠密图）、Kruskal O(e·log e)（稀疏图）

n=6 → 15 < 16  ✗
n=7 → 21 ≥ 16  ✓   → 至少 7 个顶点
```

## 5.5 查找与排序

### 折半查找（二分查找）

```
最大比较次数 = ⌈ log₂(n + 1) ⌉
平均查找长度 ASL ≈ log₂(n+1) - 1
前提：有序 + 顺序存储
```

> 例：n = 100 → ⌈log₂101⌉ = ⌈6.66⌉ = **7 次**

### 排序复杂度与比较次数

| 排序算法 | 平均 | 最坏 | 最好 | 稳定 | 比较次数 |
|----------|:----:|:----:|:----:|:----:|----------|
| 直接插入 | O(n²) | O(n²) | **O(n)**（有序） | ✅ | 最多 n(n-1)/2 |
| 冒泡 | O(n²) | O(n²) | **O(n)**（有序） | ✅ | 最多 n(n-1)/2 |
| 简单选择 | O(n²) | O(n²) | O(n²) | ❌ | n(n-1)/2（固定） |
| 快速 | **O(n log n)** | **O(n²)**（有序） | O(n log n) | ❌ | — |
| 堆 | O(n log n) | O(n log n) | O(n log n) | ❌ | — |
| 归并 | O(n log n) | O(n log n) | O(n log n) | ✅ | — |
| 希尔 | O(n^1.3) | O(n²) | — | ❌ | — |

> 🔴 **必背结论**：
> - **快速排序在"基本有序"时退化到 O(n²)**（选到最差枢轴）——高频陷阱！
> - **稳定的排序**：插入、冒泡、归并、基数（口诀：**"插泡归基，稳如老狗"**）
> - 要求"**前 k 小**"用堆排序，O(n log k)

### 页面置换算法的缺页次数

> **例题**：页面访问序列 `1,2,3,1,4,5,1,2,3,4`，物理块 3 块。求 FIFO / LRU / OPT 的缺页次数。

| 算法 | 淘汰规则 | 缺页次数 |
|------|----------|:--------:|
| FIFO | 淘汰**最早进入**的页 | 9 |
| LRU | 淘汰**最久未使用**的页 | 8 |
| OPT | 淘汰**未来最长时间不用**的页（理论最优） | 7 |

> ⚠️ **FIFO 有 Belady 异常**（增加物理块，缺页次数反而增加）；**LRU 和 OPT 不会有**。

# 七、项目管理计算

> **第二大计算题来源，每年 3~5 题。这部分公式多但极其固定，背熟就是送分。**

## 7.1 关键路径法（CPM）

### ① 直觉

> 装修房子：刷墙 3 天、铺地板 5 天、装灯 1 天。**铺地板必须等刷墙完**，装灯必须等铺地板完。
> 这条"3+5+1=9 天"的链条就是**关键路径**——它决定了**最早什么时候能完工**。
> 中间任何一环拖 1 天，整体就拖 1 天；但"买家具"这种可以边做边等的活，晚几天不影响（有**浮动时间**）。

### ② 六个参数

```
【正推，求最早】
  ES（最早开始）= max(所有紧前活动的 EF)
  EF（最早完成）= ES + 工期 D

【逆推，求最晚】
  LF（最晚完成）= min(所有紧后活动的 LS)
  LS（最晚开始）= LF - 工期 D

【浮动】
  总浮动 TF = LS - ES = LF - EF        ← 不影响总工期的可拖延时间
  自由浮动 FF = min(紧后活动 ES) - EF   ← 不影响紧后活动最早开始的可拖延时间

【关键路径】
  总浮动 TF = 0（或最小）的活动连成的路径；路径长度 = 项目最短工期
```

### ③ 例题精讲

> **题**：活动关系如下，求关键路径与总工期。
> | 活动 | 紧前 | 工期(天) |
> |------|------|:--------:|
> | A | — | 3 |
> | B | A | 5 |
> | C | A | 4 |
> | D | B, C | 6 |
> | E | C | 2 |

```
路径：
  A → B → D = 3 + 5 + 6 = 14
  A → C → D = 3 + 4 + 6 = 13
  A → C → E = 3 + 4 + 2 = 9

最长路径 = A→B→D = 14 天  → 关键路径，总工期 14 天

活动 C 的总浮动：
  C 在最长路径链上属于 A→C→D（13 天），可拖延 14 - 13 = 1 天
  → TF(C) = 1 天
```

### ④ 口诀
> **"最早正推取最大，最晚逆推取最小；总浮动为零是关键，压缩工期先压它。"**

---

## 7.2 挣值分析（EVM）— 必考，公式最多的一块

### ① 三个基本参数（先记这三个，其余全是它俩的组合）

| 参数 | 全名 | 含义 | 一句话 |
|------|------|------|--------|
| **PV** | 计划值 (BCWS) | 到此刻**应该**完成多少工作 | 计划要干多少 |
| **EV** | 挣值 (BCWP) | 到此刻**实际**完成了多少工作（按预算算） | 实际干了多少 |
| **AC** | 实际成本 (ACWP) | 到此刻**实际花了**多少钱 | 实际花了多少 |

> 🔑 **最关键的理解**：`EV` 是"已完成工作量的预算价值"。**三者都用钱（或工时）计量**，所以能直接相减。

### ② 四个偏差 + 两个指数（全表背下来）

```
【偏差 = 相减，正数是好事】
  成本偏差 CV = EV - AC      >0 成本节约；<0 超支
  进度偏差 SV = EV - PV      >0 进度提前；<0 落后

【指数 = 相除，大于 1 是好事】
  成本绩效 CPI = EV / AC     >1 节约；<1 超支
  进度绩效 SPI = EV / PV     >1 提前；<1 落后
```

### ③ 预测类（三个）

```
BAC = 项目完工总预算（Budget At Completion）

【典型偏差（当前偏差会持续下去）→ 用 CPI 修正，默认用这个】
  EAC（完工估算）= BAC / CPI
  ETC（完工尚需估算）= (BAC - EV) / CPI

【非典型偏差（当前偏差是偶然，以后按计划走）】
  EAC = AC + (BAC - EV)

【无论哪种，以下都成立】
  ETC = EAC - AC
  VAC（完工偏差）= BAC - EAC      >0 有结余；<0 超支
  TCPI（完工尚需绩效指数）= (BAC - EV) / (BAC - AC)
```

> 📌 **题干怎么区分典型/非典型**：
> 出现"**当前的偏差是由于特殊原因造成的，以后不会再发生**" → 非典型；
> 出现"**按目前的绩效继续**""**偏差具有代表性**" → 典型；**没说就按典型**。

### ④ 例题精讲

> **题**：某项目总预算 BAC = 200 万，第 6 个月末检查：
> 计划应完成 PV = 100 万，实际完成工作的预算价值 EV = 90 万，实际支出 AC = 110 万。
> 求 CV、SV、CPI、SPI，判断项目状态，并预测 EAC、VAC。

```
CV = EV - AC = 90 - 110 = -20 万    → 超支 20 万
SV = EV - PV = 90 - 100 = -10 万    → 进度落后（相当于少干了 10 万的活）

CPI = EV / AC = 90 / 110 ≈ 0.818    → 每花 1 元只产出 0.818 元的价值
SPI = EV / PV = 90 / 100 = 0.90     → 只完成了计划的 90%

判断：成本超支 + 进度落后，项目状态不佳

EAC = BAC / CPI = 200 / 0.818 ≈ 244.5 万
ETC = EAC - AC = 244.5 - 110 = 134.5 万
VAC = BAC - EAC = 200 - 244.5 = -44.5 万   → 预计超支 44.5 万
```

### ⑤ 口诀（背这一句，6 个公式全记住）

> **"EV 打头是老大，减 AC 看成本，减 PV 看进度，除完大于 1 就是好。"**
> 补一句：**"CV/SV/CPI/SPI：凡是 EV 在前，结果大于 0 / 大于 1，都是好消息。"**

## 7.3 PERT 三点估算

```
期望时间 tE = ( 最乐观 O + 4 × 最可能 M + 最悲观 P ) / 6
标准差 σ = (P - O) / 6        方差 σ² = [(P-O)/6]²

完工概率：
  tE ± 1σ  →  68.26%
  tE ± 2σ  →  95.44%
  tE ± 3σ  →  99.73%
```

> **例题**：某活动 O=6 天，M=12 天，P=24 天。求期望工期、标准差，以及"在 16 天内完成"的概率。
```
tE = (6 + 4×12 + 24) / 6 = 78 / 6 = 13 天
σ  = (24 - 6) / 6 = 3 天

16 天 = tE + 1σ → 概率 ≈ 50% + 68.26%/2 = 84.13%
```

## 7.4 沟通渠道数

```
沟通渠道数 = n(n - 1) / 2        （n = 干系人/团队成员数）
新增 m 人后增加的渠道数 = (n+m)(n+m-1)/2 - n(n-1)/2
```

> 例：团队从 6 人增至 9 人 → 原 15 条，现 36 条，增加 **21 条**。
> （这就是为什么"加人反而更慢"——沟通成本爆炸式增长）

## 7.5 决策树与 EMV

```
EMV（期望货币值）= Σ ( 各情景概率 × 该情景收益 )
选 EMV 最大的方案
```

> **例题**：方案 A：成功概率 60%，收益 100 万；失败概率 40%，损失 20 万。方案 B：稳赚 40 万。选哪个？
```
EMV(A) = 0.6 × 100 + 0.4 × (-20) = 60 - 8 = 52 万
EMV(B) = 40 万
→ 选 A
```

## 7.6 进度压缩（赶工）

```
赶工成本斜率 = (应急成本 - 正常成本) / (正常时间 - 应急时间)
压缩原则：优先压缩「关键路径上、成本斜率最小」的活动
```

## 7.7 运筹数学补充（选择题稳定出分点）

> 架构师上午题的"经济/管理计算"不止关键路径和挣值，下面三类也常出：

### ① 马尔可夫状态转移矩阵（注意：不是双机热备可靠性模型！）
```
状态转移：下一期份额 = 本期份额 × 转移概率矩阵 P
平稳分布 π 满足：π = π × P   （长期市场占有率）
```
> **例题**：A、B 两品牌，月转移矩阵 P = [[0.7,0.3],[0.2,0.8]]（行=当前品牌，列=下月）。若本月 A 占 60%、B 占 40%，求下月份额。
> ```
> 下月 A = 0.6×0.7 + 0.4×0.2 = 0.42 + 0.08 = 0.50
> 下月 B = 0.6×0.3 + 0.4×0.8 = 0.18 + 0.32 = 0.50
> ```
> ⚠️ 这个马尔可夫是"算市场占有率/用户转移"，与教材第9章"双机热备 λ/μ 可靠性模型"是两码事——后者案例不考手算。

### ② 线性规划（单纯形/图解法，考目标函数极值）
```
max/min Z = c₁x₁ + c₂x₂
s.t.  a₁x₁ + b₁x₂ ≤ (或 =, ≥) d₁  ...
```
> 选择题常给可行域顶点，让你代顶点算 Z 取最大/最小；约束不等式方向别看反。

### ③ 博弈论（纳什均衡，概念+小算）
```
纯策略纳什均衡：任何一方单独改变策略都不会更好
```
> 多为 2×2 收益矩阵，找"行最优∩列最优"的交点。选择题考识别，不考复杂求解。

# 八、性能与容量估算

> 这类题在选择题和案例中都会出现，是"架构师味儿"最浓的计算题。

## 8.1 Little 定律（排队论基础，近年热门）

```
L = λ × W
  L = 系统中平均并发数（队列中的请求数）
  λ = 到达率（QPS / 每秒请求数）
  W = 平均逗留时间（响应时间，注意单位统一为秒）

等价形式：并发数 = QPS × 平均响应时间
         QPS = 并发数 / 平均响应时间
```

> **例题**：系统 QPS = 200，平均响应时间 100 ms，求系统内平均并发请求数。
```
W = 100 ms = 0.1 s
L = λ × W = 200 × 0.1 = 20
→ 系统内平均同时有 20 个请求在处理
```

## 8.2 排队论 M/M/1（了解即可）

```
服务强度 ρ = λ / μ   （必须 < 1，否则队列无限增长）
系统中平均顾客数 L = ρ / (1 - ρ)
平均逗留时间 W = 1 / (μ - λ)
    其中 μ = 服务率（每秒能处理多少请求）
```

> **例题**：请求到达 λ = 10 个/秒，系统处理能力 μ = 12 个/秒。
```
ρ = 10/12 ≈ 0.833
L = 0.833 / (1 - 0.833) ≈ 5
W = 1 / (12 - 10) = 0.5 s
```
> ⚠️ 注意：**当 ρ 接近 1 时，响应时间会爆炸式增长**（L 的分母趋近 0）。这就是"为什么系统load 到 90% 就卡死"的数学解释。
> 例：ρ = 0.95 → L = 19；ρ = 0.99 → L = 99。**利用率从 95% 提到 99%，队列长度翻 5 倍**。

## 8.3 缓存命中率

```
命中率 = 命中次数 / 总访问次数
```

- **缓存穿透**：查一个根本不存在的 key → 每次都打到 DB
- **缓存击穿**：某个热点 key 过期瞬间，大量并发打到 DB
- **缓存雪崩**：大批 key 同时过期 → DB 压力骤增
- **布隆过滤器**：**可能有误判（假阳性），但绝不会漏判（假阴性）**——必考结论

## 8.4 磁盘阵列 RAID 容量

| 级别 | 方式 | 可用容量 | 容错 |
|:----:|------|:--------:|:----:|
| RAID 0 | 条带化 | **100%** | ❌ 无 |
| RAID 1 | 镜像 | **50%** | 坏 1 块 |
| RAID 5 | 分布式奇偶校验 | **(n-1)/n** | 坏 1 块 |
| RAID 6 | 双校验 | **(n-2)/n** | 坏 2 块 |
| RAID 10 | 先镜像再条带 | **50%** | 每组坏 1 块 |

> 例：4 块 1TB 盘组 RAID 5 → 可用 **3 TB**，利用率 75%

## 8.5 分库分表容量估算

```
单表数据量 = 总数据量 / 分表数
预估存储 = 单表数据量 × 单条记录大小 × 1.5（预留 50% 空间与索引）
```

# 九、多媒体数据量

```
① 未压缩图像容量 = 水平像素 × 垂直像素 × 位深度 / 8    （字节）
   例：1024×768，真彩色 24 位
       = 1024 × 768 × 24 / 8 = 2,359,296 B = 2,359,296 / 1,048,576 ≈ 2.25 MB

② 未压缩音频容量 = 采样频率 × 量化位数 × 声道数 × 时长 / 8
   例：44.1 kHz，16 bit，立体声，1 分钟
       = 44100 × 16 × 2 × 60 / 8 = 10,584,000 B ≈ 10.09 MB

③ 未压缩视频容量 = 每帧图像容量 × 帧率 × 时长
   例：2.25 MB/帧，25 fps，1 分钟
       = 2.25 × 25 × 60 = 3375 MB ≈ 3.30 GB
```

> ⚠️ 陷阱：分辨率单位（1024×768）、位深度（bit 要 ÷8）、字节换算（1MB=1024KB=1048576B）。

## 📎 附：计算题每日 15 分钟训练法

计算题属于"**不用就忘**"的技能，靠考前突击效果差。推荐每天 15 分钟：

1. **早上 5 分钟**：默写"一页纸公式卡"（只看框架，不看内容，卡住的地方标红）。
2. **中午 5 分钟**：从真题里挑 2 道计算题，**只做不说**，重点练"认模型"这一步（10 秒内说出这是哪类题）。
3. **晚上 5 分钟**：把白天错的题**重抄一遍题干 + 正确解法**，写清"我当时错在哪"。

> 🔑 关键是 **第 2 步的「认模型」**。考场上你不会没时间算，你只会**认不出这是哪类题**。
