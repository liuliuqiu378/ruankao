# 第 1 章 操作系统

## 1.1 进程与线程

### ① 直觉

> **进程 = 一栋房子**（有独立地址、独立水电表）；**线程 = 房子里的房间**（共享房子的地址和水电，但有各自的床和桌子）。
> 建房子贵（创建进程开销大），隔个房间便宜（创建线程开销小）；房子之间说话要靠写信（IPC），房间之间说话张嘴就行（共享内存）。

### ② 核心概念

| 概念 | 说明 |
|------|------|
| **进程** | 程序的一次执行过程，是**资源分配**的基本单位 |
| **线程** | 进程内的执行单元，是**CPU 调度**的基本单位 |
| **进程组成** | 程序段 + 数据段 + **PCB（进程控制块，进程存在的唯一标志）** |
| **PCB** | 进程唯一标识；包含 PID、状态、优先级、现场信息、资源清单等 |
| **线程共享** | 地址空间、全局变量、打开的文件、信号处理 |
| **线程独有** | 线程 ID、程序计数器、寄存器组、栈、errno |

### ③ 进程 vs 线程（必考对比表）

| 维度 | 进程 | 线程 |
|------|------|------|
| 基本单位 | **资源分配** | **CPU 调度** |
| 地址空间 | 独立，隔离性强 | 共享所属进程的地址空间 |
| 切换开销 | **大**（要换页表、刷新 TLB） | **小**（只换寄存器和栈） |
| 通信方式 | 管道、消息队列、共享内存、信号量、Socket | 共享全局变量（需同步） |
| 崩溃影响 | 一个进程崩溃**不影响**其他进程 | 一个线程崩溃**导致整个进程崩溃** |
| 并发性 | 进程间可并发 | 进程内线程也可并发（并发度更高） |

> 🔴 **必背结论**：
> - **进程是资源分配的最小单位，线程是 CPU 调度的最小单位**。
> - 线程**共享**什么、**独有**什么，是高频选择题。

### ④ 进程状态（三态模型）

```
        时间片到 / 被抢占
   ┌─────────────────► 就绪 ◄────────┐
   │                    │            │
   │                    │ 调度/分派   │ 等待的事件发生
   │                    ▼            │
   └────── 运行 ──────────────► 阻塞 ┘
        等待某事件(I/O请求等)
```

| 转换 | 触发 |
|------|------|
| 运行 → 阻塞 | 等待 I/O、申请资源失败（**主动行为**） |
| 阻塞 → 就绪 | I/O 完成、资源到位（**被动，非运行态**） |
| 运行 → 就绪 | 时间片用完、被高优先级抢占 |
| 就绪 → 运行 | 被调度 |

> ⚠️ **陷阱**：**阻塞不能直接到运行**，必须先到就绪。选项里有"阻塞→运行"的直接排除。

### ⑤ 进程间的两种关系

| 关系 | 含义 | 典型场景 |
|------|------|---------|
| **同步**（直接制约） | 协作：A 必须等 B 完成某步才能继续 | 生产者-消费者：消费者要等生产者放入 |
| **互斥**（间接制约） | 竞争：同一时刻只能一个进程用临界资源 | 两个进程同时要打打印机 |

- **临界资源**：一次只允许一个进程使用的资源（打印机、共享变量）
- **临界区**：访问临界资源的那段**代码**
- **同步机制四原则**：空闲让进、忙则等待、有限等待、让权等待

## 1.2 PV 操作与信号量

### ① 直觉

> 信号量 = **停车场的剩余车位显示屏**。
> **P 操作**（wait / 申请）：车位 -1；若 ≤0 说明没位了，排队等着。
> **V 操作**（signal / 释放）：车位 +1；若还有人排队，叫醒一个。

### ② 公式

```
P(S)： S = S - 1； 若 S < 0，则进程阻塞，进入等待队列
V(S)： S = S + 1； 若 S ≤ 0，则唤醒等待队列中的一个进程
```

| 信号量类型 | 初值 | 用途 |
|-----------|------|------|
| **互斥信号量** | **1** | 保护临界区，P、V 成对出现在**同一进程**内 |
| **同步信号量** | **0** 或 资源数 | 控制先后顺序，P、V 出现在**不同进程**中 |
| 资源信号量 | 资源总数 N | 表示可用资源数量 |

### ③ 经典模型：生产者-消费者（单缓冲区）

```
semaphore empty = 1;   // 空缓冲区数量
semaphore full  = 0;   // 满缓冲区数量（已放入产品）
semaphore mutex = 1;   // 互斥访问缓冲区

生产者：                      消费者：
  P(empty);                     P(full);
  P(mutex);                     P(mutex);
  放入产品;                     取出产品;
  V(mutex);                     V(mutex);
  V(full);                      V(empty);
```

> 🔴 **铁律**：
> 1. **同步 P 必须在互斥 P 之前**（`P(empty)` 在 `P(mutex)` 前）——否则会**死锁**（占着缓冲区等空位）。
> 2. **互斥的 P、V 必须紧挨着临界区**，中间不能有其他代码。
> 3. **P、V 必须成对出现**。

### ④ 例题

> **题**：3 个进程共享一台打印机，互斥信号量的初值和取值范围是？
```
初值 = 1（一台打印机，互斥信号量）
最小值 = 1 - 3 = -2（3 个进程都在等待，|负数| = 等待进程数）
取值范围：-2 ~ 1
```
> 📌 **通用结论**：n 个进程共享一个互斥资源，信号量范围 = **[1-n, 1]**。
> 用这个结论 + [极端值代入法](./07-计算题专项.md#三大秒杀技巧不会算时用来救命)（n=1 时范围为 [1,1]）可秒杀。

## 1.3 死锁

### ① 四个必要条件（**缺一不可**，破坏任一即可预防死锁）

| 条件 | 含义 | 生活比喻 |
|------|------|---------|
| **互斥** | 资源一次只能一个进程用 | 一个马桶只能一个人用 |
| **占有且等待**（请求和保持） | 已占有一些资源，又申请新资源且不释放已有 | 占着碗里的，看着锅里的 |
| **不可抢占** | 资源不能被强行夺走 | 不能把别人碗里的抢过来 |
| **循环等待** | 形成首尾相接的等待环 | A 等 B，B 等 C，C 等 A |

> 🔴 **必背**：**四个条件同时成立才可能死锁**。题目问"如何预防死锁"→ 答"破坏四个条件之一"。

### ② 死锁的处理策略

| 策略 | 做法 | 特点 |
|------|------|------|
| **预防** | 破坏四个必要条件之一 | 简单但资源利用率低 |
| **避免** | **银行家算法**：分配前先试算，若进入不安全状态则不分配 | 需预先知道最大需求量 |
| **检测** | 画**资源分配图**，看能否完全化简 | 允许死锁发生，事后发现 |
| **解除** | 剥夺资源 / 撤销进程 / 进程回退 | 事后补救 |

### ③ 资源数下限公式（常考）

```
系统有 n 个进程，每个进程需要 k 个同类资源
保证「绝不可能发生死锁」的最小资源数 m = n × (k - 1) + 1
```
> **例题**：3 个进程，每个需要 4 台打印机，至少配几台才不会死锁？
> `m = 3 × (4-1) + 1 = 10 台`
> （原理：最坏情况每个进程都拿到 k-1 个，再多 1 个就能让某个进程完成并释放）

### ④ 银行家算法：找安全序列

```
思路：依次寻找「当前可用资源 ≥ 该进程还需要的资源」的进程，
      假设它完成并释放已分配资源，更新可用资源，继续找下一个。
若能找到覆盖所有进程的序列 → 安全序列存在，系统处于安全状态。
```

## 1.4 存储管理

### ① 存储管理方案对比

| 方式 | 划分依据 | 碎片 | 特点 |
|------|---------|:----:|------|
| 单一连续 | 整个内存给一个程序 | 无外部碎片 | 单用户单任务 |
| 固定分区 | 预先划成固定大小 | **内部碎片** | 简单，浪费 |
| 可变分区 | 按需动态划分 | **外部碎片**（可紧凑解决） | 首次适应/最佳适应/最坏适应 |
| **页式** | 内存分"页框"，程序分"页"，**大小固定** | 只有**页内碎片** | 由**硬件**做地址变换，用户不可见 |
| **段式** | 按**逻辑模块**分段，**大小可变** | **外部碎片** | 用户可见，便于共享和保护 |
| **段页式** | 先分段，段内再分页 | 段间外部碎片 + 页内碎片 | 结合两者优点，开销大 |

> 🔴 **必背对比**：
> - **分页**是**物理**单位、**大小固定**、**用户不可见**（对程序员透明），目的是**提高内存利用率**。
> - **分段**是**逻辑**单位、**大小可变**、**用户可见**，目的是**便于共享、保护、动态链接**。

### ② 页式地址变换

```
逻辑地址 = 页号 P + 页内偏移 W
物理地址 = 页框号 f × 页面大小 + 页内偏移 W
        （f 通过查页表得到：页表[P] = f）

页面大小 = 2^页内偏移位数
```

> **例题**：页面大小 4KB，逻辑地址 `0x2A6F`，页表中第 2 页（从 0 开始）对应页框 5，求物理地址。
```
4KB = 4096 = 2^12  → 页内偏移占低 12 位
0x2A6F = 0010 1010 0110 1111
页号 = 高 4 位 = 0010 = 2
页内偏移 = 0xA6F
物理地址 = 5 × 0x1000 + 0xA6F = 0x5000 + 0xA6F = 0x5A6F
```

- **快表（TLB）**：页表的高速缓存，**命中则只需 1 次访存**（否则需 2 次：查页表 + 取数据）
- **多级页表**：解决页表太大的问题（占用的页目录也占内存）

### ③ 页面置换算法

| 算法 | 规则 | 特点 |
|------|------|------|
| **OPT** | 淘汰未来最长时间不用的页 | 理论最优，**无法实现**（需预知未来） |
| **FIFO** | 淘汰最早进入的页 | 简单，但有 **Belady 异常**（物理块增加，缺页反而增加） |
| **LRU** | 淘汰最久未使用的页 | 性能好，需硬件支持（栈/计数器） |
| **Clock** | 循环扫描，淘汰访问位=0 的页 | LRU 的近似，开销小 |

> 🔴 **必背**：**Belady 异常只有 FIFO 会有**；LRU 和 OPT 属于"栈算法"，不会有。

## 1.5 文件系统

### ① 文件索引结构（计算常考）

一个文件的索引节点包含若干**索引项**，索引项分四类：

| 类型 | 指向 |
|------|------|
| **直接索引** | 直接指向数据块 |
| **一级间接索引** | 指向一个索引块，该块存 N 个数据块地址 |
| **二级间接索引** | 指向索引块 → 索引块 → 数据块 |
| **三级间接索引** | 三层 |

```
设：每个盘块 1KB，每个地址占 4 字节 → 一个索引块可存 1024/4 = 256 个地址

最大文件长度 = (直接索引数 + 256 + 256² + 256³) × 盘块大小
```

> **例题**：某文件系统盘块 1KB，地址占 4 字节，索引节点含 8 个直接索引、1 个一级间接、1 个二级间接。求单文件最大长度。
```
一个索引块可存地址数 = 1024 / 4 = 256
直接：8 块
一级：256 块
二级：256² = 65536 块
总块数 = 8 + 256 + 65536 = 65800 块
最大文件 = 65800 × 1KB ≈ 64.26 MB
```

### ② 磁盘空闲空间管理

| 方法 | 说明 |
|------|------|
| **位示图** | 每个盘块对应 1 bit（0=空闲，1=占用）。直观、易找连续空间 |
| 空闲表法 | 记录连续空闲区（起始块号 + 块数） |
| 空闲链表法 | 空闲块用指针串成链 |
| 成组链接法 | UNIX 采用，结合了前两者优点 |

### ③ 文件共享

- **硬链接**：多个目录项指向**同一个索引节点**（inode），`ln`。删除一个链接不影响其他。
- **软链接（符号链接）**：一个特殊文件，内容是**目标文件路径**，`ln -s`。删除目标文件后链接失效。

## 1.6 设备管理

### ① I/O 控制方式（演进顺序，按 CPU 干预程度递减）

| 方式 | CPU 干预 | 特点 | 适用 |
|------|:--------:|------|------|
| **程序查询（轮询）** | 全程 | CPU 不断查询设备状态，**效率最低** | 简单设备 |
| **中断驱动** | 每次传输完 | I/O 完成后发中断通知 CPU | 慢速设备（键盘） |
| **DMA** | 仅在**开始和结束**时 | 数据在内存与设备间**直接**传送，不经过 CPU | 块设备（磁盘） |
| **通道** | 最少 | 专用处理器，可执行通道程序 | 大型机 |

> 🔴 **必背**：**DMA 传输的基本单位是「数据块」，中断方式的基本单位是「字（字节）」**。

### ② 缓冲技术

- **单缓冲**：一块缓冲区，读入与处理**串行**
- **双缓冲**：两块缓冲区，读入与处理可**并行**
- **环形缓冲 / 缓冲池**：多缓冲统一管理

### ③ SPOOLing 技术

> **一句话**：把**独占设备虚拟成共享设备**（如把一台打印机"变成"多台逻辑打印机）。
>
> **生活比喻**：打印店的排队系统——你点"打印"后文件进了队列（**输出井**），打印机按顺序慢慢打，你觉得自己在独占使用。
>
> **核心组成**：输入井/输出井（磁盘上）+ 输入/输出缓冲区（内存中）+ 输入/输出进程
>
> 🔴 **必背**：SPOOLing **提高了 I/O 速度**，将独占设备改造成**共享设备**，实现了**虚拟设备**功能。它**不提高 CPU 利用率**（这是常见干扰项）。

# 第 2 章 计算机网络

## 2.1 体系结构

### ① 两张表必须背

**OSI 七层模型（从下往上）**

| 层 | 名称 | 功能 | 典型协议/设备 | 数据单位 |
|:--:|------|------|--------------|---------|
| 7 | **应用层** | 为应用程序提供网络服务 | HTTP、FTP、SMTP、DNS、Telnet | 报文 |
| 6 | **表示层** | 数据格式转换、加密解密、压缩 | JPEG、MPEG、SSL/TLS | — |
| 5 | **会话层** | 建立、管理、终止会话 | RPC、NetBIOS | — |
| 4 | **传输层** | 端到端的可靠/不可靠传输 | **TCP、UDP** | 段（Segment） |
| 3 | **网络层** | 路由选择、拥塞控制、IP 寻址 | **IP、ICMP、ARP、RIP、OSPF、BGP**；**路由器** | 包/分组 |
| 2 | **数据链路层** | 帧的封装、差错控制、流量控制 | Ethernet、PPP、HDLC、VLAN；**交换机、网桥** | 帧（Frame） |
| 1 | **物理层** | 比特流的透明传输 | RJ45、光纤、IEEE 802.3；**中继器、集线器** | 比特 |

> 🔴 **口诀（从下往上）**：**"物链网传会表应"** → 谐音 **"巫联网传会镖瘾"**（想象一个巫师用网传镖，上瘾了）

**TCP/IP 四层模型**

| TCP/IP 层 | 对应 OSI |
|-----------|---------|
| 应用层 | 应用层 + 表示层 + 会话层 |
| 传输层（TCP/UDP） | 传输层 |
| 网际层 / 网际互联层（IP） | 网络层 |
| 网络接口层（主机-网络层） | 数据链路层 + 物理层 |

### ② 设备与层次的对应（易考）

| 设备 | 工作层次 | 作用 |
|------|:--------:|------|
| **中继器 / 集线器 Hub** | 物理层 | 放大信号，不能隔离冲突域 |
| **网桥 / 交换机 Switch** | 数据链路层 | 按 MAC 地址转发，**隔离冲突域**，不隔离广播域 |
| **路由器 Router** | 网络层 | 按 IP 地址转发，**隔离广播域** |
| **网关 Gateway** | 高层（4~7 层） | 协议转换 |

> 🔴 **必背**：**路由器可以隔离广播域；交换机只能隔离冲突域，不能隔离广播域；集线器什么都不隔离。**

## 2.2 核心协议

### ① TCP vs UDP（必考对比）

| 维度 | **TCP** | **UDP** |
|------|---------|---------|
| 连接 | **面向连接**（三次握手） | **无连接** |
| 可靠性 | **可靠**（确认、重传、排序、流控、拥塞控制） | **不可靠**（尽最大努力交付） |
| 传输单位 | 字节流 | 报文 |
| 速度 | 慢（开销大，首部 20 字节） | 快（首部仅 8 字节） |
| 拥塞/流量控制 | 有（滑动窗口、慢开始等） | 无 |
| 支持 | 一对一 | 一对一、一对多、多对多 |
| 应用 | HTTP、FTP、SMTP、SSH、MySQL | DNS、DHCP、SNMP、**视频/语音通话**、TFTP |

> 🔴 **必背**：**DNS 同时用 TCP 和 UDP**——域名解析用 UDP（53 端口），**区域传送用 TCP**。

**TCP 三次握手 / 四次挥手**
```
握手：① SYN=1, seq=x
      ② SYN=1, ACK=1, seq=y, ack=x+1
      ③ ACK=1, seq=x+1, ack=y+1

挥手：① FIN=1, seq=u
      ② ACK=1, ack=u+1          （半关闭：A 不再发，B 仍可发）
      ③ FIN=1, ACK=1, seq=v, ack=u+1
      ④ ACK=1, ack=v+1          （A 等 2MSL 后关闭）
```
> **为什么挥手要四次、握手只要三次？**
> 因为**第二次握手时，服务端可以把 SYN 和 ACK 合并一起发**；而挥手时，被动关闭方收到 FIN 后可能还有数据没发完，所以 ACK 和 FIN **不能合并**，必须分两次。

| 端口 | 协议 | 用途 | | 端口 | 协议 | 用途 |
|:----:|------|------|-|:----:|------|------|
| **20/21** | FTP | 文件传输（数据/控制） | | **443** | HTTPS | 加密 HTTP |
| **22** | SSH | 安全远程登录 | | 1433 | SQL Server | 数据库 |
| **23** | Telnet | 远程登录（明文） | | **1521** | Oracle | 数据库 |

### ③ HTTP 状态码（必背）

| 类别 | 含义 | 高频码 |
|:----:|------|--------|
| **1xx** | 信息，请求已接收，继续处理 | 100 Continue |
| **2xx** | **成功** | **200 OK**、201 Created、204 No Content |
| **3xx** | **重定向** | **301 永久重定向**、302 临时重定向、**304 Not Modified（命中缓存）** |
| **4xx** | **客户端错误** | **400 请求语法错误**、**401 未认证**、**403 禁止访问（认证了但没权限）**、**404 资源不存在** |
| **5xx** | **服务器错误** | **500 服务器内部错误**、**502 Bad Gateway（网关收到无效响应）**、**503 服务不可用**、**504 Gateway Timeout（网关超时）** |

> 🔴 **必背区分**：
> - **401 未认证（没登录）** vs **403 禁止（登录了但没权限）**
> - **502 网关收到无效响应** vs **504 网关超时**（502 是"对方回了但不对"，504 是"等太久没回"）

### ④ 路由协议

| **外部网关 EGP** | **BGP** | 自治系统之间，路径矢量 |

| 考点 | 结论 |
|------|------|
| **ARP** | IP 地址 → **MAC** 地址 |

| **NAT** | 私有 IP → 公网 IP，解决 IPv4 地址不足 |

| **IPv6** | 地址 **128 位**，用**冒号十六进制**表示 |
| **VLAN** | 虚拟局域网，工作在数据链路层，可隔离广播域 |
| **冲突域/广播域** | 集线器全共享；交换机每端口一个冲突域、一个广播域；路由器每端口一个广播域 |

# 第 3 章 数据库系统

## 3.1 三级模式与两级映像（必考）

### ① 直觉

> **外模式** = 每个部门看到的**报表视图**（销售部只看销量，财务只看金额）
> **模式** = 公司的**总账**（全部数据的完整结构）
> **内模式** = 账本**怎么存在保险柜里**（物理存储方式）

### ② 表格

| 层次 | 别名 | 数量 | 说明 |
|------|------|:----:|------|
| **外模式** | 子模式 / 用户模式 | **多个** | 单个用户看到的数据视图 |
| **模式** | 逻辑模式 / 概念模式 | **唯一** | 全体数据的整体逻辑结构 |
| **内模式** | 存储模式 / 物理模式 | **唯一** | 数据的物理存储结构与方式 |

### ③ 两级映像与数据独立性（🔴 核心考点）

| 映像 | 保证的独立性 | 含义 |
|------|-------------|------|
| **外模式 / 模式 映像** | **逻辑独立性** | 模式（表结构）改变时，修改映像即可保持外模式不变 → **应用程序不用改** |
| **模式 / 内模式 映像** | **物理独立性** | 存储结构（内模式）改变时，修改映像即可保持模式不变 → **应用程序不用改** |

> 🔴 **必背**：
> - **逻辑独立性** 靠 **外模式/模式映像**；**物理独立性** 靠 **模式/内模式映像**。
> - 口诀：**"外模保证逻辑，模内保证物理"**（"外→逻辑，内→物理"，一一对应）。

## 3.2 E-R 模型与关系模式转换

### ① 实体间联系的三种类型

| 类型 | 说明 | 例子 |
|------|------|------|
| **1 : 1** | 一个 A 对一个 B | 一个班级 ↔ 一个班主任 |
| **1 : n** | 一个 A 对多个 B | 一个班级 ↔ 多个学生 |
| **m : n** | 多个 A 对多个 B | 学生 ↔ 课程 |

### ② 转关系模式的规则（🔴 必背）

| 联系类型 | 转换规则 |
|----------|---------|
| **1 : 1** | 在**任意一方**加入另一方的主键作为外键（也可独立成表） |
| **1 : n** | 在 **n 方（多方）**加入 **1 方**的主键作为外键 |
| **m : n** | **必须新建一个关系表**，包含**双方主键（组成联合主键）** + 联系自身的属性 |

> **例题**：学生（学号，姓名）、课程（课程号，课程名），"选课"联系带属性"成绩"。转关系模式。
```
学生（学号，姓名）                主键：学号
课程（课程号，课程名）            主键：课程号
选课（学号，课程号，成绩）        主键：（学号，课程号）联合主键
                                 外键：学号 → 学生，课程号 → 课程
```
> ⚠️ 陷阱：m:n 联系**不能**简单地在某一方加外键（会导致多值），**必须新建表**。

## 3.3 关系代数（考基本运算符的识别）

| 运算 | 符号 | 含义 | 记忆 |
|------|------|------|------|
| 并 | ∪ | 两关系元组合并（去重） | — |
| 差 | − | 属于 R 但不属于 S | — |
| 交 | ∩ | 同时属于 R 和 S | — |
| 笛卡尔积 | × | R 的每个元组 × S 的每个元组 | 行数相乘 |
| **选择** | **σ**（sigma） | 按**行**筛选（WHERE） | s**e**lect → 横向 |
| **投影** | **π**（pi） | 按**列**筛选（SELECT 列名） | p → **列**（Projection） |
| **连接** | **⋈** | 按条件横向拼接 | — |
| 除 | ÷ | "全部"类查询（含"所有""全部"时用） | 查询"选修了**所有**课程的学生" |

## 3.4 范式（必考 2~3 题）

### ① 直觉

> 范式 = **数据表的"整洁度等级"**。等级越高，冗余越少、异常（插入/删除/更新异常）越少，但表被拆得越碎、查询越慢。

### ② 各级范式（逐级递进，记住"消除什么"）

| 范式 | 要求 | 消除了什么 | 通俗说法 |
|:----:|------|-----------|---------|
| **1NF** | 属性**不可再分**（原子性） | 重复组、多值属性 | 一个格子只能放一个值 |
| **2NF** | 1NF + 非主属性**完全**依赖于候选码 | **部分函数依赖** | 不能只依赖主键的一半 |
| **3NF** | 2NF + 非主属性**不传递**依赖于码 | **传递函数依赖** | 不能"通过别人"依赖主键 |
| **BCNF** | 3NF + **所有决定因素都包含码**（主属性也不能依赖于非码） | 主属性对码的部分/传递依赖 | 更严格版 3NF |
| **4NF** | BCNF + 无非平凡**多值依赖** | 多值依赖 | — |

### ③ 判断口诀（配合例题用）

```
① 不满足 1NF：有"复合属性"（如"联系方式：电话+邮箱"放一格）
② 不满足 2NF：主键是联合主键，但有非主属性只依赖其中一部分
③ 不满足 3NF：存在 A→B→C 的链条（非主属性 C 传递依赖于 A）
```

> **例题**：关系模式 R（学号，课程号，姓名，课程名，成绩），判断最高范式。
```
候选码：（学号，课程号）
函数依赖：
  学号 → 姓名           ← 部分依赖！（姓名只依赖学号，不依赖课程号）
  课程号 → 课程名       ← 部分依赖！
  （学号，课程号）→ 成绩 ← 完全依赖

→ 存在部分函数依赖 → 不满足 2NF → 最高只到 1NF

改进（拆表）：
  学生（学号，姓名）
  课程（课程号，课程名）
  选课（学号，课程号，成绩）   ← 达到 3NF
```

### ④ 反规范化（案例常考，选择题也考）

> **为什么需要**：范式过高 → 表太碎 → 查询要大量 Join → **性能差**。
> **常用手段**：增加冗余列、增加派生列（如"订单总金额"）、重新组表、分割表（水平/垂直）
> **代价**：**牺牲规范化，换取查询性能**；带来**数据冗余和不一致风险**。
>
> 🔴 **必背**：反规范化是**以空间换时间**，代价是**更新异常风险增加**。

## 3.5 事务与并发控制

### ① ACID（必背）

| 特性 | 含义 | 生活比喻 |
|------|------|---------|
| **A**tomicity 原子性 | 要么全做，要么全不做 | 转账：扣款和加款必须同时成功或同时失败 |
| **C**onsistency 一致性 | 事务前后数据都满足完整性约束 | 转账前后**总额不变** |
| **I**solation 隔离性 | 并发事务之间互不干扰 | 你在转账时，别人查不到中间状态 |
| **D**urability 持久性 | 提交后即使宕机也不丢失 | 钱转完，银行停电也认账 |

### ② 并发引发的三类问题

| 问题 | 现象 |
|------|------|
| **丢失更新**（丢失修改） | 两个事务同时改同一数据，后提交的覆盖了先提交的 |
| **读"脏"数据** | 读到另一事务**未提交**的数据，而该事务后来**回滚**了 |
| **不可重复读** | 同一事务内两次读同一数据，结果不同（因为别的事务**修改/删除**了它） |
| **幻读**（补充） | 同一事务内两次按条件查询，**行数**不同（别的事务**新增**了符合条件的记录） |

> 🔴 **区分不可重复读 vs 幻读**：
> - **不可重复读** = 同一行数据的**内容**变了（UPDATE / DELETE）
> - **幻读** = 符合条件的**行数**变了（INSERT）

### ③ 封锁协议（三级）

| 级别 | 加锁规则 | 解决了 |
|:----:|---------|--------|
| **一级** | 修改前加 **X 锁**，**事务结束**才释放 | ✅ 丢失更新 |
| **二级** | 一级 + **读取前加 S 锁**，**读完立即释放** | ✅ 丢失更新 + ✅ 读脏数据 |
| **三级** | 一级 + **读取前加 S 锁**，**事务结束**才释放 | ✅ 丢失更新 + ✅ 读脏 + ✅ 不可重复读 |

### ④ 锁的类型

| 锁 | 名称 | 规则 |
|:--:|------|------|
| **X 锁** | 排他锁 / 写锁 | 只有加锁者能读写；其他事务不能加任何锁 |
| **S 锁** | 共享锁 / 读锁 | 多个事务可同时加 S 锁读；但不能再加 X 锁 |

> **相容矩阵**：
> | | S | X |
> |--|---|---|
> | **S** | ✅ | ❌ |
> | **X** | ❌ | ❌ |

### ⑤ 隔离级别（从低到高）

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|:----:|:----------:|:----:|
| 读未提交（Read Uncommitted） | ❌ 有 | ❌ 有 | ❌ 有 |
| 读已提交（Read Committed） | ✅ 无 | ❌ 有 | ❌ 有 |
| 可重复读（Repeatable Read） | ✅ 无 | ✅ 无 | ❌ 有 |
| 串行化（Serializable） | ✅ 无 | ✅ 无 | ✅ 无 |

> 📌 **MySQL InnoDB 默认「可重复读」**，且通过 MVCC + 间隙锁在多数场景避免了幻读。

### ⑥ 两段锁协议（2PL）

```
事务分两阶段：
  ① 扩展阶段：只能加锁，不能解锁
  ② 收缩阶段：只能解锁，不能加锁
→ 遵守 2PL 的并发调度，一定是「可串行化」的（充分条件，非必要）
→ 但仍可能产生「死锁」
```

## 3.6 数据库安全与备份

| 考点 | 结论 |
|------|------|
| **备份类型** | **完全备份**（全部数据）、**增量备份**（上次备份以来变化的部分）、**差异备份**（上次**完全**备份以来变化的部分） |
| 冷备份 vs 热备份 | 冷 = 停机备份；热 = 不停机（在线）备份 |
| 恢复速度 | 完全 > 差异 > 增量 |
| 备份速度/空间 | 增量最省，完全最费 |
| **数据脱敏** | 对敏感数据变形（如手机号中间 4 位打码），用于非生产环境 |
| 视图机制 | 通过授权让用户只能看到视图，实现**隐藏敏感数据** |

> 🔴 **必背区分**：
> - **增量**：基于**上一次任何类型**备份之后的变化
> - **差异**：基于**上一次完全备份**之后的变化

# 第 4 章 数据结构与算法

> 计算部分（复杂度、数组地址、树/图节点数、查找比较次数）见 👉 [07 第 5 章](./07-计算题专项.md#五数据结构与算法计算)。本篇只讲**概念与辨析**。

## 4.1 线性表

| 结构 | 存储 | 存取方式 | 插入/删除 | 适合场景 |
|------|------|---------|:---------:|---------|
| **顺序表（数组）** | 连续空间 | **随机存取** O(1) | O(n)（需移动元素） | 查找多、改动少 |
| **链表** | 分散 + 指针 | 顺序存取 O(n) | **O(1)**（只改指针） | 频繁插入删除 |

> **链表变体**：
> - **单链表**：只有后继指针
> - **双向链表**：前驱 + 后继
> - **循环链表**：尾节点指向头节点
> - **静态链表**：用数组模拟链表（游标实现）

> 🔴 **必背**：**顺序表随机存取、链表顺序存取**；顺序表**存储密度高**（无指针开销），链表**存储密度低**。

## 4.2 栈与队列

| 结构 | 特点 | 生活比喻 | 典型应用 |
|------|------|---------|---------|
| **栈** | **后进先出（LIFO）** | 一摞盘子，只能从顶上拿 | 函数调用、表达式求值、括号匹配、递归、撤销（Undo） |
| **队列** | **先进先出（FIFO）** | 排队买票 | 缓冲区、打印队列、BFS、消息队列 |
| **双端队列** | 两端都能进出 | 两头都能进出的通道 | — |
| **优先队列** | 按优先级出队 | VIP 通道 | 堆、任务调度 |

### 循环队列（计算常考）

```
队空：front == rear
队满：(rear + 1) % maxSize == front     ← 牺牲一个存储单元区分空/满
元素个数：(rear - front + maxSize) % maxSize
```

> **例题**：循环队列容量 50（数组 [0..49]），front=10，rear=25，队列中元素个数？
> `(25 - 10 + 50) % 50 = 15 个`

## 4.3 串与 KMP

- **串**：字符的有限序列；**空串**（长度 0）≠ **空格串**（长度 1）
- **子串**：串中任意连续字符组成的序列；**空串是任意串的子串**
- **KMP**：利用**部分匹配表（next 数组）**，失配时不回退主串指针，时间复杂度 **O(m+n)**
- **next[j]** = `P[0..j-1]` 中「最长的相等的真前缀与真后缀」的长度

## 4.4 树与二叉树

### ① 概念

| 术语 | 含义 |
|------|------|
| **度** | 节点的子树个数 |
| **叶子（终端节点）** | 度为 0 的节点 |
| **树的度** | 树中节点的最大度数 |
| **深度/高度** | 树的最大层数（根节点为第 1 层） |
| **森林** | m 棵互不相交的树的集合 |

### ② 特殊二叉树

| 类型 | 定义 | 特点 |
|------|------|------|
| **满二叉树** | 每层都满 | 深度 h 有 2^h - 1 个节点 |
| **完全二叉树** | 按层序编号，与满二叉树一一对应 | **适合顺序存储**；叶子只在最后两层 |
| **二叉排序树（BST）** | 左子树 < 根 < 右子树 | 中序遍历得到**有序**序列；查找 O(log n) ~ O(n) |
| **平衡二叉树（AVL）** | BST + 任一节点左右子树高度差 ≤ 1 | 保证 O(log n)；失衡时旋转（LL/RR/LR/RL） |
| **B 树** | 多路平衡查找树，所有节点都存关键字 | 用于**文件系统/数据库索引** |
| **B+ 树** | B 树变体，关键字只在**叶子节点**存全，且叶子**用链表相连** | **MySQL InnoDB 索引结构**；特别适合**范围查询** |

> 🔴 **B 树 vs B+ 树（必考对比）**
> | 维度 | B 树 | B+ 树 |
> |------|------|-------|
> | 关键字存储位置 | 所有节点 | 只在**叶子节点**（非叶只存索引） |
> | 叶子节点 | 不相连 | **用链表相连** |
> | 查找稳定性 | 可能在任一层结束 | **每次都到叶子**，性能稳定 |
> | 范围查询 | 效率低（需中序遍历） | **效率高**（沿链表扫即可） |
> | 单机查询 | **可能更快**（命中非叶节点就返回） | 稍慢 |

### ③ 二叉树遍历

| 遍历 | 顺序 | 记忆 |
|------|------|------|
| **前序（先根）** | 根 → 左 → 右 | 根在最**前** |
| **中序（中根）** | 左 → 根 → 右 | 根在中**间** |
| **后序（后根）** | 左 → 右 → 根 | 根在最**后** |
| **层序** | 从上到下、从左到右 | 需**队列**辅助 |

> 🔴 **必背结论**（高频考点）：
> 1. **已知「前序 + 中序」或「后序 + 中序」→ 可唯一确定一棵二叉树**
> 2. **已知「前序 + 后序」→ 不能唯一确定**（除非是满二叉树）
>
> 📌 记忆：**必须有中序**（中序用来区分左右子树）。

## 4.5 图

| 概念 | 说明 |
|------|------|
| **度** | 无向图：边数；有向图：入度 + 出度 |
| **连通图** | 无向图中任意两点可达 |
| **强连通图** | 有向图中任意两点互相可达（最少 **n** 条边构成环） |
| **生成树** | 含全部顶点的极小连通子图，**n-1 条边** |
| **最小生成树** | 权值之和最小的生成树：**Prim**（适合**稠密**图）、**Kruskal**（适合**稀疏**图，按边排序 + 并查集） |
| **拓扑排序** | AOV 网，每次选**入度为 0** 的顶点；**若有环则无法完成** |
| **关键路径** | AOE 网，从源点到汇点的**最长路径**，决定项目最短工期 |
| **最短路径** | **Dijkstra**（单源，边权非负）；**Floyd**（任意两点，动态规划） |
| **图的存储** | 邻接矩阵（适合稠密，O(n²) 空间）；邻接表（适合稀疏，O(n+e)） |
| **遍历** | **DFS**（用**栈**/递归，回溯）；**BFS**（用**队列**，层序） |

> 🔴 **必背**：
> - DFS 用**栈**，BFS 用**队列**。
> - **Prim/Kruskal 是贪心**；**Dijkstra 是贪心**；**Floyd 是动态规划**。
> - **拓扑排序能完成 ⟺ 图是无环的（DAG）**。

## 4.6 查找

| 方法 | 平均查找长度 | 要求 | 特点 |
|------|:------------:|------|------|
| 顺序查找 | O(n) | 无 | 最简单 |
| **折半查找** | O(log n) | **有序 + 顺序存储** | 判定树是**平衡二叉树** |
| 分块查找 | 介于两者 | 块间有序，块内无序 | 折中方案 |
| **哈希查找** | **O(1)** | 哈希函数 + 冲突处理 | 空间换时间 |

**哈希冲突处理方法**
- **开放定址法**：线性探测（会产生**聚集**）、二次探测、伪随机探测
- **链地址法（拉链法）**：冲突的元素链在同一位置（HashMap 用的方式）
- 再哈希法、建立公共溢出区

> 🔴 **必背**：装填因子 α = 记录数 / 表长，α 越大冲突越多，查找越慢。

## 4.7 排序（速查表，详见 [07 第 5.5 节](./07-计算题专项.md#55-查找与排序)）

| 算法 | 平均 | 最坏 | 稳定 | 一句话特点 |
|------|:----:|:----:|:----:|-----------|
| 直接插入 | O(n²) | O(n²) | ✅ | 基本有序时 **O(n)** |
| 冒泡 | O(n²) | O(n²) | ✅ | 基本有序时 **O(n)** |
| 简单选择 | O(n²) | O(n²) | ❌ | 比较次数固定 n(n-1)/2 |
| **快速** | O(n log n) | **O(n²)**（有序时） | ❌ | 平均最快，但**不稳定、怕有序** |
| 堆 | O(n log n) | O(n log n) | ❌ | 适合求 **Top K** |
| 归并 | O(n log n) | O(n log n) | ✅ | 需 O(n) 辅助空间 |
| 希尔 | O(n^1.3) | O(n²) | ❌ | 分组插入 |
| 基数 | O(d(n+r)) | 同左 | ✅ | 不基于比较 |

> 🔴 **稳定性口诀**：**"插泡归基，稳如老狗"**（插入、冒泡、归并、基数 是稳定的）。

## 4.8 五大算法策略

| 策略 | 思想 | 特征 | 典型例子 |
|------|------|------|---------|
| **分治** | 拆成独立子问题，递归求解再合并 | 子问题**相互独立** | 归并排序、快速排序、二分查找、汉诺塔 |
| **贪心** | 每步都做**当前最优**选择 | **贪心选择性质** + **最优子结构** | Prim、Kruskal、Dijkstra、哈夫曼、部分背包 |
| **动态规划（DP）** | 记录子问题解，避免重复计算 | **最优子结构** + **重叠子问题** | 0-1 背包、最长公共子序列、矩阵连乘、Floyd |
| **回溯** | 深度优先搜索 + **剪枝**，走不通就回退 | 求**所有解** | N 皇后、迷宫、0-1 背包（枚举） |
| **分支限界** | 广度优先 / 最小代价优先，用限界函数剪枝 | 求**一个最优解** | 旅行商问题、0-1 背包 |

> 🔴 **贪心 vs 动态规划（必考区分）**：
> - **贪心**：每步选当前最优，**不能回退**，需要「贪心选择性质」
> - **DP**：考虑所有选择，**保存子问题解**，需要「重叠子问题」
> - **能用贪心解的，一般也能用 DP 解，但反过来不成立**
>
> 📌 经典例子：**0-1 背包必须用 DP**（贪心不成立）；**部分背包（物品可分割）可用贪心**（按单位价值排序）。
